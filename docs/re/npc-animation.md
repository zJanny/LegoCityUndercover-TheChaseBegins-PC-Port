# NPC animation: the idle state of level characters

How a level character (`char_ai_actor` and similar) animates while it stands: the animation slot, the idle state function, the random choice between `idle` and `idle2`, the generator. Skeleton and animation data: [skeleton-animation.md](skeleton-animation.md). Natives that start animations from scripts: [script-natives-animation.md](script-natives-animation.md). Items: [animation-characters.md](../plans/features/animation-characters.md), [level-objects.md](../plans/features/level-objects.md).

## Current state

- An idle character with an animation player runs the idle state 0x1d5070 each update; when the slot kind (0x22f560) is 6 it picks an id with 0x214870 / 0x219614 and starts it via 0x21941c (blend 0.1, speed 1.0). With id 0 the generator 0x25b2b8 chooses `idle` or `idle2` (id 280) 50/50. [§2026-10-15T09:29:00](#ts-20261015-092900)
- The generator is a lagged recurrence over an 11-word table at 0x52fcb8: `v = ror(t[first] + t[second], 29)`, cursors 0 and 7 after seeding (xorshift32 steps 13, 17, 5). The boot seed is time based. [§2026-10-15T09:29:00](#ts-20261015-092900)
- Only entities with an animation player animate (20 of 110 in the measured state); disabled characters and those of unloaded rooms have none. The clock is 3000 ticks per second; idle is 19 frames and idle2 69 frames at 15 fps, and a character starts the next clip at the first update after the previous one finished. [§2026-10-15T09:29:00](#ts-20261015-092900)
- The slot player: a 0x58-byte slot, newest first; start 0x245b40, position 0x24cbd4 (modes 0 to 6, loop bit 13), kind 0x22f560, stop 0x225c5c, offset 0x22c2fc, type callbacks in the 0x24-byte table at 0x52ce8c. Length, rate and loop bit come from the type callbacks (loop bit = joint table bit 29, so length = frames). [§2026-10-15T18:33:06](#ts-20261015-183306)
- Port: `src/runtime/animation_slots.*`, `npc_idle.*`, `game_random.*`, `game_characters.*`; the pose is clamped to `frames - 1` (stand-in ANIM-S2). [§2026-10-15T18:33:06](#ts-20261015-183306)
- The donut-shop view matches the original in layout; the idle phase was not compared. [§2026-10-15T10:50:38](#ts-20261015-105038)
- A script animation (PlayCharAnim) puts the character into state 0x50, whose update starts no idle and only requests state 1 once the clip is finished, so a finished script clip stays visible for one update. [§2026-10-18T14:28:08+02:00](#ts-20261018-142808)
- Open: seed formula of 0x105d8c (the port uses a fixed seed), which slot 0x252878 picks as current, who pauses slots (0x24f8fc), the pose sampler's handling of [span, span + 1), blend between clips, gang classes and the AIMillAbout state.

Entity: +0x08 = CRC32 of the lower-case instance name (`1-1_AI_DonutShopMan` = 0xf373e1bf), class pointer at +0x1c (class name string at class+0x20), node +0x3c, animation component inline at +0x40 whose word +0x44 points to the player struct (0x233900 returns slots for it only when byte 0 & 0x20). Player struct: byte 0 flag 0x20 (has animations), byte 1 slot capacity (4), byte 2 slot count, +0x2c slot array.
- Of 110 level characters only 20 have an animation player in this state: the 14 pedestrians (walk, mode 6), `char_freeplay_crimerobber` / `crimevictim`, one pig, and three `char_ai_actor`: `1-1_AI_DonutShopMan`, `1-1_AI_DonutShopMan01`, `1-3_Blocker`. The characters the level start script disables (`1-1_AI_DonutCop`, the `1-3_*` cast, ...) and those of rooms that are not loaded have no player: no animation exists before the entity is enabled.
- **Slot** (0x58 bytes, newest first through 0x252878): +0 animation object, +4 u16 mode (low 3 bits; bit 13 = loop bit of the data, 0x400 = blend applied), +8 start id (counts up per start), +0xc u16 rate (15), +0x2c u16 first frame (0), +0x2e u16 end frame (= frame count: 0x13 idle, 0x45 idle2), +0x30 float rate x speed (15.0), +0x34 / +0x3c start clock, +0x38 end clock (-1 while playing), +0x40 float blend time. Written by 0x245b40 (start; `0x23afc0` wraps it). Weights of the slots: 0x115ecc, pose over all slots: 0x2533e0.
- **Position** (0x24cbd4, called through 0x24bf80): `p = (clockNow - start) * rate * speed / ticksPerSecond (+ offset)` with the clock object of the animation owner; the clock is 3000 ticks per second ([studs.md](studs.md)). Mode 0 (play once): below 0 -> 0; `p >= length` sets the finished flag (bit 31 of the flag word) and `p = length`. Modes 1 and 6 loop (`p mod length`), 2 reversed once, 3 ping-pong, 5 reversed loop. `0x22f560(slot)` returns 6 when there is no slot or the slot reports finished, otherwise its mode. Frame pair for the pose: floor(p) and floor(p + 1), clamped by the same rules (0x24bf80).
- **Blend** (0x115ecc): the newest slot gets weight `min(elapsed / (blend * ticks), 1)`, each older slot the rest, 0 blend time takes all the rest.

**Idle state 0x1d5070(entity, ctrl)** (every update of a character in state 0): `kind = 0x22f560(0x233900(entity + 0x40))`; when 6 it calls `id = 0x214870(entity, ctrl, &flag)` and `0x21941c(blend 0.1, speed 1.0, entity, id, mode 0, 0, 0xffff ...)`; then the idle locomotion mover 0x20cd30 (root motion) and the rest. Execution trap on 0x21941c (`ct1`): every start of the three characters comes from lr 0x1d50e8 (the call at 0x1d50e4), with r1 = 0 (`idle`) or 0x118 = 280 (`idle2`).
- `0x214870`: id 0x118 when `0x219b80(entity)` (entity equals the word at `*0x3746f4 + 8`); otherwise `0x219614(entity, 0)` (role 0), or role 9 for the armed case (`(ctrl+0xdc & 0x1f) >> 3 == 2` with the weapon conditions).
- `0x219614(entity, role)`: record `role * 14` of the table at `*0x374294` (7 x s16: default and six variants chosen by `0x2106d8(ctrl, 0..2)`, bit 2 of `*(ctrl+0xe0)+0x130`, `ctrl+0x13c`); 0x271 = none -> record[0]. **When the id is 0 and the entity is not the player (or `0x236104()` is 0): `0x25b2b8()`; bit 2 set -> 280 (`idle2`), else 0 (`idle`).** One random call per start, 50 / 50.
- tablesanimations sheet 1: row 0 "idle", row 280 "idle2"; the file is `models/char_minifig/<class folder>/<name>_minifig.bfnanm` (`idle_minifig`: 19 frames, 15 fps; `idle2_minifig`: 69 frames, 15 fps, both `class_generic`; every class folder has both). The three characters play `class_generic` (their `AnimationClass` is empty).

- The frames-plus-one curve: slot length equals the decoder's `frames` (19, 69); samples of non-root curves are `frames`, so the second frame of the last pair is out of range; the port clamps the pose to `frames - 1` (assumed, not read: the curve decoder's bounds were not read).

**RNG 0x25b2b8 / seed 0x25b254.** 11-word table at 0x52fcb8, cursors at 0x376724 (first) and 0x376728 (second). `v = ror(t[first] + t[second], 29); t[first] = v; both cursors - 1, wrapping from 0 to 10; return v`. Seed: 0 becomes 0xffffffff; 11 xorshift32 steps (13, 17, 5) fill t[0..10]; cursors 0 and 7. Verified on the trap `rng2` (`ctrace 0x25b304`, 134 calls in 30 updates): every output from the 12th on equals `ror(v[n-11] + v[n-7], 29)` (123 of 123), which is the recurrence of this table and cursor distance (first - second = 4 mod 11). The first outputs after a `read` of the table did not match a simulation from the read state, because other updates ran in between (gap not measured). Seed callers: 0x105d8c builds it from calendar fields (0x2566d4, 0x111310 ...; not transcribed) and 0x101e5c reseeds from the previous output; the boot seed is time based, so a run cannot be matched call for call.

## 2026-10-15T18:33:06+02:00 — The general animation slot player: start 0x245b40, position 0x24cbd4, kind, stop, offset, the type callbacks (REA/Ghidra pseudo-code and llvm-objdump of `game.arm.elf`; oracle `m11-3-repair-van-marker` (user state) with OpenGL, GDB `read` and `ctrace`, no RPC)

**Type callbacks.** The player calls per-type functions from a table of 0x24-byte records at 0x52ce8c (filled at run time; index = low 4 bits of the animation's type byte). Read in the oracle: type 0 = {+0xc 0x1081ec, +0x10 0x108190, +0x14 0x107990, +0x18 0x107d0c, ...}. 0x1081ec (**length**): the header u16 +4 & 0x3fff, minus 1 unless joint table bit 29 is set (0xffff without data). 0x108190 (**rate**): the known rate table 0x376764. 0x107990 (**loop bit**): joint table bit 29. In the port `assets::animationLength`, `animationLoops`. `idle`, `idle2`, `walk`, `postboxstuck_idle` (class_generic) all have bit 29, so length = frames (19, 69, 12, 42).

**Start 0x245b40** (`0x23afc0(entity, animation, mode, first, end on the stack, s0 speed, s1 blend)` passes its arguments through): when the slot count equals the capacity the last slot is released (0x24cf70) and its animation freed when no other slot holds it; the count grows up to the capacity, the older slots move down one place (0x251eb0) and the new slot is slot 0. Slot fields: start id = the player's counter + 1 (31 bits), mode = r1 & 7, bits 0x9c00 cleared, first frame +0x2c and end frame +0x2e (0xffff takes the length callback), rate +0xc from the rate callback, +0x30 = rate x speed, +0x34 = +0x3c = the owner's clock (0x256af4), +0x38 = -1, +0x40 = blend, +0x14 = the entity. Bit 13 = the loop bit; when it is clear and the mode is 1 or 5, bit 13 is set and the end frame grows by 1. With an empty player and a type compare against `*0x376758` the blend becomes 0.0 (not ported). The tail calls 0x1ce608 with the start fraction (first / length, or 1 - that for modes 2 and 5) and sets 0x400.

**Position 0x24cbd4(slot, offset, &flags)**: mode 6 sets the finished flag (bit 31). `p = (stop clock or now - start) * rate x speed / ticks per second + offset`; span = end - first. Span equal to 1 with bit 13 (0 without) finishes at once with p = 0. Mode 0: p < 0 -> 0; p >= span finishes, p = span. Modes 1 and 6: n = p / span (unsigned), p -= n span; with bit 13 a p below 1.0 after the first pass becomes p + span (n - 1), so later passes run over [1, span + 1); flags low bits = n. Mode 2: p = span - p, below 0 finishes at 0. Mode 3: period 2 span, p above span mirrors. Mode 5: p -= n span, a non-zero p becomes span - p. Result first + p.

**Kind 0x22f560**: no slot or no animation -> 6; modes 0 and 2 -> 6 when the position is finished, else the mode; any other mode is returned as is. **Stop 0x225c5c**: pause 0x24f8fc(slot, 1) (stop clock = now when it is -1) and mode 6; the pose stays at the stop clock. 0x24f8fc(slot, 0) resumes: start += now - stop, stop = -1. **Offset 0x22c2fc(frame, slot)**: modes 0, 1, 3 distance = frame - first; modes 2, 5 distance = span (+1 with bit 13) - (frame - first); start = now - int(ticks x distance x rate / (rate x rate x speed)); in mode 6 the stop clock = start + that time. **Current slot**: 0x233900 returns the slot 0x252878 picks; the port uses slot 0 (the newest).

**Oracle check** (`m11-3-repair-van-marker`, `ctrace 0x24cbd4 1`: 145 calls in one update, 32 slot pointers in arrays of 4; `read` of each array): 1-1_AI_DonutLady (entity 0x08a6d6b0, +8 = 0x9b8fc0c1 = CRC32 of `1-1_ai_donutlady`) has slot 0x08a6f460: +4 = 0x2401 (mode 1, bit 13, 0x400), start id 1, rate 15, first 0, end 42, rate x speed 15.0, +0x34 = 0x21873, +0x38 = -1, +0x3c = 0x1e841 (the start was moved by a pause of 12338 ticks). The pedestrians' slots are mode 1 or 6 with end 12 (walk), the idle characters mode 0 (0x2400) with end 19 or 69. The donut lady's node is at her placement (871.821, 51.838, 700.958, rotation -37.08 about Y): the stuck pose is the animation alone.

**Port.** `src/runtime/animation_slots.*` (start, position, kind, stop, mode change, offset, the WaitForCurrent test, clock 3000 ticks per second), the idle state `runtime::NpcIdle` now starts its clips in the slot player when the kind is 6, `game_characters::LevelCharacters` keeps one player per level character, advances one clock by the update's dt (100 ticks per 1/30 s update) and poses slot 0. Tests `animation-slots` (the rules above and the recorded slot) and `npc-idle`.

Unknowns:

## 2026-10-18T14:28:08+02:00 — Script animations and the idle state: the user-animation state 0x50 (REA on game.arm.elf; found while fixing DETECT-2)

- **PlayCharAnim enters state 0x50.** 0x29e5f0 calls 0x295a8c (play) and then requests state 0x50 (0x51 for PlayCutscene) with 0x2414b4. The state table entry (24 bytes at `*0x3742c8 + id * 0x18`; descriptor words at 0x3577f4..0x35780c: update 0x2a47b0, enter 0x25fbec, name "USER ANIM"; 0x51 the same pair) has the update 0x2a47b0: `0x22f560` of the entity's slot; when the kind is 6 (no slot or finished) it requests state 1 with 0x2414b4(entity, ctrl+0x50, 1, 0); then 0x215804 (locomotion helper, not read) and `ctrl+10 = ctrl+8`. It never starts an idle clip.
- **Consequence.** While a script animation plays the idle state 0x1d5070 does not run, and in the update that sees the end only the state change is requested, so a finished script clip is visible as kind 6 to `WaitForCurrentCharAnim` / `WaitForCurrentAnim` (0x263ae4, 0x2a06a8) until the next update, when the new state starts an idle. The port started the next idle in the same update that saw the end, so the wait never saw the finished clip and the Doorlock script stalled at pc 17 (DETECT-2, [abilities-detective.md](abilities-detective.md)). Fix: `NpcIdle::enterScriptAnimation` (PlayCharAnim on a level character), tests `npc-idle` (`testFinishedScriptAnimationStaysForOneUpdate`) and `game-doorlock-detective-1-2` (the script ends at update 1064 of a run from the alley; the detective point then enables `1-2_Dtv_DogSpot_01`).
- **Not read:** the enter function 0x25fbec (no procedure at that address in REA), 0x215804, what state 1 is for characters other than the player (the idle state is described as state 0 above, the carrying doc names state 1 as the default), and whether the request takes effect in the same update (the port gives the wait one update either way).
- **Seen in the port after the fix (lead check, `chase-game --call-script 1-2_Spawn_Doorlock` from the alley, 1100 updates):** the script ends at update 1064 and the first detective point is on, but `PositionObject 1-2_Doorlock_Holmes 1-2_Doorlock_Teleport` is not applied (`chase-game` places only the player and vehicles and prints `PositionObject not applied`), so Holmes stays where the bin animation leaves him; whether he is visible jumping out was not checked frame by frame.
