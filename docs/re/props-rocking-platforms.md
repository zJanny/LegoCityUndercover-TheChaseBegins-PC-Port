# Platforms and attached nodes

The platform class (ObjectType 64): its record, trigger messages, travel and node move, and the node hierarchy of AttachObject that carries attached objects with a moving node. Split from [props-rocking.md](props-rocking.md), where WaitForPlatform, the rocking props and the generator scene of mission 1-3 are.

## Current state

- The platform class (kind 64): the create, the post-link (`ObjectTo` or `Platform_Path`), the messages 0xff, 0xfe and 43, the request 0x2150bc and the update 0x2807c8 (step dt x 30 x `speed`, the ends by type, the shaped lerp of the node from R+0x18 to R+0x24) are read and ported in `platform_node_move.*`; the crane platform goes down 10.63 in 102 node moves and its wait ends 103 updates after the trigger, as in the oracle. Not ported: `orient` and type 7 rotations without a path, shape curves, lift timers (SCRIPT-S301). - AttachObject puts the child's node under the parent's and sends message 43 (the platform's list R+0x60); the startup attaches the girder to the crane platform and the girder guy, the crow and the rope to the girder, so they go down with it. The port carries the moves and turns of platform nodes (SCRIPT-S302). [§2026-10-26T22:54:42](#ts-20261026-225442), [§2026-10-28T00:06:31](#ts-20261028-000631)
- Path platforms: the node takes the spline position at count x the shaped value (at the arc length fraction 0x22a4c0 with `ConstantSpeed`) and the squad 0x270c60 of the path's two quaternion tables (or, without them, the `orient` turn along the tangent); ported in `platform_path.*`, with a rigid carry that turns the attached objects. The lawn mowers of mission 1-3 go round their paths, the gardener in his seat; not yet compared with the oracle. [§2026-10-28T00:06:31](#ts-20261028-000631)

## 2026-10-28T00:06:31+01:00 — Path platforms: the spline, ConstantSpeed, the squad of the path's quaternions, and the lawn mowers of mission 1-3

Method: llvm-objdump (`--triple=armv6k --mattr=+vfp2`) of `artifacts/game/game.arm.elf`, read instruction by instruction (20261027-mission13-A, 2026-10-27, no REA session): the path part of the update 0x280f2c..0x281024 and its end 0x2812f8..0x281408, the arc length parameter 0x22a4c0..0x22a670, the path orientation 0x270c60..0x270db4, the slerp 0x21a600..0x21a724, the quaternion rows 0x248870..0x24890c, the forward turn 0x237a0c..0x237a78 with the cross product 0x23b960 and the normalisation 0x257ea0, the quaternion normalisation 0x1ff9cc, the copy 0x2554c0 and the row copy 0x232788. The level data was printed with throwaway programs over the C++ level loader (all levels for the census).

**The path pose (update 0x2807c8 with R+0x50 set, after the shaped value s).** p = 0x22a4c0(path, s) when `ConstantSpeed` (R+0xb8 bit 1), else count x s (u16 path+2; count, not count - 1). Slot 0 of the path's type in table 0x359b38 (20 bytes per type; the same words as 0x358f9c: type 0 0x1c17c0, type 1 0x1b33fc) gives the position and the tangent at p (flag 1). When the path has quaternions (path+8): 0x270c60(path, count x s) and 0x248870 write the node's rotation rows; this takes count x s even with `ConstantSpeed`. Else, when `orient` (R+0xb6 bits 10..11) is not 0, the tangent becomes the forward row and 0x237a0c builds right = (z, 0, -x), or (0, -z, y) when |forward y| is above 0.98 (bits 0x3f7ae148), normalised, and up = forward x right (0x23b960 is a x b); 0x232788 copies the three rows into the node. The path branch skips the slerp of R+0x30 / R+0x40 and the lerp of R+0x18 / R+0x24: the node's new translation is the path position. Then, as for every platform, the rows are normalised (0x257ea0: (0, 0, 1) for a length whose bits are at most 0x34000000), the node's world matrix is rebuilt and the move goes to 0x23d6c4 with delta = position - translation and the yaw change (0x24765c of the forward row before and after).

**0x22a4c0(path, t).** |t| (a negative t is negated); no points: 0; t with bits 0x3f7fffff or 0x3f800000: count; bits below 0x34000000: 0. Otherwise the cumulative lengths (path+0x14, built on each call when it is null, which it is in the level data: entry 0 is 0, entry i adds slot 1 of the type (0x293540 for type 0) with 20 steps per segment from point i - 1 to i, count + 1 entries on a closed path), target = fmod(t, 1) x total, and a binary search over 0 .. count - 1 for the entry pair around the target: the result is i + (target - L[i]) / (L[i + 1] - L[i]). This is the function the detective footprints use with 10 steps ([abilities-detective.md](abilities-detective.md)).

**0x270c60(path, out, p), a squad.** No quaternions (path+8 null): the identity. An open path clamps p to 0 .. count - 1; i = floor(p), j = i + 1, f = p - i; a closed path with at least 3 points wraps i by the signed remainder plus count and keeps j unwrapped (the tables have count + 4 entries, the last ones repeat the first with the sign flipped); any other path limits j to count - 1. q1 = slerp(Q[i], Q[j], f), q2 = slerp(C[i], C[j], f), out = slerp(q1, q2, 2 f (1 - f)), all with mode 2, normalised by 0x1ff9cc. Q is the block of the path record +0x10 (path+8), C the block after it (record +0x14, path+0xc), both 16-byte quaternions from block offset 0x40; the C++ loader now reads C as `LevelPath::orientationControls`.

**0x21a600(out, a, b, mode, t).** dot = a.b summed in the order x, y, z, w. Mode 2 keeps the sign; any other mode negates the dot and b's weight when (dot < 0) differs from the mode (mode 0: the shortest way, as 0x270b70 uses it). A dot whose bits exceed 0x3f7fff58 blends with 1 - t and t; otherwise theta = acos(dot) (0x21bbb8) and the weights are sin((1 - t) theta) / sin theta and sin(t theta) / sin theta (0x235dc0). 0x248870 makes the rows 1 - (yy + zz), xy - wz, xz + wy / xy + wz, 1 - (xx + zz), yz - wx / xz - wy, yz + wx, 1 - (xx + yy) and leaves the translation alone.
