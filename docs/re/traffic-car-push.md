## 2026-11-12T00:04:45+01:00 — The push of a character by a traffic car, message 45 of the characters and the cop whistle state (llvm-objdump of game.arm.elf only; no REA session, no emulator)

Evidence: round 20261111-chase, agent 20261111-chase-F, 2026-11-12; llvm-objdump (armv6k, vfp2) of 0x2baef0..0x2bb180, 0x18e4c8..0x18f680 (case 45), 0x283d0c..0x283eb8, 0x242554, 0x229948, 0x24092c, 0x250da8, 0x2408c4, 0x257e78, 0x257f14, 0x247f00 (to 0x247c90, the library cosf), 0x200354..0x200c04 (the player input), 0x276338, 0x29a2e0, 0x26e254, 0x241098 and the entity message dispatch 0x244fc8. Pinned by CTest `traffic-car-push` (`tests/traffic_car_push_test.cpp`).

**0x2baef0(car, move, entry, list, count, slide).** owner = entry +0x10.
1. Nothing (result 0) when 0x1fc508(car, owner, 0) says the pair does not collide, or when hword +0x10 of the car or of the owner lacks bit 0x200.
2. The push vector starts as four zero floats (the constant 0x56d3a0) and 0x1f49d8(car, move, entry, vector, slide) fills it; without a hit the result is 0.
3. Message 45 goes to the owner (0x244fc8, args {car, vector}). Without slide the result is 1.
4. With slide: when the owner's word +0xc has bit 3 and 0x245b00(car) holds, 0x233594(car, owner, 0) runs and the result is 0.
5. Otherwise every entry of the list whose owner is neither the car nor the owner, whose owner has hword bit 0x100, whose word lacks bit 1 and which does not ignore the car (0x1fc508) is tested with 0x1f49d8(car, move, entry, no vector, slide); the first hit ends the loop. The loop has no other effect.
6. When the car has hword bit 0x2000 or the owner has bit 0x100, message 45 goes to the car with {owner, 0} and the result is 1.
7. Else, with m = the owner's node matrix, every entry whose owner has bit 0x200 and does not ignore the owner (0x1fc508(owner, o, 0)) is tested with 0x1f49d8(owner, vector, entry, second vector, 1); on the first hit the entity o moves by the second vector (0x23d39c on its matrix translation, then 0x24c118) unless it has bit 0x100. Last, m moves by the vector and the owner's node is set. The result is 0.

**Message 45 of the characters.** The character class (kind 27) registers 0x18e4c8 as its message handler (slot +0x14 of the descriptor registered at 0x16d868). Case 45 (0x18ef8c) tail-calls 0x283d0c(entity, ctrl, args). It sends event 17 (`0x21e1d4(ctrl +0x50, entity, 17, args)`) always. With args and a sender (args +0): a character sender (0x245b00) gets event 18 with the character; a sender of kind 179, 183 or 243 is the hit test. Test: p = the car's local point (+0x60) times its node matrix (0x250da8), moved along row 2 by half the car's z half-extent (+0x74) x 0.5 (0x283ea8); d = (the character's position - p) . row 2 (0x257f14, 0x257e78); q = the signed forward speed of the vehicle body, 0x229948 = the dot product of the body's forward row (body +0x24) with the velocity at (body +0x7c) +0x13c (body = entity +0x84; see [pedestrians-inputs.md](pedestrians-inputs.md) and [vehicles-physics.md](vehicles-physics.md)). It hits when q >= 5.0 (0x283eb0) and d >= cosf(70.0) (0x283eac, radians: 0.6333). The hit is message 0 with the 28-byte record {move 0, sender the car, damage 1 when the character is *0x3772c0 else 0, force q (the forward speed), kind 3, weapon 1}, the record of [combat-characters.md](combat-characters.md). At the end ctrl +0x315 bit 2 is cleared. The handler answers 0 and ignores every message while the state is 82.

**The cop whistle.** The player input 0x200354 (player branch only) reads, in this order: 0x2369a8(19) (bit 19 of the extras mask *0x374724, which no loader fills: [save-format-state.md](save-format-state.md) says it is 0 after a load, the menu toggles set it), ctrl +0x6c = 1, the press edge of slot 1 (channel 13, D-pad Down, [arm-executable.md](arm-executable.md)), ctrl +0x13c = 0 and the byte +0x20 of the player's row of the character table (*0x372e10, stride 0x28) = 3; then it requests state 0x1b2 (0x2414b4). State 0x1b2 (table 0x357a08): enter 0x276338 starts the clip row 709 (0x21941c, blend 0.1, speed 1.0, mode 0) and continues into 0x26e254; update 0x29a2e0 requests state 1 when the clip's slot has finished (kind 6 of 0x22f560). 0x26e254 sets the stop end to 0x241098() + 0x235498(60) + 120. The clock 0x241098 is a timer total times the rate [[P + 0xc] + 0xc] = 30 over the divisor 3000 ([props-rocking-attach.md §2026-10-28T00:40:30](props-rocking-attach.md#ts-20261028-004030)), and the clock advances 100 ticks per update ([arm-executable.md](arm-executable.md)): which would be 1 unit per update and a stop of 120 to 179 updates (4 to 6 s). This is not established: a trap measured +0.99 per stepped update and the use markers count 2 per update (SCRIPT-S247, SCRIPT-S297), and the timer unit of 3000 per second is unread (SCRIPT-384). The port uses 1 per update as the stand-in TRAFFIC-S33.

**Port.** `src/runtime/traffic_car_push.*`: `makeTrafficCarPush` (the hook `push`), `receiveCarPush`, `copWhistleRequested`, `enterCopWhistle`, `updateCopWhistle`, `gameClockAfter`. The world is hooks: nothing in the port supplies them yet, so no car pushes a character in play. The whistle is not requested in play: the extras mask is 0 after a load, which is what the original does by default.

Unknowns:
- 0x1f49d8 (the push vector and the shape test; it calls 0x287ac4, 0x21bb78, 0x250da8, 0x23f50c, 0x22ec3c and more), the squash 0x233594, and what the states do with events 17 and 18 (0x21e1d4 chain).

## 2026-11-12T08:05:53+01:00 — The cop whistle request, state and clock connected in chase-game (llvm-objdump of game.arm.elf only; no REA session, no emulator)

Agent 20261112-traffic-E. Read again: the request in the player input 0x200354, 0x2008a4..0x200924, in order: 0x2369a8(20) (an unrelated call to 0x2840d4), then 0x2369a8(19) = 0, skip; ctrl +0x6c (hword at 108) = 1; the press count of pad slot 1 (halfword at record +0x10 of the pad table with stride 20) non-zero; the word ctrl +0x13c = 0; the byte +0x20 of the row `ctrl +0x2cc` x 0x28 of the character table (*0x372e10) = 3; then 0x2414b4(entity, ctrl +0x50, state, 0) asks for the state 0x1b2. This confirms the entry above.

- **ctrl +0x13c is the carried object.** [carrying.md](carrying.md) (and carrying-animation.md) set it from the attach hook 0x2ce4a4 and read it as "something is carried". So the whistle needs empty hands; the port's `carry.carryingMode() != 0` stands for it.
- **The byte +0x20 of the character row** is indexed by ctrl +0x2cc, the character enum of the player. Its meaning is not read; the port plays one player character and takes the byte as 3 (TRAFFIC-S43, TRAFFIC-60).
- **The extras mask** `*0x374724` is 0 after a load, so the whistle never starts in a normal run, as in the original. The development option `--extras MASK` sets the mask for a run (bit 19 = 524288); the same mask answers `IsRedBrickExtraActive`. The menu that toggles bit 19 is not recovered.

**Port.** `src/runtime/player_cop_whistle.*` (`PlayerCopWhistle`: the request through `copWhistleRequested`, the enter through `enterCopWhistle`, the update through `updateCopWhistle`); glue `src/game_cop_whistle.cpp`: the D-pad Down press edge is pad slot 1, the state is `playerControllerState` (idle only with free hands, outside vehicles and scripts), the clip row 709 is loaded from the player's animations and its length in updates ends the state (the arrest's rule), the clock is `gameClockAfter(update)` for the enter and for `TrafficDriveStep::clock`. While the state runs the player stands and plays the clip. The clip `whistle` (row 709) is in the player's class folder `models/char_minifig/class_police/` and is 22 updates long in the port's decoding; that it lives with the police class fits the character row byte +0x20 = 3 but is an inference, not read. Log lines: `cop whistle: player state 434 at update N`, `cop whistle: player state 1 IDLE at update N`. No binding is added: D-pad Down already has its keyboard binding ([controls.md](../controls.md)).

Unknowns:
- The clock unit and its value at the level start (TRAFFIC-59); the meaning of the character row byte +0x20 = 3 and the menu toggle of extra 19 (TRAFFIC-60).
- Whether the clip's slot reports finished (kind 6) on the update the port ends the state; measured in neither.

## 2026-11-12T08:17:17+01:00 — The push vector 0x1f49d8, the squash 0x233594 and the listeners of the events 17 and 18 (llvm-objdump of game.arm.elf only; no REA session, no emulator)

Evidence: round 20261112-traffic, agent 20261112-traffic-C, 2026-11-12; llvm-objdump (armv6k, vfp2) of 0x1f49d8..0x1f5058, 0x25b390, 0x23f50c, 0x227790, 0x258858, 0x237b8c, 0x237eb4, 0x2536a8, 0x23ba14, 0x2554c0, 0x257f14, 0x23d39c, 0x250da8, 0x23d434, 0x257ea0, the call site 0x2bafc0, 0x233594, the event dispatch 0x21e1d4 / 0x1eb8c4, the listener initialisers 0x34eb60..0x34ec58 and 0x34ffdc..0x3500ec, the state construction 0x1e09f4, the attach functions 0x268e24 and 0x28b96c, the handlers 0x3305fc, 0x334888 and 0x1e3040; words of the image read with a throwaway script (0x1f4d1c..0x1f4d2c, 0x1f5054, 0x376910, 0x377130, 0x377138, the vtables 0x3655f4 and 0x36583c). Pinned by CTest `traffic-push-world` (`tests/traffic_push_world_test.cpp`).

**0x1f49d8(mover, move {x, y, z, turn}, entry, vector, slide).** owner = entry +0x10; M = 0x21bb78(entry) (the owner's node matrix times entry +0x14); a vector is cleared (0x25b390). When both the mover and the owner have hword +0x10 bit 0x100, slide is cleared. The turn is 0 on every call of 0x2baef0 (the contact slide passes (move, 0.0), the second push the four zero floats 0x56d3a0).
1. A mesh entry (entry +0x1c set): 0x287ac4(mover, move, entry, 93, 3, *0x376910, 0.0) (only a pure turn takes 0x287ac4(mover, null, entry, 80, 0, ...)); no hit gives 0. A hit with a turn and slide turns the mover (0x2536c0, 0x23b998, 0x23b960, 0x17e3c0, 0x20b214, the slide 0x23d434 with 92, then the node); every hit stores the owner in *0x377134 and gives 1.
2. A box entry whose owner's kind (+0x12) is in the list 0x58d9b0 (count *0x377138, 0 in the image's data) gives 0.
3. The mover's world centre c = mover +0x60 times its node matrix (0x250da8); the moved centre p = c + move (0x23f50c). The box is the 6 floats at entry +0x18 (the owner's +0x60 / +0x6c). When |M row 1 y| < 0.99 (0x1f4d2c, compared as bits) and neither the mover has bit 0x2000 nor the owner 0x900, the box becomes its world box (0x22ec3c), its centre minus M's translation, and M a copy (0x258858) with an identity rotation (0x237b8c).
4. A mover with 0x2000 or an owner with 0x900: with owner 0x800, for each part i of the owner node's record +0xc0 (byte +8 = 2, parts +0x14, count hword +2) 0x27f174(mover, move, part box, part matrix 0x236368 x M, c, p, slide); else 0x27f174(mover, move, box centre, box half, M, c, p, slide). A hit stores the owner in *0x377134 and gives 1; the vector is not written.
5. Otherwise q = p in M's frame (0x237eb4: (p - t) dotted with the rows) minus the box centre; a hit needs -h < q < h on each axis with h = box half + the mover's half extents +0x6c (open bounds). Without slide a hit gives 1 (no store in *0x377134).
6. With slide: L = |move| (0x2536a8); d = the mover's translation minus M's in x and z, normalised (0x23ba14: (0, 1) when the length is at or below 2^-23), times L, times 0.5 (0x1f5054). The pushed entity's vector is (-d.x, -0.0, -d.z); 0x23d434(owner, vector, 88, 17, 0.0, 0.0) slides it (0x208d84 with the owner's world box); the mover's own move (d.x, 0, d.z) gains what the slide changed (after - before), 0x23d434(mover, it, 92, 17, *0x376910, 0.0) slides it, and its node translation gains its x and z (0x24c118). The result is 1. So both sides take half of the move's length apart, and the mover takes what the pushed one could not.

**The squash 0x233594(target, sender, weapon).** Message 0 to the target with {no move, sender, damage 32000, force 0, kind 0, byte +0x15 255, weapon}. In 0x2baef0 (0x2bafc0) the target is the mover and the sender the pushed owner: a pushing character (0x245b00) is squashed by an owner with word +0xc bit 3. A traffic car is no character, so it never runs for one.

**Events 17 and 18.** 0x21e1d4 hands an event to the listeners of the state on top of ctrl +0x50 (0x1eb8c4: listener +4 the type, vtable +8 the handler(listener, entity, list, state, type, argument)). Only two pairs of listeners have the types 17 and 18 (every listener built before an atexit registration 0x248518, and no listener in the data segments): `leGOCSSuperKnockback_ColliderEvent` / `_CollideeEvent` (0x58d908 / 0x58d914, vtable 0x3655f4, handler 0x3305fc), attached by 0x268e24 to the state object 0x58d920 (id 0x99), and `GOCharacterThrowFinisher_ColliderCollisionEvent` / `_CollideeCollisionEvent` (0x5158d8 / 0x5158e8, +0xc = 15, vtable 0x36583c, handler 0x334888), attached by 0x28b96c to 0x5158f8 (id 0x199). Types 15 and 16 are the floor and ceiling events of the same states. In every other state the events do nothing.
- **0x3305fc (state 0x99).** Event 17 with args and a sender (args +0), or event 18 with an entity: message 0 to it with {no move, no sender, damage *0x377130 (1 in the image's data), 0, kind 0, weapon 0}. Then, for every event it gets, 0x23cd80(self, 0): the character is destroyed.
- **0x334888 (state 0x199).** Event 17 with args (a null sender, *args = 0, still reaches 0x1e3040, which reads byte +0x12 of null in 0x245b00; the port skips the null sender, which the car push cannot send, as its sender is always the mover) or event 18 with an entity calls 0x1e3040(listener, self, other) with the record {no move, sender self, damage 1, force 0, kind = listener +0xc (15), weapon 0}. A character other (0x245b00) for which 0x22716c holds: nothing when its ctrl +0x140 is self, 0x23a70c(ctrl, 52) holds or 0x21a2d4(other, self, 8) fails; else ctrl +8 and +0xa = (int) (atan2f(n.x, n.z) x 10430.378) with n = self - other normalised (0x257ea0), 0x23deb4(other), byte +0xe of [ctrl +0xe0] = 1 and 0x22e884(other, ctrl, record).
