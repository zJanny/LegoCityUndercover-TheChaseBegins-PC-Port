# Shadows: the shadow light, the shadow camera and the receiving stages

Reverse-engineering findings. Entries are chronological. Addresses are for the Europe v1.0 build. Feature file: [rendering-shadows](../plans/features/rendering-shadows.md). Related: [materials.md](materials.md), [rendering-lighting.md](rendering-lighting.md), [object-kinds.md](object-kinds.md).

## Current state

- The shadows are a shadow map, not blobs: the first light with `CastShadows` renders the mesh nodes flagged `Shadow_Caster` into a 512 x 512 PICA shadow texture through an orthographic camera (scale 1 / `ShadowRadius`, depth 1 to 76) placed 51 m back along the light's forward axis from a focus point ahead of the game camera. Draws of nodes flagged `Shadow_Receiver` bind that texture on unit 0 and append two combiner stages that darken by the shadow constant. [§2026-10-27T19:02:08](#ts-20261027-190208)
- Characters, vehicles and most props cast and do not receive; the room models and some props receive. lvl_01's shadow light is `Directional01` (opacity 0.6 of its class, black, radius 15). [§2026-10-27T19:02:08](#ts-20261027-190208)
- Oracle outside the police station after mission 1-1: the focus, the shadow camera's axes, y and z, the projection, the constant 0x999999 and the darkness of the player's shadow (0.37 to 0.39 of the lit ground, port 0.40) agree with the port; the shadow camera's x is 2.08 m further in the oracle. ## 2026-10-27T19:02:08+01:00 — The shadow map: light, focus, camera, casters, receivers and the two stages (REA Ghidra 12.1.2 and llvm-objdump on `artifacts/game/game.arm.elf`, oracle RPC request 20261027-graphics-B-1)

Round 20261027-graphics, agent 20261027-graphics-B. REA (Ghidra) decompiled 0x1dc680, 0x2ca6e8, 0x203b34, 0x1ceb74, 0x1c1b68, 0x1959c4, 0x27c724, 0x2e4858, 0x1c1b50, 0x12956c, 0x2128c8, 0x188778, 0x265a1c, 0x205160, 0x22e7c4, 0x21bbbc, 0x1c22d0, 0x1cfb1c, 0x21db64, 0x1d0838, 0x2def8c, 0x32ccd4, 0x170d90, 0x2d7590, 0x22dedc, 0x241118, 0x1ef12c and 0x17e27c; the rest is llvm-objdump. The oracle values were read by the servant (20261027-graphics-servant, 2026-10-27, recorded from a save state outside the police station after mission 1-1, OpenGL, RPC, one load).

**0x37796c is the per-draw render state block**, not a shadow texture. Byte +0 is set by 0x129560 for each draw: 1 when the shader program has the `Shadows` uniform (program record word 0x2e), the material is no reflection material (0x37796d = 0), 0x3767f5 (the draw's receiver bit) is set and 0x52a430 (shadow lights drawn this frame) is not 0. Byte +1 is the reversed unit order of reflection materials (materials.md). +4 is the current shader program, +0x14 the shadow opacity, +0x18 the packed shadow constant, +0x1c the bound texture units.

**The shadow light.** The light record (built by 0x23a9fc at entity data +0xb8, layout in rendering-lighting.md) has `CastShadows` at +0x3c (data +0xf4); 0x23aa24 forces it on for LightType 5. 0x22dedc (each frame over the registered lights) reads for a casting light `ShadowOpacity` (default 0.5) into 0x101864, which clamps it to 0..1 into 0x377980, and `ShadowColour` (0..255 floats, default the vector at 0x56d400) into 0x265dd8, which packs per channel trunc((255 - c) x opacity + 0.5) into 0x377984. 0x1b20bc (level start) writes the `ShadowRadius` (default 15.0, literal 0x1b22cc) of the first enabled directional casting light to 0x516418; 0x2e6264 reads the level's own `ShadowRadius` (default 15.0, literal 0x2e6710) into the same word. 0x1ceb74 calls 0x1dc680 for each casting light that is not switched off; 0x1dc680 takes only the first one (0x52a430 becomes 1), puts the light's shadow target (light data +0xf8, made by 0x17e27c: texture 512 x 512, 1 MB) into 0x376804 and builds the shadow camera with 0x2ca6e8. The crane minigame of mission 3-5 moves the shadow from `Directional01` to `CraneMiniGame_Light` and back (0x2d7590, 0x1ef12c).

**The focus** (frame pass 1 of 0x2e4858): when the player's height comp+0x240 is less than 0x516418 from the camera's y (camera entity 0x376890), the vector (0, [0x52a17c], -[0x52a178]) times the camera matrix (0x249ee8, row vector) is the ray; when its y is negative, t = (player y - camera y) / ray y clamped to plus or minus 0.8 radius (0x2e4d5c), point = camera + t ray, then point += 0.8 radius x normalise(camera row 2 with y = 0). 0x1c1b68(radius, -50, 25, point) stores the point at 0x530844, the radius at 0x376800, -50 at 0x376808 and 75 at 0x37680c. Otherwise the previous values stay. The scanner view (0x51641e) sets 0x52a430 = 0, so no shadow is drawn there.

**The shadow camera** 0x2ca6e8: when the focus is closer than 0.8 radius to the camera, it moves forward by the difference along camera row 2. The camera takes the light's node matrix with the position focus + (near - 1) x light row 2, orthographic (0x21255c), scale 1 / radius on x and y (0x212548), aspect 1, near 1 and far range + 1 = 76; the projection goes to 0x530850, the camera matrix to 0x52a434. Pass 2 (0x1959c4) renders the caster list (0x530654 .. 0x530664, filled for nodes with draw mask 0x40, which 0x22e7c4 sets with the caster bit) into the target between 0x293840 and 0x29fdbc; it flips the cull bits of the materials at 0x530124 when the light's forward and the camera's forward point apart (dot product compared with plus or minus 0.1).

**Casters and receivers.** 0x1c22d0, 0x1cfb1c and 0x21db64 read the bool parameters `Shadow_Caster` and `Shadow_Receiver` (default 0) of every placed entity with a node tree and set bit 0 (0x22e7c4) and bit 1 (0x21bbbc) of +0xde of every mesh node (type 0x37674c) of the tree. The room setup 0x1c3098 sets the receiver bit on the root node of a room scene record (0x1d0838) when its +0xc byte is 0. Of the shipped classes all 308 `chars/` classes and all 53 `vehicles/` classes have caster 1 and receiver 0; the props and leprops are mixed (for example `props/parkour_railgrab`: caster 0, receiver 1). The draw lists 0x188778, 0x265a1c and 0x205160 copy the receiver bit into 0x3767f5 for each node they draw.

**The receiving stages.** For a receiving draw 0x12df94 binds the target's texture (0x130bd8 returns target + 0x94 when its data pointer +0xb0 is set) on unit 0 with parameters 0x20101106 (shadow 2D texture, linear, clamp to border, border white) and shifts the material's textures to units 1 and up; the material key gets bit 18. 0x129560 loads the shadow matrix uniform: a bias (u = 0.5 y + 0.5, v = -0.5 x + 0.5 for the rotated screen) times the shadow projection times the inverse view 0x52a090. After the material's stages 0x12ecd4 appends, when the key bit is set and at most four stages are used: source (texture 0, constant, constant), operands (colour, colour, 1 - colour), combiner 8 (multiply then add), constant 0x377984; then (previous, previous buffer), combiner 1 (modulate), with the buffer taking the output of the stages before. So the colour is multiplied by texture0 x k + (1 - k): 1 where lit, 1 - k / 255 in shadow (0.4 for black at opacity 0.6).

**Character ground probe.** 0x203b34 (called from the character updates) runs the ray 0x22f134 below the character only when bit 2 of comp+0x316 (EnableShadow, `ATTR_HasShadow` in the character setup 0x236e2c) is set and stores the hit height at comp+0x244 (else -FLT_MAX); no reader of it in the shadow passes was found.
