### The class

- 56 files under `levels/vehicles/`: 52 vehicle classes (`vehicle_police_trooper`, `vehicle_van_donut`, ...), `wheel`, `vehicledrop_*`. Every vehicle class file carries the object type **ObjectType = 0xb7 (183)**. 27 objects of lvl_01 are vehicles (trooper 3, caravel 3, donut van 2, ...). `1-1_Police_Car` (room8, 887.38 17.80 1117.32, yaw 224.8) has `SpawnParked` 1, `SpawnUnshovable` 1, `MusicTrack` 12. `1-1_DonutVan` (room33, 869.45 53.81 691.87) and `1-1_DonutVan01` (room8, 820.46 18.57 1051.93, yaw 180.3) set nothing but `MusicTrack` 16 or no flags.
- Class descriptor for type 183: built at 0x155b5c (`mov r0,#183; bl 0x246240`, same layout as the door descriptor in [doors.md](doors.md#ts-20261013-211700)): create 0x156ee4, post-link 0x15624c, destroy 0x159b9c (13 instructions), update 0x1571dc, slot +0x10 0x157190, message handler 0x159bd0 (172 instructions), release 0x1571a0, link 0x156f74. **Read** (create, post-link, link, update); handler **partly read**.
- Entity layout (as far as read): entity+0x7c = the vehicle record (0x350 bytes, allocated by create), entity+0x84 = the physics body (0xdd4 bytes, built by 0x33ce74 with the descriptor at 0x5863b4), entity+0x12 byte = object type, +0x10 u16 = owner flags.
- Create 0x156ee4 (36 instructions): allocates entity and record, zero-fills, calls the generic object set-up 0x2442b4, sets bit 5 of byte +0xde of the model's first resource when its type bits equal `*0x37674c`.
- Post-link 0x15624c: `numWheels` (class value 4 for trooper and donut van) into record +0x314, record +0x318 = array of the wheel objects found by name `Wheel%02u` (0x2450f0), each wheel's scene node attached under the vehicle node; ends by calling the base post-link `(*0x584d20)`.
- Link 0x156f74 (139 instructions): builds the body (0x33ce74), re-finds the wheels, runs the five handling loaders **0x243f90, 0x243e9c, 0x243c50, 0x243628(entity, numWheels, wheels), 0x2435d0**, sets `BumpCollision` (bit 0x10000 of body+0xc4), copies per-wheel data with 0x1cb7f8 into body+0x2b8 + n * 0x154, calls the base link `(*0x584d38)`, registers the body with 0x243300 and 0x2432d8 / 0x2432bc (depending on entity flag bits 0x4 and 0x400). **Read.**
- Parameter reader 0x23ed0c (called by the handler after message 0x80000000, i.e. after the instance parameters exist): `VehicleType` → record +0x2ec (index into the vehicle table, below), `MusicTrack` → +0x2ee, `NoMusic` (bit 2 of +0x312, inverted), `DriverPosition` (float3 → +0x27c, flags 0x2000030), health: byte +0x30c = 100, +0x30e = health from the vehicle table (+8), +1 when `0x2369a8(0x10)`, +0x30d = +0x30e, `HealthOverride` (default -1; above 0 replaces both), `Invulnerable` (+0x311 bit 2), `ATTR_CameraOverride` (+0x311 bit 0), `ATTR_CameraPosY/PosZ/LookY/LookZ/PanScale` → +0x2f0..+0x300, `RC_Vehicle` (+0x311 bit 4), `BigHitOnContact` (+0x311 bit 5), `PlayerDisable` (+0x311 bit 1), **`SpawnUnshovable` → state word (+4) = 10, else `SpawnParked` → +4 = 4**. **Read.**

### Record flags and fields used by the natives

| Field | Meaning | Writer |
|---|---|---|
| +2 u16 | current state | state step |
| +4 u16 | requested state (a state change happens when +4 differs from +2, see 0x2424d0) | parameter reader (4 parked, 10 unshovable), VehicleSetUnshovable (10), stuck rule in 0x16ce9c (8) |
| +0x288 / +0x28c / +0x290 / +0x294 | steer / accelerate / brake / hand brake inputs of this update | player input 0x29cd9c, AI input |
| +0x311 bit 1 | **locked** (cannot be entered; also `PlayerDisable`) | VehicleSetLocked 0x26fe78 → 0x192dcc; checked by the vehicle search 0x225d94 |
| +0x311 bit 6 | **jump out not allowed** (set when AllowJumpOut is 0) | VehicleAllowJumpOut 0x27c014 → 0x1fd6b4 (stores `!arg`) |
| +0x310 byte | **forced stop** | VehicleSetForcedStop 0x29ea7c → 0x229be4; SetForcedStopOnMyVehicle 0x2b9df0 (the player's vehicle, nothing when on foot); StopPlayerVehicle 0x27c040 |
| +0x31c float | stuck timer | 0x16ce9c (above 2.0 seconds → state 8) |
| +0x2a4 | link to another entity (towed / carried, flag +0xaf bit 0) | not read |

### Handling data

- **Class file parameters** (same names in every vehicle class; values are the trooper's, the donut van differs): `Mass` 1300 (van 2000), `dtPower` 0.3 (0.5), `dtFinalDrive` 5, `TopSpeed` 28 (30), `AirYaw` 200, `AirPitch` 80, `Gravity` -13, `DampingLinear` 0.02, `DampingAngular` 0.1, `CentreOfMass`, `InertiaScale`, `CollSpheres` (float3, collision spheres), `numWheels` 4, `Redline` 6900, `MaxRPM` 7500, `IdleSpeed` 900, `Inertia` 0.15, `Friction` 0.025, `WheelDriveRatio` 0.3 (0.2), `WheelSuspensionRatio` 0.65, `WheelSuspensionScale` 1 (0.75), `SteeringLockMin`, `Alt*` steering values, about 40 more hashes that are not in the strings of the executable (they are built with format strings, e.g. per gear or per wheel; `%sWheelRadius`, `%sWheelFrictionStatic`, `%sWheelFrictionDynamic`, `%sWheelInertia`, `%sSkidWidth`, `%sWheelWidth` are the loader strings at 0x243acc..0x243b28), sound ids `ATTR_SFX_START/STOP/IMPACT/DESTROYED/SKID/WHEELSPIN/REV_LOOP`, `ATTR_RevMin/MaxFrequency`, `SirenSFX` (trooper), `EmergencyLightPattern`, `BrakeLightParticle`, `TrafficHeightOffRoad`, camera `ATTR_Camera*`, and the child objects `Wheel01..04` (class `vehicles/wheel`, mesh `Veh_Wheel_20x12`) plus light objects. The handling data is therefore in the class files (one parameter record of about 120 entries each), not in a separate table. Loader functions: 0x243f90 (steering), 0x243e9c (alt steering), 0x243c50, 0x243628 (per wheel), 0x2435d0, 0x2441d0 (suspension scale, final drive).
- **Vehicle table** (`tables/tablescharacters.bxls` sheet 4, 49 rows, runtime pointer `*0x372e14`, stride 0x18): row = `VehicleType` (trooper 22 = 0x16, donut van 36 = 0x24 — both match the class files). Columns after the name: price (50000), **health (trooper 5, others 4; record +0x30e)**, a hash, a flag, **horn sound id in the row's field at +0x12 (735..740)**, and a last flag. The horn reads it in 0x29cd9c.
- Sounds under `sounds/vehicles/` (engine start / rev per car, horns, siren, skid); music: `MusicTrack` (1-1 police car 12, donut van 16) is started by 0x2a39f0 for the player's vehicle in 0x23019c, `VehicleEnableDrivingMusic` (0x2bf2b4) toggles it.

### Per-update path (all **read** unless noted)

1. 0x1571dc (update, 199 instructions, 96 in its own body): enables or disables the body by the scene's active flag (0x2426e4), then picks the **input provider**: none while the vehicle is frozen (record +0x312 bit 0), **0x29cd9c when this is the player's vehicle** (`0x24255c(*0x3772b8) == entity`), else **0x1d8df0** (AI / parked drivers, not read), or 0x26d934 when linked to a tow partner. Second callback is 0x16ce9c. 0x2424d0 runs provider, then (when +4 == +2) 0x16ce9c. Also toggles the wheel child objects between attached and detached by distance to the camera (LOD), counts down timers +0x304 and +0x308, and calls 0x1765cc.
2. 0x29cd9c (player input, 25 instructions): steer = slot 0 value, overridden by the two d-pad slots (-1 / +1); accelerate = slot 6 (A) > 0, brake = slot 7 (B) > 0; both forced to 0 when record +0x14 as a float exceeds 0.75; slot 9 pressed → horn (sound id from the vehicle table, 0x2e4 when `0x2369a8(7)`), through 0x229e80.
3. 0x23019c (input to physics and effects, about 430 instructions): honours forced stop (+0x310 → brake 1, accelerate 0, steer kept), sets the hand brake in states 3, 4, 11, copies the four inputs to the body (body+0x1bc steer, +0x1c0 accelerate, +0x1c4 brake, +0x1c8 hand brake), runs the engine sound / effect machine (record +0x2dc), starts the track `MusicTrack` for the player's vehicle in state 4 (`0x2a39f0`), emergency lights and the idle timer for the stuck/exhaust effects.
4. 0x16ce9c (post step, 130 instructions): runs 0x23019c (or 0x1bc79c when linked), clears body flag 0x100000, **stuck rule**: when the float at node+0x14 (compared as an integer) is below 0.2 and the entity is not frozen and the body speed is below 2.0, +0x31c accumulates dt; above 2.0 s the requested state becomes 8 (not read further). Then the wheel-contact test 0x275c00 (called unless the state is 2, 3, 5, 8, 9), the type-7 hook 0x1d44f0, 0x1d8d58 and 0x28f8b0.
5. The **physics body** class (vtable 0x365910: +4 0x33d06c, +8 0x33aea8 update with 119 instructions, +0xc 0x33c3e8, +0x18 0x33c434, ...; constructor 0x33ce74 sets default parameters and a 0x154-byte record per wheel at body+0x2b8). **Located**: about 60 functions and 1,700 instructions are reachable from the update through functions with at most 8 callers (rigid body integration 0x33b084 with 189 instructions, wheel / suspension functions around 0x33b378..0x33cdfc, `0x20c0e4`). Not read.

### States of the vehicle record

Values observed in the oracle: 1 (traffic vehicle with a driver object), 4 (parked), 5 (driven by the player). Values seen as code constants: 3 (hand brake, local flag), 4 (parked), 6 and 7 (VehicleSetUnshovable does nothing while the current state is 6 or 7), 8 (stuck), 10 (unshovable), 11 (hand brake). 2, 3, 5, 8, 9 skip the wheel-contact test. The transition function (who copies +4 to +2 and what enter / exit do to the state) was **not found**. A state table with names would be a stronger source: the vehicle class has no state-name strings near 0x155be4 (that table belongs to the "Teleport MIB" character states).

### Entering and leaving (player side)

- The player's character controller (record at entity+0x7c, u16 at +0x6c is the active **locomotion state**) enters a driving state through `0x2414b4(entity, ctrl+0x50, state, 0)`: it checks the event veto hook `*0x377198`, then 0x2eafc8 pushes the state descriptor at `*0x3742c8 + state * 0x18 + 0x14`. Descriptors of the driving states are defined in data at 0x34e714..0x34e7d8 (name, id, three words): **"Drive Jump In" 0x11a (282)**, **"Drive Jump Out" 0x11b (283)**, **"Drive" 0x11c (284)**, "Drive Jump In Event", "Drive Jump Out Event", "Vehicle Enter Event" (0x34e7b0). Other seat states are 0x17e, 0x17f (383, used by VehicleJumpOut for characters in a vehicle), 0x19a, 0x19b (411, the second "driving" state) and 0x19c.
- **`0x24255c(entity)`** (4 instructions): returns the vehicle pointer ctrl+0x130 when ctrl+0x6c is 0x11c or 0x19b, else 0. It is the "player is in a vehicle" test of the trigger pass ([script-triggers.md](script-triggers.md#ts-20261014-155345)), of the vehicle update (player's vehicle input), of SetForcedStopOnMyVehicle and of VehicleJumpOut. **Read.**
- **Find a vehicle to enter: `0x225d94(character, excluded)`** (108 instructions): returns 0 when the character is carrying something (0x225754 == 2), has type byte 0x9f or ctrl+0x6c == 0x101; otherwise queries the world grid around the character (box ±5, descriptor mask 4, flags 0x200 / 3), accepts entities whose type byte is **0xb3, 0xb7 (vehicles) or 0xf3**, with owner flag bit 0 clear and **record +0x311 bit 1 (locked) clear**, and returns the nearest one whose distance (0x270498 against the entity's box at +0x60 / +0x6c) squared is below 4.0 (2 m) and whose height difference fits. **Read.**
- **Prompt: 0x1835d0** (character update, 224 instructions): for the player, when no driving state is active and ctrl+0xe0+0x130 bit 2 is clear, 0x225d94 decides whether the button prompt (HUD object 0x2ed) is shown; it plays the sound 0x22d7c0(9, 0) once when ctrl+0xe0+0x131 bit 2 allows entering. **Read.**
- **The enter / leave handlers.** Oracle (below): holding **X** next to a parked vehicle raises event 200 (0xc8) in the controller's event stack (0x21e1d4 chain, dispatch at 0x1eb92c), which calls **0x322a04** (37 instructions): it needs a vehicle (argument or 0x225d94), ctrl+0xe0+0x131 bit 2 set and +0x130 bit 2 clear, for the global player also 0x27bb24 != 0, then stores the vehicle in ctrl+0x130 and pushes state **0x11a** (jump in). 0x322aa4 ("Vehicle Enter Event", table entry 0x322aa0) was **not** called by X: if ctrl+0x6c is 0x11c or 0x19b and a vehicle is set it refuses (returns 0) when the vehicle entity's flag word +0xc has bit 4 set, when the vehicle's record +0x31c is above 0, or when its record +0x311 bit 6 (jump out not allowed) is set, otherwise pushes state **0x11b** (jump out); when not in a vehicle it runs 0x225d94, stores ctrl+0x130 and pushes 0x11a. A third entry 0x322b7c pushes state 0x157. The state functions of the driving states live in 0x31ff00..0x322900 (about 36 functions, 2,000 instructions: Jump In 0x3202f8, 183 instructions reachable; Drive update 0x307e7c, 1,136; event 0x320e3c, 748 / 1,092; Jump Out 0x32281c / 0x3222f4). **Located**; the animations (`ride_car_drive`, `ride_car_driveleft`, `ride_car_driveright` are rows 573..575 of `tablesanimations` sheet 1) and the node hand-over were not read.
- Events `PlayerVehicleEntered`, `PlayerVehicleExiting`, `VehicleChaseEnded`, `PlayerVehicleBoundEntered` are names registered at 0x15b944..0x15b990; the firing site of PlayerVehicleEntered was not located.

### Collision of vehicles

The collision doc ([collision.md](collision.md)) saw vehicle entities registered with mask 6 and owner flags 0x1341 (bit 0 set: excluded from the player's and the vehicle search's queries) or 0x1340. The code that sets +0x10 to these values was not found in the class functions above (create does not set them; the generic set-up 0x2442b4 or the scene registration may). The body has its own collision sphere data (`CollSpheres`, `ExtraColSpheres1`) and the level's `Collision_Vehicle` meshes and `collision_vehicle` boxes (mask 17, [collision.md](collision.md#ts-20261013-144500)) are what vehicles drive on.
