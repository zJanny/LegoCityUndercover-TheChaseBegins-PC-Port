# Script natives: the death of a character (message 1 of kinds 27, 121 and 242)

What DestroyProp / KillObject (and every other caller of the entity destroy 0x23cd80) does to a character: message 1 of the character handler 0x18e4c8, the fall-apart body 0x1d3b50 and its pool, the bricks, the stud drop and the respawn tail. Split from [script-natives-world.md](script-natives-world.md). For developers; no game assets.

## Current state

- Message 1 of the character handler 0x18e4c8 (case 0x18e93c) for kinds 27, 121 and 242: the mode is `DisableFallapart` & 3 (0 fall apart, 1 bricks, 2 vanish, 3 nothing); mode 0 lets a minifig (0x22716c: `CharacterEnum` not 145 for kinds 27 / 149 and bosses, the `IsMinifig` bit for 121, never for the mech 242) fall apart and treats any other character like mode 1 (bricks only with `SmashDebrisColour`, then 0x21e854, the disable and the rate-limited sound 0x21e734). No level file of the 856 names `DisableFallapart`, `SmashDebrisColour` or `IsMinifig`. [§2026-10-19T13:21:05](#ts-20261019-132105)
- The tail: the player's entity, every entity while 0x22b0b4 holds, and a character with `AIFriendly` and `AIRespawnIfFriendly` (default 1) come back (enabled, state 11); any other character drops studs (0x21e2e4 mode 1, count 0), is disabled and goes to 0x21e218 (AI respawn at its spawn point or 0x21decc). - The fall-apart body: a pool of four slots (0x374208, 152 bytes each) with the part objects BrokenHead / Body / Arm / Legs / Hips 01..04 of `levels/charbits.blvl` (the head is a dummy that carries the character's head node; the legs or the hips by a draw modulo 2); 32 updates of flight (gravity 0.075 per update, bounce 0.5, a line test of the part's bounds sphere, rest below speed 2.0 with x and z below 0.125), then 32 updates of blinking on bit 0 of 0x241098, then free; sound 548 at the start. - Open: the stud drop of modes 0 to 2 of 0x21e2e4, the respawn and AI after-death 0x21e218, the character sound table behind record +0x2c2, the unit of the clock 0x241098, the texture copy 0x270ae0 / 0x22ad0c and the head attach 0x22690c / 0x2268f4, the writer of 0x5163e8 + 0x25 and of byte +0x12e bit 5.

**Message data and order.** 0x23cd80 sends message 1 with a zeroed word (0x23ce88..0x23ce98), so byte 0 bit 0 is clear and r8 = 1 at 0x18e9f4 (the condition of the sound 0x21e734 in the brick branch). Before the switch: when the record word +0x130 (the used object) is an entity of kind 171, it gets message 8 (0x18e95c..0x18e974); r5 = the node's world matrix (0x250810 of entity +0x3c), 0x24ce78 on entity +0x44.

**Mode switch 0x18e994..0x18eaa8.** When bit 5 of the sub-structure byte +0x12e (record +0xe0) is set, the whole switch is skipped. No store to +0x12e sets bit 5 (the eleven `strb` to +0x12e in the image touch bits 0, 2, 3, 6 and 7; no `strh`/`str` covers it), so it reads as clear. The mode is bits 4 and 5 of +0x12f, written by 0x237010 from `DisableFallapart` (0x2451d0, default 0, int; the string at 0x2371bc).
- Mode 0: 0x22716c(entity) non-zero -> 0x1d3b50 (below); zero -> the brick branch.
- Mode 1 (and mode 0 without a minifig): with +0x12f bit 1 (`SmashDebrisColour` given, 0x237060) 0x23aebc(entity, &+0xb8, &+0xbc, 2, 1, 1); then 0x21e854, the disable 0x2428c0 and, with r8, 0x21e734.
- Mode 2: only the disable. Mode 3: no branch.

**0x22716c (minifig test).** No record: 0. Kind 27 or 149, or entity +0xc bit 14 (`Boss_IsBoss`, 0x242290 -> 0x27fcb4): the character byte +0x2cc is not 145. Otherwise 0x236b6c (the kind is in the list 0x3743ec, filled by 0x23e394 from the creates of 121, 159 and 242): bit 7 of +0x12e. The character byte comes from `CharacterEnum` (0x236d98, default 192); bit 7 of +0x12e is set from `IsMinifig` by the create of kind 121 (0x16c220, string 0x16c254) and cleared by the create of kind 242 (0x15a428); kind 159's create was not read.

**Colours.** `SmashDebrisColour` (0x2371e4) into +0xb8 and `SmashDebrisColour2` (0x2371f8, else the first colour) into +0xbc, each component converted to an integer and its low byte kept, alpha 255. 0x23aebc -> 0x20c938 takes the class's `DebrisColour` / `DebrisColour2` first, `DebrisRatio`, and `DebrisAmount` when above 0, else the fourth argument: 2 bricks.

**0x21e854.** 0x22af80(entity, 0, 0), 0x22ae28(entity, 0, 0) twice (the weapon slots the AI setup fills from a class parameter at 0x242290..0x2422d4) and the disable of the 12 attachment entities at sub-structure +0x28.

**0x21e734 (rate-limited sound).** The halfword record +0x2c2 (0x236fd0: from the table `*0x375f7c`, rows of 68 bytes, indexed by byte +0x21 of the character table row `*0x372e10 + 40 x CharacterEnum`); when it is not zero and either differs from the last one (0x377150) or the clock 0x241098 is past the last time (0x377154) plus 60, it plays it with 0x23ae84 and stores id and time.

**The tail 0x18eaac.** A debug print ("Game over man. Game over!" with the node position), 0x2b96c0 (only for the player entity `*0x3772c0`), 0x21e700 (the entry of the eight 64-byte records at 0x5187cc whose +0x2c is the entity gets 0x2459d8). Then the entity comes back when it is the player's, when 0x22b0b4 holds (signed byte 0x5163e8 + 0x25 equals 1; its writer was not read) or when record byte +0xdb bit 2 is set and `AIRespawnIfFriendly` (0x18ec40, default 1) is not 0: for the camera focus `*0x3772b8` 0x26d1f0, then 0x242cf0, 0x23f734(node, 0), state 11 through 0x2414b4 and record +0x174 = 0. Byte +0xdb bit 2 is `AIFriendly` (0x1c6f04, string 0x1c701c, default 0), read by 0x1c6e84 from the character setup 0x24166c (0x24227c) for entities that are not the player. Any other entity: 0x21e2e4(mode 1, count 0, the node position, direction 0x56d400, s0 = s1 = 1.0, stack 0, 0, 0, 30, 0, 0) when bit 5 is clear, 0x21e2e4(mode 0, count 30, ..., stack 1, 0, 0, 30, 0, 0) when set; then the disable and 0x21e218. Mode 1 of 0x21e2e4 takes the stud records 0..19 and becomes mode 2 when the next random word is a multiple of three (0x21e6ac..0x21e6d0); the 30 goes to 0x19913c as its third argument ([studs.md](studs.md) lists the stud modes as not ported). 0x21e218: when bit 0x377540 & 0x3771d7 or +0xdb bit 2, it frees the record +0xc8 (0x215988) and either hands over to 0x22471c (record byte +0x315 bit 7) or puts the node at the spawn position record +0xac (unless 0x2364cc), runs 0x22f03c, clears +0xdc bits 3 and 4 and idles (0x2246c0); otherwise 0x21decc.

**The fall-apart pool.** Created by 0x15ce3c (once, byte 0x377531): 0x25c030(608, 1, 1) = four slots of 152 bytes; per slot the entities `BrokenHead0N`, `BrokenBody0N`, `BrokenArm0N`, `BrokenLegs0N`, `BrokenHips0N` (N = slot + 1, looked up with 0x2450f0 in the object of 0x23b370) at +8, +0xc, +0x10, +0x14, +0x18, the sound 548 at +0x94, white node colour for all parts but the head, all disabled. In `levels/charbits.blvl` the head objects are `dummy/dummy` without a mesh; the others name `char_bits_body`, `char_bits_arm`, `char_bits_leg`, `char_bits_hips` (bounds half extents 0.36, 0.19, 0.17, 0.36 in x; the body and arm carry `upper_TEST.tga`, legs and hips `lower_Test.tga`).

**Start 0x1d3b50(entity).** 0x21e854; the first slot with byte +0 clear (none: the disable and return); +3 = 3 + 0x235498(2) (legs or hips); a head node left on the head part from an earlier use goes back to its owner; the character's head node (record +0x16c) is moved under the head part (0x245048, 0x22690c, 0x2268f4(head, 0)) and coloured white (0x23e110); +0 = 1, +4 = the entity; the character's world matrix copied (0x258858), translation y + (-0.6) for the head, then y - (-1.4) (so 0.8 above the node) for body, arm and the lower part (0x24c118); the upper texture found on the character's node for `upper_TEST.tga` (0x270ae0) or the class's `UpperTexture` put on body and arm (0x22ad0c), the same for `lower_TEST.tga` / `LowerTexture` on the lower part; +2 = 1, +1 = 32; per used part (0, 1, 2 and +3): the node under the scene root (0x245008), enabled, velocity x = (r - 0.5) x 2, y = 2.0, x again = (r - 0.5) x 2 (the second draw overwrites the first; z keeps its old value), the vector times 0.1 (0x248850), spin (third, second, first) of three draws (r - 0.5) / 4 (0x2501ac); then the character's disable, 0x23ae84(548, entity) and 0x21e734. r is 0x2345dc (16 bits of 0x25b2b8 times 2^-16).

**Update 0x16c100 -> 0x231a08**, called by the game update 0x2e5470 unless byte 0x377531 is set. +2 = 1 (flying): 0x22b1f8 for parts 0, 1, 2 and +3 (the head with the bounds of its child node when it has one), then +1 counts down; at 0 the slot blinks (+2 = 2, +1 = 32). Blinking: +1 counts down; at 0 the release 0x182348 (+0 = 0, the used parts disabled, the head node back under its owner's node with 0x2268f4(head, 1), or freed when the owner has no node); otherwise, when bit 0 of 0x241098() is clear, each used part is enabled when disabled and disabled when enabled. 0x182270 frees the slots of one entity (caller 0x1d4c50, an AI state).

**Part motion 0x22b1f8 -> 0x1d27f4**(0, node, bounds centre node+0xa0, velocity, s0 = the half extent x node+0xac, s1 = 0.5, s2 = `*0x37716c`, spin). `*0x37716c` is 0.075: the static initialiser 0x350708 stores it with 0.5 at +8 and 8.0 at +0x10, and the level setup 0x2e65f0 sets it again through 0x18cc90. 0x298274 is a nearest-hit line test (0x21ab20, filter record with 0x362298, 69, 16) from the bounds centre through the node matrix to that point plus unit velocity x radius plus the velocity. No hit: translation += velocity. Hit: the translation moves by (hit point - (centre + unit x radius)), the velocity becomes (v - 2 (n . v) n) x 0.5 (0x27c514), the rest of the travel (|v| - that distance) x 0.5; when |v| was below 2.0 and |x| and |z| of the new velocity are below 0.125 (bit compare with 0x3e000000) the node matrix is set and the step ends (no gravity, no turn); otherwise the translation moves on by the unit new velocity x the rest and the spin becomes (r - 0.5) / 2 from three draws (third, second, first). Then velocity y -= 0.075 and the matrix becomes T(-c) R(spin) T(c) M (0x24d434, 0x227790 a -= b, 0x237c48, 0x2588f4 A x B, 0x258c9c A x inverse(B) of a rigid B, 0x258a10 A x B). 0x23b998 gives the unit vector and the length ((0, 0, 1) at 2^-23 or less).
