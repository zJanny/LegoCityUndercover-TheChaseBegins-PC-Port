# Hand items: the objects a clip's hand item track shows

Every object that a clip's hand item track (hash 0xba1e5b53) names and that hangs on a bone of the character: the glass, the scanner, the handcuffs on the zipline, hammer, axe, whistle, tea cup and the rest of the 144 clips that carry the track. The track, the glass and the scanner were read first ([abilities-detective.md §2026-10-18T19:30:00](abilities-detective.md#ts-20261018-193000)); this topic holds the generic rule and the item list. Feature files: [abilities-detective.md](../plans/features/abilities-detective.md), [player-traversal.md](../plans/features/player-traversal.md).

## Current state

- One rule for every item: the event names the object and the bone (words 0 and 4 of the sub-animation's data block); a rise shows the object and hangs it on the bone, a fall hides it; nothing is special to the glass or the scanner. [§2026-10-27T18:27:37](#ts-20261027-182737)
- The 144 clips name 30 objects; 25 of them are in `levels/players.blvl` (the character's own items; the zipline grab, slide and dismount clips of each class name the class's own item, `Ability_Handcuffs` for police). [§2026-10-27T18:27:37](#ts-20261027-182737)
- The port loads an item's model when its first event arrives, keeps shown, hidden and bone per name, and draws it on the bone with the glass's matrix rule (DETECT-S8). [§2026-10-27T18:27:37](#ts-20261027-182737)
- Objects not in `levels/players.blvl` (`blowtorch`, `Prop_Key`, `Weapon_BaseballBat`, `Ability_GrappleBinding`, `Ability_GrappleBindingFX`) belong to other characters' clips and are not drawn. [§2026-10-27T18:27:37](#ts-20261027-182737)

## 2026-10-27T18:27:37+01:00 — The hand item track for every clip: item list, zipline and the generic rule (llvm-objdump of 0x1d5bb0..0x1d5d60 and 0x2450f0, C++ decoder dump of every clip of `models/char_minifig/class_*` and of `levels/players.blvl`; round 20261027-graphics, agent 20261027-graphics-A; no emulator)

**Handler (read again, objdump).** The branch of the event handler that runs the track (compare against the hash literal at 0x1d5eb0, loop from 0x1d5c24): for each animation slot of the entity (`+0x74` count, slots 284 bytes apart) and each track of the slot (hash array), a track whose hash is 0xba1e5b53 reads the two name words of the sub-animation's data block (`[block]` object name, `[block+4]` bone name). A positive change of the track's value calls the name lookup 0x2450f0 with the base entity and the object name, then 0x22acdc(entity, object, bone, 0) and 0x242cf0(object); a negative change calls 0x2450f0 and, when the object is found, 0x2428c0(object). The base entity is the result of 0x239678(entity) when that entity's kind byte (`+0x12`) is 65, else the event's entity (0x239678 was not read). 0x2450f0 itself is a lookup by name along the child links of the node (it takes a path with `.` separators), so it finds any child of the character by name; nothing in it or in the branch knows one item from another.
