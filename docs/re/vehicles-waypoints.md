**Reach test 0x17b0c8 to 0x17b4a0 (read).** The player's vehicle r6 is `0x22ec10` (the vehicle pointer ctrl+0x130 while the controller state +0x6c is 0x11a, 0x11b or 0x11c), else `0x24255c`. Kind 1 matches when: a named vehicle is set and equals r6; else r6 != 0 and (VehicleType byte is 0 or `0x229e6c(r6)` (signed byte of the vehicle record +0x2ec) equals it). Kinds 0 and 2 always match. With bit 2 of +0x8e (fired) clear, the first test is the player node in the bound (the foot test, as before). If it fails and r6 != 0, the second test 0x17b21c runs. It builds `O = W * inverse(V)` (0x258bc4; W the waypoint node matrix, V the vehicle node matrix, row vectors, translation in row 3), `u = (boundCentre - O.translation)` turned by the rows of O (0x229a40: `u'_k = dot(row_k, u)`), clamps `u'` into the vehicle box `[+0x60 - +0x6c, +0x60 + +0x6c]` (0x22997c; centre and half extents of the entity box, [vehicles-boarding.md](vehicles-boarding.md#ts-20261015-081549)), moves the clamped point `p * O3 + O.translation` (0x254250) and tests it with the bound (0x22f650, same shapes). The sign of the translation looks reversed against a true frame change; it is transcribed as read. A hit with bit 6 clear: kind 0 with r6 != 0 does not fire; unless the vehicle's name hash equals `5-8_Vehicle_RC` (0x24da28, case-insensitive) it shows the tip text key `0xa0fc8748` through 0x235fb4 / 0x235f30 (colour 0xffffad4a like the tip texts, 0.5 s, restarted every update the player stays inside). Other kinds set bit 2, state 2, timer 0.001 and store the player (+0x7c) and r6 (+0x80).
