**Message handler 0x1b59f0.** With `ReTriggerTime` above 0 only message 0xfc (the sound record's id through a callback) is answered. Otherwise:
- 0xff: 0x242cf0 (enable). A running emitter (+0x20) only gets 0x23619c(e, 0) (clears its "no new particles" bit 4 of +0x150). Else 0x23de24(0, definition, 0x56d400 (bss, read as the zero vector), parent = the node entity +0x3c, 0, 0, 0), or with `JustMoveSpawnPoint` the node's world position and no parent; on success the node's bounds are copied into the emitter (+0xa0, +0xac), a path is attached (0x215400), flag 4 and the timer are set as in the create, the callback 0x2c7984 is installed (0x23de14) and the shake 0x21535c runs.
- 0xfe: with an emitter and `Instance` 0: 0x23619c(e, 1), the emitter's parent link moved (0x245048 / 0x245008), +0x1c = the definition's +0x80 (0x18a0a4 returns the emitter's +0x144, the definition), 0x23ddb4(+0x1c) ends the emitter over that time; with `Instance` 0x272204 releases a shared emitter; the callback is cleared and +0x20 = 0; with a sound record 0x22c58c(+0x1c); then 0x2428c0 (disable).
- 0xfb with a value: 0x242cf0; without: the emitter ends over 0.1 s (literal 0x3dcccccd), +0x20 = 0, +0x30 = 0.125, the sound stops unless `AlwaysEmitSound`, then 0x2428c0.

**Update 0x1a8394** (the entity pass runs it whatever bit 0 of +0x10 says; it skips only bits 0x24). When the node's room has flag bits 0x2001 (>> 5) and an endless emitter runs, the emitter ends over 0.1 s and the update returns. With `Damage` and an emitter, after +0x18 passed 0.1 s and is below the duration - 0.1: the player (or with `DamageAllObjects` every entity of the query 0x237f30 near the emitter's box) whose box touches the emitter's box gets message 0 (damage record) or 0x1d0fcc for damage type 2. Then:
- One-shot (flag 4 clear): when the timer is below 0 (or `ReTriggerTime` is -5 and no emitter runs): `ReTriggerTime` 0 or above restarts the emitter when `Instance` is 0 and `ReTriggerTime` is not 0, and then `ReTriggerTime` 0 disables the object (0x2428c0) while any other value sets the timer to `ReTriggerTime` + `TimeRandomiser` x random; a negative value other than -5 sets the timer to 1000. +0x18 = 0. Then timer -= dt (0x23602c) and +0x18 += dt; for a negative `ReTriggerTime` a sound countdown +0x1c ends the emitter when it reaches 0.
- Endless (flag 4): without an emitter and outside rooms with the flags above, after the delay +0x30 the emitter starts by itself (with `Instance` it shares the emitter of another kind 1 object with the same definition, 0x272148); a running emitter with `JustMoveSpawnPoint` follows the node (0x22f0b4).
- A running emitter follows `SpawnPointAttachedTo` (+0x3c), and the sound record keeps playing (0x232f18).
- 0x1a82b8 (+0x10) clears flag 0x10 and sets the delay +0x30 to 0 or 0.125 from a visibility test 0x24f05c of the node's bounds.

**In the port.** `ParticleObjects` loads every level object of kind 1 and runs the message handler's 0xff and 0xfe for `ReTriggerTime` 0 or below and the one-shot timer of `ReTriggerTime` 0, which disables the object again after the duration; the emitter is started at the object's `initialposition` with the particle system of the level. `TriggerObject LadderKick 1` of `1-4_SO_Phase2` starts effect 148 and `TriggerObject LadderLand 1` of `1-4_AI_Goon_10_Run_Off_Script` effect 11 (log lines `particle object NAME: effect N started`, `disabled`).

**Stand-ins (SCRIPT-S325).** Not ported: the endless self-start, `ReTriggerTime` above 0 and -5, message 0xfb (EnableObject sends no message in the port), `Instance` sharing, the parent node (the emitter does not follow a moving or attached node), the path, the damage, the sound record, the screen shake, the room test, the visibility delay and the kind 1 objects nested in class files (182 in the eight levels). The callback 0x2c7984 is not read: the port takes an emitter that has ended as gone. The update runs after the script runner with the other level updates, an order the port chose.
