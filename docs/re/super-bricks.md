# Super bricks (placed pickups and the counter)

The super build bricks that lie in a level (the pickup classes `pickups/pickup_sbbrick2x2` and `pickups/pickup_sbbrick2x4`, the rainbow bricks), how one is picked up and the counter it feeds. The bricks that fly out of destroyed objects are [debris.md](debris.md) (VEH-123). Replica: `SuperBrickField` (src/runtime/super_brick.*), `SuperBrickObject` / `drawableObjects` (src/assets/level.cpp), glue src/game_super_bricks.*. Studs: [studs.md](studs.md).

## Current state

- A placed super brick is a pickup of object type 0x84 with `pickuptype` 103 (0x67); the other pickup types of that object type are 101 (red brick, also `pickup_goldbrick`), 102 (character token) and 104 (vehicle token). - The pickup test (0x1acdd0): while the brick is idle and its timer is 0 and bit 4 of the player's entity word +0xc is clear, the distance between the brick node and the player node below 1.5 starts the pickup; the timer becomes 1.0, the state 3. 31 updates later (the timer counts down by the frame time) the destroy 0x1d737c adds the amount to the u32 at 0x593430, plays UI sound 14 (amount 10 or more) or 2, and makes the save request 0x21cf38(0). - The super brick count is the u32 at 0x593418 + 0x18 = 0x593430, copied by the save summary 0x17caf8 into slot +0x5190 (earlier docs call it the stud total). The helipad build spends it (0x26d760, count -= cost, then a save request); a second adder in the HUD update 0x2a5f80 applies a pending amount at HUD +0x2ac. - Idle bricks spin about +y by -pi per clock second (the clock of 3000 ticks per second) and take the tint `*0x3743f8` (a cycling rainbow colour); a collected brick flies to the HUD while it fades by int(timer x 255). [§2026-10-19T19:20:44](#ts-20261019-192044)
- `EnableSuperBricks` (byte 0x3743f2) is not read by the pickup; it gates the debris super bricks only. [§2026-10-19T19:20:44](#ts-20261019-192044)
