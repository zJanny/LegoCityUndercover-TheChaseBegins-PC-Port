### Data format (the "unrecovered model+0x1c section" of models.md 2026-10-12T16:10)

- The loader 0x114640 (ev_080a4fc6…8d97) reads the section in pool −14. It is collision geometry. It is present in 776 of the 3113 models, 1725 items in all (312483 triangles, 262633 tree nodes). Level master models (`models/<level>/<level>.bfnmdl`, a model with no meshes) hold the world's static collision, in world coordinates; props and other models hold their own.
- Item (0x2c bytes, one per section entry): +0x10 node count, +0x14 triangle count, +0x28 flag for an optional block set (0x11fd20, 8 items, not read). The vertex count is the vertex block size / 12.
- Blocks per item, in loader order: name (C string, e.g. "Collision_Floor", "Collision1", "Collision_Player_44", "Collision_Vehicle"), a NULL, 4 bytes, the node chunk table, the triangle chunk table (4 bytes per 1024 records). Then for each item: node chunks, triangle chunks (1024 records per chunk, the last one short), the vertex block.
- Node (0x1c bytes): box centre f32×3, box half extents f32×3, u32 info. Bit 0 of info marks a leaf, (info & 0x1f) >> 1 is the child or triangle count (up to 15), info >> 5 the index of the first child node or triangle. Node 0 is the root. Checked on all 1725 items: walking the tree from the root reaches every triangle exactly once (the box is centre plus half extents: a first reading as min and max was wrong, found because a box query returned nothing).
- Triangle (0x20 bytes): normal f32×3, plane offset f32 (normal · p = d, checked against a triangle read from the running game), three u32 vertex indices (the loader turns them into pointers `vertices + index * 12`), a surface byte at +0x1c, three bytes that are mostly 0xff and not understood. Surface byte values seen: 0, 2, 4, 6, 12, 24, 26..31. The queries test `1 << surface` against exclusion masks (0x2467c0 is a 64-bit shift); the player's wall query excludes bit 19 (0x80000), which does not occur in the data read.
- lvl_00_policestation master model: Collision2 (1616 triangles, x −301..−251, room 3), Collision1 (1201, x −27..21, the lobby), Collision3 (130, x 217..245). Player1Start y 1.4203 is on the Collision1 floor. lvl_01_cherrytreehills master model: 153 items, 41853 triangles (Collision_Floor, Collision_Player_NN, Collision_Vehicle, ...).
- Which items count for the player is not known (see unknowns). The replica uses every item of the master model; the differential test passed with all of them.

### Code

- Mover 0x20cd30 (ev_08be8f79…099a in player.md), order of calls for the player in one update (execution traps, `tools/oracle/coll-*.txt`): 0x2b01e4, then 0x21a73c from 0x20d154 (wall slide, then node x and z += result), then 0x20b48c from 0x20d59c (ground). The ground probe is skipped while the character stands still on the ground (0x20d500 area: ctrl+0x314 bit 6 set and delta zero).
- Ground, 0x20b48c (ev_7846beae…3319) → 0x22f134 (ev_6710722a…1621) → 0x1f9884 (ev_6e08accc…e501) → bisection 0x2023e4 (ev_aa15df80…7c68). Candidate triangles come from 0x208d84 (ev_9cc7be90…811d) → 0x20c850 (ev_7608f1e7…c007: spatial grid DAT_00578dfc, then tree query 0x21ba0c / 0x196990 ev_32fb8a66…1907), filtered by 0x2ce21c (ev_20d9cf2b…2651) and 0x209a98 (ev_61413173…00bc). Box/triangle test 0x20c2b0 (ev_1d911920…baaf) is the standard separating-axis test (plane, 3 box axes, 9 edge axes with normalised edges).
  - Probe start P = node · (entity+0x60 with y = entity+0x64 − entity+0x70) = node position + forward · 0.08 + 0.30 up. For a character with 0x245b00 ≠ 0 (the player has type byte 27 at entity+0x12) 0.30 grows by |movement| · sqrt(1 − 0.6088²) · max(dt · 30 − 1, 0). End Q.y = node y − 0.1 − distance, distance = max(|root delta| · sqrt(1 − 0.6088²) − 0.1, 0.05) (0x20cd30 at 0x20d540..0x20d598: 0x20e968 is a vector length; 0.05 is *0x3771ac through 0x21df6c).
  - Box: centre (P.x, (P.y + Q.y) / 2, P.z), half extents (ex, (P.y − Q.y) / 2, ez). ex and ez come from the player box half extents (entity+0x6c: 0.6, 0.85, 0.52) reduced by the margins at 0x37713c/0x377140 (0.24 each): (0.36, 0.28), rotated by the facing to a world box and clamped to 0.36 (the longer side). Confirmed by a trap on 0x2023e4: centre y 16.6487, half extents (0.36, 0.2403, 0.36) for node y 16.589, root delta 0.2277.
  - Candidates: triangles overlapping that box. Only floor-like ones count: normal y above *0x376910 (0.6087610, 0x3f1bd7c3), else above *0x376914 (0.087155, 0x3db27e52); none means no ground.
  - 0x2023e4 bisects the box height: half = half height / 2 + 1.19e-7; below 0.005 it returns the box centre y; if the upper half box overlaps a candidate it recurses into it, else if the lower half overlaps it recurses into that, else it returns the box top (centre y + half height). The result is the height of the highest floor under the footprint, to about 0.005.
  - 0x1f9884 then keeps the node height when |node y − result| < 0.01 (0x3c23d70b), otherwise takes the result. This is why the recorded height stays constant over long stretches and changes in steps of about 0.0047.
  - 0x20b48c sets the node y to that height and clears the vertical speed. With nothing found it takes the falling path (0x203b34, ctrl+0x2b8), not replicated.
- Wall, 0x21a73c (ev_0a4b5935…7e91) → 0x208d84 with box = entity+0x60/+0x6c, matrix = node matrix translated by the movement → candidate filter 0x209a98 with flags 0x6c (keep triangles with normal y ≤ 0.6088 and normal · movement < 0) → 0x2092d8 (ev_e6391a54…55af) with flags 3: each candidate that overlaps the oriented box at the destination (triangle moved into the box frame, `0x20c2b0`) is applied in list order: flatten the normal to the ground plane and normalise it, then `0x22f928` (ev_a09971d5…3533): if movement · normal < 0, movement −= normal · (movement · normal). The adjusted movement is applied to the node; ctrl+0x21c/+0x220 get the x and z the slide changed (out − in) and ctrl+0x224 holds the movement before the slide.
- Second pass (flag 0x10 of 0x208d84, set for the player because 0x245b00 is non-zero: `r4 = 0x13` at 0x21a810..0x21a834): when the first pass overlapped a wall, 0x208d84 runs again at the slid destination with the slid movement (candidate filter and slides as before). If that pass overlaps a wall again and any wall of its candidate list meets any wall of the first pass's candidate list at a normal dot product in (−1, 0) (`0x257e78`, bits below 0xbf800000), x and z of the movement are set to zero: the character stops in a corner. Found because in a two-wall contact the recorded movement was zero while the single-pass slide kept moving (67 updates of wall3_2).
- The candidates are the triangles of the tree leaves that touch the world box of the oriented box (a superset of the exactly overlapping ones; the exact overlap decides only the slide). This matters for the corner test: a wall that is not overlapped still counts as a candidate.
- Arithmetic that decides ties: dot products are `vmul` then two `vmla` (unfused, x, y, z); 0x257ea0 normalises as length = sqrt(x² + y² + z²), length bits ≤ 0x34000000 gives (0, 0, 1), else the vector is multiplied by 1/length (not divided). Replicating this changed one corner update (the slid movement lies within 1e-8 of parallel to the wall, and the sign of that dot decides whether the wall is a candidate in the second pass).
- The level queries use masks passed down from 0x20cd30: low mask 0x80000 (surface 19 excluded), high mask 0. The ground query's masks were not traced.

### The world grid and its entries

- `DAT_00578dfc` is the world grid. At +0 a table of up to 2048 entry pointers; at +0x6000 the control block: u16 count at +0x6002 (1593 at gameplay-start), u16 +0x6004 free index, grid size in bytes +0x2c / +0x2d / +0x2e = 32 x 4 x 16 cells, cell table pointer +0x34, enable word +0x30; the world box (floats) at the start of the control block. Cells list their entries (u16 index lists); `0x237f30` walks the cells the query box touches (z, y, x loops) and tags visited entries with entry flag bit 1.
- Entry = 0x20 bytes, pool at 0x56defc, count at 0x376924 (1216 dynamic ones at gameplay-start): +0 mask word, +4 kind (0 box, 1 mesh), +5 flags (bit 1 visited), +6 table index, +8 / +0xb cell bounds, +0x10 owner entity, +0x14 optional extra matrix (null for entities), +0x18 shape (kind 0: owner+0x60 centre and +0x6c half extents; kind 1: root node of the collision item), +0x1c kind 1: the collision item (the 0x2c-byte record of the model section).
- Entry matrix (0x21bb78): the owner's scene node world matrix (`0x250810` of owner+0x3c), multiplied by +0x14 when that is set. Kind 1 queries run in the item's local space (the query box is moved by the inverse matrix, 0x196990 → 0x21ba0c → 0x1dc528); the triangles they return are local and are moved by this matrix before the overlap tests.
- Kind 0 (box) entries: when the caller passes the flag (the last stack argument of 0x196990, **1 for the player's wall and ground queries**: trap of 0x196990 during the lamp walk, stack words `00080000 00000000 0056d578 0000012c 00000001`), 0x196990 expands the box into 12 triangles with `0x21ba50`: corners centre ± half (bit 0 x, bit 1 y, bit 2 z set = plus), moved by the matrix; vertex indices {0,2,1} {3,1,2} {4,5,6} {7,6,5} {0,4,2} {6,2,4} {1,3,5} {7,5,3} {0,1,4} {5,4,1} {2,6,3} {7,3,6} (DAT_00376930); normals −z −z +z +z −x −x +x +x −y −y +y +y rotated by the matrix (DAT_00376954); plane offset = vertex 0 · normal. The triangle pool is written only by this function, which never sets the surface byte, so it is 0. The camera does not expand boxes: its collider object takes them through the second vtable slot (camera.md).
- Static level collision (the master model's items) is registered as kind 1 entries with mask 1 from tables of the scene (0x30e0d8 reads +0x304 / +0x308: 0x20-byte entries built at load): 147 mesh and 7 box entries with mask 1 at gameplay-start (the master model has 153 items; the difference is not explained). ### Registration of an entity (0x30e0d8 → 0x2ba3f4)

- Every entity of the zone lists (scene +0x58, +0x68, +0x70) whose owner flag u16 at +0x10 has bit 0x200, or whose +0x78 is set, with byte +0x13 equal to 0 or 2 and a scene node, gets one entry.
