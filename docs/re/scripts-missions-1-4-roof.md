**The lists.**
- 0x58deb0 and 0x58dec8 are two arrays of six entity pointers (0x58dec8 = 0x58deb0 + 0x18). The helper 0x2b6b5c of SwapAllegiance toggles bit 2 of the entity word +0xc and moves the entity between them; 0x58deb0 holds the entities with the bit set (AIBadGuy).
- 0x206d18(entity) returns at once when ctrl+0xd8 bit 5 is set. Otherwise it picks the list by the entity word bit 2, looks for the entity in it (and sets bit 5 when found) or takes the first empty slot and sets bit 5. With a slot it points ctrl+0xc8 to the 128-byte record `0x58dfb0 + 128 x slot` (bad guys) or `0x58e2b0 + 128 x slot` (others) and initialises it (0x202054, 0x1976b8: the path record of [ai-navigation.md](ai-navigation.md)). Every call that did not return at the first test ends with ctrl+0x72 = 0. A seventh character of a side gets no slot and no record.
- 0x21decc(entity) returns at once when the entity word bit 14 (Boss_IsBoss) is set and sub +0x15 is not 1, or when bit 5 is clear. Otherwise it empties the slot, sets ctrl+0xc8 = 0 and clears bit 5. Callers: 0x18f684, 0x1de544, 0x1de57c, 0x26a9e0, 0x289670, 0x2a9cb0, 0x2b1150, 0x2bba50. Callers of 0x206d18: 0x1d4734, 0x1f5f38, 0x1fc0f4, 0x200c70, 0x201584, 0x211084 (the aggro 0x21102c), 0x22473c, 0x22d8f8 (the AIMove front end), 0x2895a0, 0x2a1230, 0x2a9c0c, 0x2a9cf0; only the two named were read. 0x2cab6c (tail jump from 0x182e24) and the end of 0x2afdf0 empty both lists and clear bit 5 of every entry (0x2cab6c with the argument 0).
- Readers: 0x1d36ac and 0x1d3718 (the takedown grab of the player), 0x282498 / 0x28265c (the attack target test, PLAYER-S15) and the update 0x307980 of the FallArrestBoundSystem.

**The airborne flag.** ctrl+0x314 bit 6 means the character stands on the ground. The character mover 0x20b498 clears it at its start (0x20b4cc) and sets it at 0x20b6cc when the ground probe found a surface; 0x20d468 and 0x231cdc clear it too. The mover, and so the fall of a thrown goon, is not ported (COMBAT-8, SCRIPT-430).

**In the port.** `EngagedTable` keeps the two lists, the ground flag and the mark (sub +0x131 bits 6..7 = 2) per character. `fallArrestUpdate` runs on the bad guys' list in slot order, and the takedown reads the mark as `autoArrestFlag` (AUTO ARRESTED 0x137 instead of PUTDOWN STUN). A character enters when the aggro asks for the pursuit and at the first update the AI moved it, and leaves when its object is disabled. A hit logs `character NAME: falls into fall arrest bound B, auto arrested at update U` and plays slot 20 of the character's sound row at its position.

**BulletTime's start routine 0x239330(system, owner, flag, scale, duration).**
- The native 0x1a2df0 passes the flag as (third argument > 0.0) (vcmpe at 0x1a2e0c, movgt / movle). A scale below 1.0 stores the owner, scale, duration and the base (C+0x1c) and sets mode +0x68 = 255. With the flag and an owner the mode becomes byte +0x18 of the record 0x20395c returns (0x211df4 of the field +0x14 of the object at 0x376870) and 0x2a36b4(owner) builds a camera shot (the owner's position against the camera through 0x226a30, 0x224168 and 0x22e1f4; not read further). Then 0x1eecec(1), which tail-calls 0x1cef9c(1), and sound 97 follow.
- A scale of 1.0 or more: the mode calls (mode -1: none; 0 or 4: 0x221054; 3: 0x1fc060), stop of 97 and 98, 0x1eecec(0) = 0x1cef9c(0), sound 99. With the flag clear the mode is 255 (-1), so no mode call is made.
- 0x1cef9c(pause) walks the 24 records of the table 0x52a850 (40 bytes: +0 the voice, +4 the DSP channel) and, for a record with both non-null and the voice's channel halfword +0x38 not -1, pauses with 0x25c5d8(channel, 2) and voice state byte +0 = 1, or resumes with 0x25c5d8(channel, 0), state 2 and halfword +0x3c = 2. Every sound that plays when a slow motion starts is held until it ends; 97, 98 (started after the pause) and 99 play. Music streams are not in this table (not verified further).
- Callers of 0x239330 (the system is the object at *0x372d3c; the owner is the player *0x3772b8 in the two read): the native (0x1a2e30: scale, duration and flag from the script); 0x15f670 (scale 0.2, duration 0.5, flag 1, taken when a byte is set in a function that also fills the record at 0x375808); 0x171afc (a scale in s16, duration 0.5, flag 0, when a byte is set); 0x1d6924 (flag 1, scale = float +12 of a record, duration = float +0 of a record divided by the update rate 30) and 0x1d6978 (scale 1.0, duration = float +4 of a record divided by the rate, flag 0) in the strike loop of the character handler; 0x2782f0 and 0x278514 (flag 0, scale from +0xe8 or a local, duration +0xe4 of a state record); 0x2e3f08 (scale 1.0, duration 0.0, flag 0: an immediate reset in a level set-up function); 0x3085a4 (scale 1.0, a local duration, flag 0, when a record byte +0x10 has bit 6). No native named `SlowMotion*` exists; the other callers sit in code of other systems.
- The slowed process: 0x23878c returns [P + 0xc] where P is the running process of 0x25cb20; it falls back to the object at 0x376af8 + 8 or the pointer at 0x58613c when P is the object at 0x376af8 + 0x20 or its +0x10 is null. Which processes use which client is not read.

- **The restore's tail (0x23948c..0x2394cc).** After sound 99 the object `5-11_AI_Boss_Dcam_Running` is looked up (0x23b350 in the object list `**0x376c78 + 0x28`); only when found and bit 0 of its halfword +0x10 is set, 0x271ccc(object) and a tail call to 0x1dd3f8(object) run. - **The writer of the scale.** The update 0x2ec070 and the stop 0x2ec044 store the blended value into `[system + 0x50] + 0x1c` (the client, when the pointer is non-zero) and then call 0x2a0744, which stores the same float at 0x376ce4 + 0x24 (0x376d08).
- **Readers of 0x376d08.** 0x159290 (an initialiser of the effect system at 0x376ce4) registers four callbacks in `0x376ce4 + 0x14 .. + 0x20` (0x2683e0, 0x27ebac, 0x1de234, 0x2b6698, 0x2b6650 are the literals around 0x159390): 0x2b6698 is the only reader of the time scale: with the scale not exactly 1.0 it replaces the integer at +0x18 of its record by `(int)((float)value x scale)` (vcvt.s32.f32, truncating, saturating) and sets bit 2 of the halfword +2; with 1.0 it does nothing; it returns 1. 0x2b6650 is a sibling that reads `0x376ce4 + 0x28` (not the time scale; its writer is not read): when that float is not 1.0 or `[record + 0x1c] + 0x1c` is not 1.0 it stores the float at `[record + 0x1c] + 0x1c`, multiplies the float +0x10 of the record by it and sets bit 0 of the halfword +2. The table is walked by 0x2b66d8 (a list at the literal 0x2b675c, count byte +8, mask word +0xc, 12-byte entries with the function at +4), which 0x202054 calls and ORs with 1. What the record is (an emitter's life, count or speed) is not read.
- **The slowed process.** The scheduler 0x100f44 multiplies the tick count of its client `[P + 0xc]` with C+0x1c; there is one process P per game phase (startup 0x585f18 with C 0x514378, loading 0x585f98, gameplay 0x586018 with C 0x5163e8, vtable 0x362014). The client the system gets is `0x23878c()` at its three set-ups (0x1642dc, 0x175cac, 0x2e63fc), taken while the gameplay process runs, so it is the gameplay client. Its Update (vtable 0x362014 +0x1c = 0x2e5158) is one large function: it calls, among others, the common mode order 0x1f1934 (0x2e5280) and 0x1f177c (0x2e5360) that the pause and menu modes also run, the scene list rebuild 0x1ed57c and 0x1ece78, the clock 0x241098 and the shot record getter 0x20395c. The camera manager update 0x23f174 is reached through 0x18207c -> 0x15bb10, and 0x18207c is called from 0x2e4140, a function in the same class; its caller was not resolved. So no separate process exists for the HUD, the character intro or the camera: what the gameplay client's Update runs is slowed with the single scale; the pieces that keep a clock of their own (the blend's 3000 Hz timer +0x28) are not.
- **The other callers (hosts).** 0x2e3f08 is in 0x2e3e98, the slot +0x20 of the gameplay client's vtable (0x362014): it runs 0x2248b4, frees the pointer +0x234, 0x27cdf8, 0x1ed614, 0x2034f4, then BulletTime(1.0, duration 0.0, flag 0, owner `*0x372d3c`'s player) and 0x198058: the slow motion is reset when the gameplay mode is left. 0x15f670 is the tail of a function that stores `0x375808 + 0x40`, sets the byte at 0x375808 and, if it is set, calls 0x239330(scale 0.2 from the pool, duration 0.5, flag 1); the others (0x171afc, 0x1d6924 / 0x1d6978, 0x2782f0 / 0x278514, 0x3085a4) keep the arguments of [§2026-11-03T08:42:13](#ts-20261103-084213); their classes and the records they read are not resolved.
