**The two state updates.** MELEE PUTDOWN 0x27726c (227..231, 325) and the takedown states' 0x283b10 (0x122..0x12f, 0x133..0x136, 0x139..0x13e) share a head and a tail on sub +0x131 (sub = `*(ctrl + 0xe0)`):
- Head, bit 5 set (a flight): on the ground (ctrl+0x314 bit 6) 0x1fdad0(entity, ctrl+0x2bc, 0) and bit 5 cleared; in the air ctrl+0x2fc -= 0.05 (literal 0x3d4ccccd, per update, not scaled by dt) and 0x215804(entity, ctrl, 1, ctrl+0x2f8). 0x27726c then skips its clip-end test and its pair motion.
- Otherwise 0x283b10 calls 0x215804(entity, ctrl, 64, 0) (65 in state 300). 0x27726c tests the clip end (slot kind 6: the end requests of [combat-characters.md §2026-11-02T15:37:50](combat-characters.md#ts-20261102-153750), then it returns) and else runs the pair motion of the state +0x6e: 0x1fda20 for 227, 229 and 325, 0x1fd9cc for 228 and 231, 0x26e284 for 230.
- Tail: with bit 4 set, bit 5 clear, ctrl+0x314 bit 6 clear and ctrl+0x244 equal to -FLT_MAX or |node y - ctrl+0x244| above `*0x3771ac` (0.05): ctrl+0x2f8 = ctrl+0x204 (0x2554c0), 0x1fdad0(entity, ctrl+0x2bc, 1) and bit 5 set.
- 0x1fdad0(entity, id, flag) finds the record of the clip id in the list ctrl+0xe4 (0x2288c0) and calls 0x233948 -> 0x24f8fc(slot, flag) for each of its clips: flag 1 stores the clock in slot +0x38 when it holds -1, flag 0 adds the paused time to the start clock +0x34 and sets +0x38 = -1; a slot in mode 6 is left. It pauses and resumes the clip.
- The takedown enter 0x28cbf8 ends with bit 5 cleared, the same fall start for a gun HIT state in the air (r7), then bit 4 cleared (0x28d3a8..0x28d404).

**The mover 0x215804(entity, ctrl, flags, vector) -> 0x20cd30.** 0x215804 turns ctrl+8 toward ctrl+10 for the kind ctrl+0x14 = 10, clears ctrl+0xc bit 0 (no stick) and sets ctrl+10 = ctrl+8 around the call. In 0x20cd30:
- Flags bit 0 clears entity +0xc bit 5, else sets it. The movement starts as the vector (zero without one); with entity +0xc bit 5 its y loses ctrl+0x2b8; 0x2c9770 adds the clip's root displacement; the stick step 0x203d18 is not taken (ctrl+0xc bit 0 is clear).
- The horizontal part slides along the walls (0x21a73c) and is added to the node; ctrl+0x21c / +0x220 keep the slide's correction (slid minus requested x and z). ctrl+0x2b8 = -movement y.
- Movement y above 0: the node rises by it (0x23d39c) after the ceiling test 0x203c10; without a ground entity and with ctrl+0x315 bit 4 set, flags bit 6 runs 0x289b80, else 0x203b34 (the ground query below); then ctrl+0x314 bit 6 is cleared and, with entity +0xc bit 5, ctrl+0x2b8 += 0x21df6c.
- Movement y 0 on the ground with no x and z (the slid x, the requested z): no probe, the contact 0x23d218 only. Otherwise, unless flags bit 1, the probe 0x20b48c (distance |movement| x sqrt(1 - 0.6088²) - 0.1) runs: ground sets the node on it and sends event 0x24 (0x2b24bc); no ground sends event 0x26 and, when the character accepts it, moves the node down by ctrl+0x2b8 and adds it to ctrl+0x2b4 ([player-falling-jumping.md](player-falling-jumping.md)).
- Last, ctrl+0x204 = node position - position at the start (0x20d72c), and ctrl+0x315 |= 0x14.

**The character's event 0x26 (0x18f0b0..0x18f274).** With entity +0xc bit 5 (flags bit 0 clear): when the current clip's record word +8 has bit 1 clear, the state equals +0x6e, the state is none of 67, 70, 128..135, 167, 176, 216..218, 222, 251, 252, 277, 371, 373 and 401..403, and 0x21e004, 0x21dfd8 and 0x2b8e18 allow it, FALL (5) is requested; then the gravity step (ctrl+0x2b8 += 0x21df6c x 30 x dt, at most 0x2b75d0). Without bit 5 (state 70 aside) nothing is done. Both return 1: the fall of the node is accepted, so a flight moves the node down by minus the vector's y.

**The animation event tracks.** The handler's branch 0x1d6a64 (event kind 0x0c39ee40) sets sub +0x131 bit 4 when a track of hash 0xc87674da (the negated literal 0x37898b26) has the value 1.0 and clears it otherwise; 0x1d69a4 (kind 0x607ed1b7) sets the byte +0x468 of the pair record (sub +0x14) from the track 0x162bb5d1 when 0x21e0d4(entity) is non-zero. Both take only entries whose weight passes a test against the slot (+0xcc equal to 1.0 or above the entry's +208). In the shipped clips the fall track is in the goon's grabbed clips (`grabbed_putdown_07`: 0 until 0.282526, 1 to the end, 0 at 1.0; also the heavy putdowns, parries, breakouts, `leap_kick`, `leap_punch`, `react_knockd_rollover`, `ride_pig_buck`), the link track in the player's grab clips (`grab_putdown_07`: 1 from 0.333488 to 0.523904).

**The throw is root motion.** `grabbed_putdown_07` (47 frames at 15 fps, the clip of fight move 3 in the oracle) has the extra curve: z 0 to frame 4, 2.297 at frame 10, 6.188 at 16, 7.257 at 28, 6.646 from 34; x about -1; y 0, yaw 0. So 0x2c9770 throws the goon about 7 forward along its own facing while the track allows the fall, and a goon that leaves the roof edge flies on with its last move.

**The pair motion.** 0x1fda20 uses the pair record R = sub +0x14 with the partner slot R+0x46c (alignment block R+0x3d0) or R+0x470 (R+0x41c): the vector is 0x285850 (the alignment: a fraction 0x2035bc(slot, 0) / 4, at most 1.0, of the way to the block's position +12 and a slerp of its rotation +24 / +40 into ctrl+8 and ctrl+10, block +0x48 = 1 when complete) plus 0x2057e4 (with R+0x468 bit 0: the partner's ctrl+0x21c / +0x220, unless the partner's +0x6e is 153, 307 or 409), then 0x215804(entity, ctrl, 65, vector) and R+0x474 = the clock. 0x1fd9cc takes 0x2057e4 alone.

**Landing with the mark.** 0x2b24bc first runs the state hook with event 15 (0x21e1d4), then when 0x21de38 holds or sub +0x131 bits 6..7 are 2: the bits become 2 and, unless 0x28b46c(+0x6e) holds (227..231, 307, 325, 409), the combat record byte +0xe = 55 and FALL ARREST HIT (310) is requested. A goon marked by a FallArrest bound in its MELEE PUTDOWN flight lands without 310 and becomes AUTO ARRESTED at the clip end (0x22e884 kind 16).

**The camera manager's mode slots.** 0x226a30 stores r0 at 0x376870 + 0x28; 0x221054 passes `*(0x3770c8 + 0x10)`, 0x1fc060 `*0x372d74`. 0x20395c = 0x211df4(`*(0x376870 + 0x14)`): the first word of the camera object C plus 120 when it is non-zero, so the shot record's mode byte is byte +0x90 of the object that word points at; what that object is was not read.

**In the port.** `moveCharacter` is 0x20cd30 for a level character (slide, rise, standing, probe, fall, ctrl+0x204), `thrownFlight` / `startThrownFall` the head and tail, `takedownEnterAir` the enter's end, `sampleFallAllowed` the branch 0x1d6a64, `fallArrestHitOnLanding` 0x2b24bc's head with 0x28b46c. The glue runs before the takedown machine for MELEE PUTDOWN and the 0x283b10 states with no movement (neither the root displacement 0x2c9770 nor the pair motion is passed), pauses and resumes the clip (`AnimationSlots::pause`), feeds the ground flag to the FallArrest update and logs `character NAME: thrown fall started at update U`, `... thrown fall ended ...` and `... lands auto arrested, state 310 requested ...`. `CameraManagerModes` keeps the requested, current and previous mode and switches once per camera update; BulletTime's restore requests the gameplay camera (0x221054) or the CameraRotFixedSet preset (0x1fc060), and a switch is logged (`camera mode A -> B at update U`). Stand-ins: SCRIPT-S346 (the mover), SCRIPT-S347 (the root and pair motion), SCRIPT-S332 (the preset camera and the shot record) in [script-system-missions-1-4-roof.md](../plans/features/script-system-missions-1-4-roof.md).
