# Vehicles: contact damage

**Where the contact message comes from.** (1) 0x271764 is Bullet's `gContactProcessedCallback`: 0x2e3bec stores it into 0x379d54, and `btPersistentManifold::refreshContactPoints` 0x1e518c calls it (0x1e5468..0x1e5484: `blx [0x379d54]` with the point and both bodies) for every point that survives the distance and drift checks, at every refresh; a reply of 2000 (callback result 1) removes the point (0x1e548c..). 0x271764 sends the entity of body A (side byte 0, data {entity of B, point, 0, 0}) and then the entity of B (side byte 1, other = entity of A) the message 0x80000002 through 0x244fc8 unless the rigid body's flag word +0xcc has bit 4; a static box has no entity. It returns 1 (drop the point) when the global byte 0x376c34 is not 0, body A has flag +0xc4 bit 0 and the normal's y is at most -0.2 (float bits at least 0xbe4cccce); the byte's value at run time is not read. 0x271764 is also called directly by the bump pass 0x2d4af0 and at 0x156e74. (2) 0x181e68 sends it from the floor pass 0x1c54f8 (the only call, 0x1c5cec) for every contact of the list just before the impulse 0x19c0a8, with data {0, ?, contact record, 0}; the record is 13 floats (time, point at +4, normal at +0x14).

**Closing speed 0x19b5c4 (with 0x19b648).** The speed is the dot product of the contact normal with the relative velocity of the contact point. For a manifold point (the message's +8 is 0): v + w x arm of the vehicle's rigid body with the arm the point's local coordinates as stored (+0x00 for body A, +0x10 for B; not turned into world axes), minus the other body's velocity at its arm (the other point when the other entity has a body); the normal is the point's normal on B (+0x40), negated for side 0. For a floor contact (+8 is the record): the arm is the contact point minus the body position, the normal is the record's (+0x14), negated for side 0, no other body. A negative result is a speed away from the contact; the thresholds below compare the float bits as signed integers.

**Contact message tail (0x179ca4, 0x179dc4..0x17a10c).** For a vehicle that is not the player's the handler returns after the target logic (a vehicle with target +0x2a4 in state 2 or 3, which is not ported). For the player's vehicle (0x24255c of the player is the entity):
- Above 10 m/s with the cool-down +0x308 equal to 0: a brick burst: the speed clamped to 10..40 is mapped by 0x22a048 to 1..3 and floored (the count byte of a particle descriptor 0x67), the burst 0x229fb8 at the contact point with the colours of the class values `DebrisColour` (default 0xffffffff) and `DebrisColour2` (default 0xffff00ff), last argument 6; +0x308 = 1.0.
- If the other entity is absent or lacks entity word +0xc bit 0x10, the speed is above 20 and the other has no body or a body without flag +0xc4 bit 0x40000: a damage message to the vehicle itself with x = (min(speed, 60) - 20) x 0.025 x 5 (that is 0.125 per m/s above 20): word +0xc = floor(x), float +0x10 = x - floor(x), byte +0x14 = 11.
- Above 3 m/s: the sound id at record +0x28 when it is not playing (0x229ef0, 0x229e80).
- Before all that: if record +0x311 bit 3 is set it is cleared, sound 95 and message 190 are sent (not ported).

**Damage message 0 (0x1799b4..0x179c88).** A hit is allowed unless the type byte (+0x17) is not 6 and one of these holds: byte +0x15 is not 0, the cool-down +0x304 is above 0, +0x311 bit 2 (`Invulnerable`), or 0x25207c (a game state timer, not read) is true. A destroyed vehicle (entity word +0xc bit 0x10) with +0x311 bit 7 and +0x304 equal to 0 is revived first (the bit is cleared). For the player's vehicle and byte +0x14 = 11: d = floor(float +0x10 x 100); with d below +0x30c the points drop by d, else the heart count (word +0xc) grows by 1. With a count above 0: a type other than 6 sets it to 1 (so a contact message costs at most one heart); +0x304 = 0.5; with the count below +0x30d the hearts drop by it, +0x30c = 100 and the smoke effect 0x22a124 (id 0x11f when one heart is left, else 0x11e) is attached; otherwise +0x311 bit 7 is set for type 6 and cleared else, +0x30d = 0 (unless the target logic keeps it), the destroy call 0x23cd80 runs, 0x29cf70 fades out the handle at +0x10 of each wheel entity's record over 5.0 (record +0x318, body +0x2b4 wheels) and the body's flag word +0xc4 loses bit 15 and gains bit 19. In both cases the model flash 0x230ae8 runs, +0x30f = 0 and, for the player's vehicle, SetHearts(+0x30d). Vehicle "7-9_RexCar" also sets +0x311 bit 2 on the player's vehicle (and 0x22b224 for a vehicle in state 6 or 7).

**Cool-down tick.** At the end of the vehicle update 0x1571dc (0x157430..0x15746c): +0x304 = max(+0x304 - dt, 0); when +0x308 is above 0 it counts down and stops at 0 the same way.

The handler returns 0, so the entity word +0xc gets bit 0x10 and 0x2320f8 drops the model node (0x24ce78, +0x58 = 0). The jump-out check 0x322aa4 refuses to leave a vehicle with that bit. **The vehicle bump pass 0x2d4af0 (adds to [vehicles-physics-props.md §2026-10-16T08:59:49](vehicles-physics-props.md#ts-20261016-085949)).** It sets the body's flag +0xc4 bit 17 while it sends its messages (0x179ca4 reads that bit of the other body in the target logic). The cool-down body +0x194 is only counted down here; its writer was not found. The neighbour must have a rigid body with broadphase handle +0xbc and pass the group test 0x2d4224 (the handle's masks +4 and +6 against the pair's). The contact point handed to 0x271764 is built on the stack: local A = -1.5 x normal, local B = hit point minus the other's position, normal from 0x1bfd24. 0x1bfff8 then applies, when the relative velocity along the normal is negative, an impulse of -0.9 x (relative speed) / (inverse mass sum) along the normal's x and z (y 0) to both bodies through 0x21981c at the arms (centre minus position, y 0).

**The pair rule of 0x271764 (the writer of the pair flag word).** After both messages the callback writes the manifold point (the fields are Bullet's: +0x54 combined friction, +0x58 combined restitution, the halfword at +0xb4 the original's flag word read by the solver at 0x331ac0): friction = table(surface A) x table(surface B) (the table pointer 0x376c48, the surfaces from body +0x9c or the point's +0x64 high half for bodies without entity), and, when neither body has flag +0xc4 bit 7, both have bit 0 and each has more than one wheel on the ground (body +0xda0, which 0x33b66c resets and 0x339078 counts per wheel with a hit) or flag bit 2, the flag word gets bit 0 when body A has flag +0xc4 bit 3 (driven) and bit 1 when body B has it; a driven body against a body with flag bit 0x10000 (class value `BumpCollision`, set by 0x159bd0 after message 0x80000000) makes friction 0.2 and restitution 1.1. Otherwise, a point whose normal y has a magnitude below 0.2 gets the surface 0xf. A point with a vehicle against a surface 0x28 or 0x25 caps the friction by the relative speed (min(|dv|, 20) x 0.3 / 20).
