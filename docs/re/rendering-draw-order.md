### The lists 0x530634

- 16 lists of 32 bytes: +0 base, +4 capacity (items of 16 bytes), +8 halfword kind mask, +0xa halfword index into the draw function table the drawer passes, +0xc float minimum node radius, +0x10 front pointer (grows up from the base), +0x14 back pointer (starts at the last item and moves down), +0x18 / +0x1c the frustum. Set-up 0x105bc4: list 0 gets kind mask 15 and table index 0; the list count is byte 0x3767f0. 0x25add8 resets both pointers each frame.
- Item: +0 low word and +4 high word of a 64-bit key, +8 data (the draw record), +0xc the draw function. 0x256734(radius, key low, key high, data, table, back, list mask) adds the item to every list of the mask whose table entry is set and whose minimum radius is not above the node radius, at the front (back = 0) or the back; mode byte 0x3767e9 (front) / 0x3767ea (back): 1 queues, 4 draws at once, 0 and 2 drop.
- 0x24f2a4 (frustum test) returns the lists whose kind mask meets the kind of the draw and whose frustum holds the box; 0x256838(kind) the lists of a kind without the test.
- 0x21d360(list) sorts and draws the front half [base, front), 0x228d20(list) the back half (back + 16, base + capacity x 16). Both go through 0x2128c8: `0x259ebc(items, count, 16, 0x2d0f84)`, then each run of items with the same draw function is handed to that function with the count. Draw functions: table 0x3767c4 = {0x188778 (mesh part), 0x1dc084, 0x1dc290}, table 0x3767d0 = {0x265828}, particles 0x376be0 = {0x2722cc}.
- 0x2e4858 (the frame passes of the normal view): pass 1 fills the lists (0x25add8 reset, 0x228d40 scene walk, 0x18a0c8(0) particles, 0x2983a0, 0x1d9634); pass 3 draws the front half of list 0 (0x21d360(0)), then 0x17fc38 and the sky 0x180fac(1); pass 4 the back half of list 0 (0x228d20(0)); pass 5 the glow.

### The library sort 0x259ebc

- 0x2d0f84(a, b): d = key(a) - key(b) as 64 bits; returns `high(d) | ((low(d) | low(d) >> 16 | high(d) << 16) & 0xffff)`, so the sign of the 64-bit difference and 0 only for equal keys.
- 0x259ebc(base, n, size, compare): for n above 10 first 0x259b94, then an insertion sort over the whole array (an element moves down past every element that compares greater; equal keys keep their order).
- 0x259b94: an explicit stack of (start, count). Per range: mid = start + count / 2, last = start + count - 1; order start, mid and last as a median of three (swap start and mid when start > mid; when mid > last, swap start and last if start > last, then mid and last); the pivot goes to last - 1. i runs up from start while item < pivot, j down from the pivot while item > pivot, swap while j > i; then swap i with the pivot. With k = i - start: left = k - 1 items from start, right = count - left - 1 items from i (the routine leaves item k - 1 out of both ranges; the final insertion sort orders it). The larger side above 10 items is pushed, the smaller side above 10 is continued; sides of 10 or fewer are left to the insertion sort.

### The keys

- Material key 0x115128 at material load 0x114860, stored at material +0x20 (low) / +0x24 (high). crc = 0xffff stepped by 0x24d20c over the signed bytes 1, 2 and 3 (`table[(crc ^ byte) & 0xff] ^ (crc >> 8)`, table of 0x25a248 for the reflected polynomial 0xa001), m = ~crc & 0xffff (CRC-16/USB). h = 0 and for every texture slot (count = (byte 10 & 0x3f) >> 3) h = 0x115648(h, slot + 0, 4) where slot +0 is the texture resource pointer that 0x250244 returned. 0x115648: crc = ~state & 0xfff; per byte the byte is added to a bit buffer at the current bit count, one round `crc = table12[(crc ^ buffer) & 63] ^ ((crc << 20) >> 26)` takes six bits, the bit count grows by 2, and when it reaches 6 a second round runs and the count drops by 2; a non-zero count at the end gives one more round; result ~crc & 0xfff (table12: 64 entries, reflected polynomial 0xf01, masked to 12 bits). Key high = ((h >> 1) & 0x7ff) | (byte 5 & 0xf) << 11 | m << 15, low = h << 31.
- Depth key 0x25688c(z): near = camera +0xc4, far = +0xc8 (1.0 and 500.0 without a camera at [0x529e30 + 0x2c]); d = z - near, d set to (far - near) x 0.99999988 when not below that, to 0 when not above 0; q = int(d x 2^31 / (far - near) + 0.5); key = q ^ 0x7fffffff (larger when nearer).
- 0x10bbe8 (one mesh of a node, per part): z is the third coordinate of the part box centre (part record +0, half extents +0xc) through the node's model matrix 0x52a090 and the view matrix 0x52a00c. Opaque parts: front, key low = (material low & 0x80000000) | (~depth & 0x7fffffff), high = material high, draw table 0x3767c4. Blended parts: back, key high = (material high & 0x80000000) | depth, low = material key >> 31; mesh flag bit 8 (mesh +0 halfword, 38 shipped meshes) sets depth to 0 for them. When node byte +0xde has bit 2 and the part is opaque in list 0, a second item goes to the back with the blended key layout and table 0x3767d0 (record flag 8).
- The part box +0 / +0xc equals the box of the part's vertices (relative meshes: in the stored space, the mesh centre is added by the matrix 0x253a00 sets for mesh flag bit 0) on all 16122 shipped parts (CTest `draw-order-real-data`).

### The pass of a part (0x10bbe8, 0x188778)

- Kind 1 when node alpha +0xdd is 255, node colour alpha +0x11b is 255, material colour alpha (byte 0x13) is 255 and material byte 9 is 0; otherwise kind 2. Mesh flag 0x40 with node +0xde bit 0 adds kind 0x10.
- The draw record (0x60 bytes from 0x52ff80) colour = material colour x node colour +0x118..0x11b / 255, its alpha also x node +0xdd / 255. Record alpha below 255, or material alpha below 255, or byte 9 not 0: back half; else front half.
- 0x188778: when the record colour is not 0xffffffff, the material is copied with that colour; a record alpha below 255 sets byte 8 (blend source index) to 4 (source alpha), byte 9 to 5 (one minus source alpha) unless it is 1 (one), and byte 6 (alpha test reference) to node +0xdd x byte 6 / 255.
- 0x23f708(node, alpha, 1, sub index, 0) goes through the node type's property handler (table 0x5303d0; mesh node type 0x37674c, record of 0x103290, handler 0x106980); key 0 with sub index -1 stores the clamped alpha in node +0x11b (0x10c6a4).

### Particles

- 0x18a0c8(0) (pass 1) builds one 16-byte item per live emitter (emitter, position) and adds it with 0x256734 to the back of the lists of kind 4: key low 0, high = depth key of the emitter position's view z (of 0 when the emitter definition +0x168 has bit 3), draw table 0x376be0 (0x2722cc).
