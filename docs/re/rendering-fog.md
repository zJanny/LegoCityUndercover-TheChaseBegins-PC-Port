## 2026-10-14T17:35:00+02:00 — The original's fog: level properties, the 128-entry LUT, the per-draw rule (llvm-objdump `--triple=armv6k --mattr=+vfp2` on `artifacts/game/game.arm.elf`, Azahar oracle with GDB traps and RPC reads, state `street-after-1-1`; REA was not used)

**Fog state** (render state block at 0x3760f0, byte and float fields)
- 0x22d808 `setFog(enable r0, colour r1, near s0, far s1)`: stores enable at 0x3760fc, the two floats at 0x376160 / 0x376164 (+0x70, +0x74) and the colour dword at 0x376168 (+0x78; byte 0 red, 1 green, 2 blue, byte 3 not used by the GPU register). Callers: 0x1a2dd8 (level setup, below), 0x172174 (handler 0x1720ac with arguments enable, near, far, red, green, blue as floats), 0x2d55bc, 0x2d59d8, 0x2e1710, 0x2e64b8, 0x3130d8, 0x313214, 0x319b7c (not classified).
- 0x1ee98c stores the byte 0x3760fd (override, returns the old value); callers 0x2d8c10, 0x2e5140, 0x2e5cc4, 0x2ef67c, 0x2ef6b0, 0x2ef828, 0x3042b4 (not classified). 0x1b24f8 (`OverrideFog`, two floats) stores a float pair at 0x51654c through 0x2131a4; the pair was 0 in the oracle and its reader was not found.
- Oracle at `street-after-1-1` (OpenGL, free run): 0x3760fc = 1, 0x3760fd = 0, 0x3760f1 = 0 (z-buffer depth, see below), 0x376160 / 0x376164 = 220.0 / 260.0, 0x376168 = (183, 199, 221). No writes to 0x3760fc, 0x376168 or the float pair during three stepped updates (watchpoints).

**Where the values come from: the level** (0x1a293c, called when a scene's room set changes; it ends in 0x22d808 at 0x1a2dd8)
- Level objects of class `lighting/lightambient` carry the float parameters `FogStart`, `FogEnd` and the vector `FogColour` (red, green, blue as 0..255 floats, converted to bytes by float to int), next to `Colour` (the ambient light colour). Parameter names are the CRC-32 hashes of the strings at 0x358b3c, 0x358b48, 0x358b50. The code also reads `DS_FogStart`, `DS_FogEnd`, `DS_FogColour` (strings 0x358b30, 0x358b24, 0x358b14) first; no level file contains their hashes, so the plain names are the ones in use.
- Rule: start >= 0 and end > start and a colour present give `setFog(1, colour, start, end)`; anything else gives `setFog(0, white, 0, 0)`. An object counts when it is of type 8, its enable byte (`[[obj+0x3c]+0xd8]`) is 0 and it either has no room or its room is the current room (the check loads the object's room from `[[obj+0x3c]+4]`). Later objects replace earlier ones; a second loop over the room list (`[scene+0x40]`, entries of 0x18 bytes, 0x30 entries) applies the same test to the room's own object chain. The exact order of the two loops and the type 8 meaning were not worked through.
- Census (`tools/convert_levels.py --param-names` over the eight `lvl_0*_main.blvl`, objects with `FogColour`): lvl_01, 03, 04, 06 and 07 have one object (`Ambient`, no room) with start 220, end 260, colour (183, 199, 221). lvl_00 has `Ambient_Basement` (room3: 20, 100, (158, 154, 122)), `Ambient_Lineup` (room5: 10, 60, (188, 186, 169)) and `Ambient_Lobby` (no room: 20, 150, (183, 199, 221)). lvl_02 has `Ambient_Island` (no room: 220, 260, (183, 199, 221)), `Ambient_Cells` (room15: 15, 60, (100, 122, 135)), `Ambient_Wardens` (room11: 20, 60, (88, 63, 44)) and `Ambient_Workshop` (room13: 10, 40, (72, 40, 20)). lvl_05 has `Ambient_Woods` (no room: 220, 260, (183, 199, 221)), `Ambient_Scene2` (room48: 30, 80, (45, 65, 100)) and `Ambient_Scene3` (room52: 20, 70, (28, 55, 55)). So there is one global object per level and room-specific ones for interiors and special scenes; interiors use a much shorter fog.

**Per-draw rule** (0x1292fc caller region, 0x129200..0x1292f0; `r4` is the material record, `r9` the draw state with the cached fog switch at +3)
- Fog is on for a draw when `((signed byte 0x3760fc) and not bit6(material byte 0xb)) and not (signed byte 0x3760fd)` is non-zero and material byte 9 (blend destination index) is not 1 (destination factor ONE: additive effects are not fogged). Then GPU register 0xe0 (texture-environment buffer / fog mode, mask 1) gets 5 (fog) and register 0xe1 (fog colour, mask 7) gets the dword at 0x376168; otherwise register 0xe0 gets 0. The switch at `r9+3` skips the writes when the state already matches.
- Material byte 0xb bit 6 is therefore a per-material "no fog" bit.

**Per-frame LUT builder 0x24e9d8** (runs when the camera's dirty word `[0x529e30+0x13c]` has bit 7; writes the command list at `*0x37614c`)
- Depth source: byte 0x3760f1 = 1 selects w-buffering (then depth map scale register 0x4d gets a computed scale); the oracle had 0, so fog uses the z-buffer depth `t` in 0..1. With the projection matrix at 0x529e30+544 (inverse built by 0x247fb0 from 0x529e30+736) the relation is `t = A * (1 - near / d)`, `A = far / (far - near)`, `d` the distance along the view axis. Read in the oracle: the matrix has `A = 1.0038609` (rows `-1.00386, 1` and `1.00386, 0`), so near = 1 and far = 260. The source of near and far was not found (see the unknowns).
- Table: `d_i = near / (1 - ((i + 1) / 128) / A)` for i = 0..127 (read back from the stack: 1.008, 1.016, ..., 85.995 at i = 126, 260.003 at i = 127). `f_i = 1 - clamp((d_i - start) / (end - start), 0, 1)`. Entry i holds `value = clamp(floor(f_(i-1) * 2048), 0, 0x7ff)` (f_(-1) = 1) and `diff = clamp(floor((f_i - f_(i-1)) * 2048), -4096, 4095)` as 13-bit two's complement; the word is `value << 13 | diff`. Registers: 0xe6 (LUT index) = 0, then 128 words to 0xe8 (header 0x07ff00e8, 0x24ee10 / 0x24ee14).
- Cache: the builder compares `(start - n) / (f - n)` and `(end - n) / (f - n)` with the floats at 0x37616c / 0x376180 (n and f are floats of an unrelated-looking object `[0x529e30+0x2c]`, offsets 196 and 200) and skips the rebuild when both are equal.
- Consequence for the picture: with 128 entries over the whole depth range the table is very coarse in distance. For the street (start 220, end 260) every entry up to index 126 is 1.0 (`0xffe000`) and entry 127 is `0xfff800`: the fog fades from 0 at d = 86 to full at 260 along the last depth interval (`fog = 1.494 - 128.494 / d`), not from 220. The start value only matters for indoor levels with a short range.
- Hardware use of the entries (PICA200, Citra/Azahar behaviour, not measured in the console): `i = floor(t * 128)`, `fraction = t * 128 - i`, `f = (value + diff * fraction) / 2048`, output `colour = f * colour + (1 - f) * fogColour`; alpha unchanged.

**Verification of the table formula.** Three LUTs were captured with a breakpoint at 0x24ed98 (`r8` points at the 128 words, `r7` at the 128 distances) after setting the floats at 0x376160 / 0x376164 and clearing the cache: (220, 260), (20, 120) and (60, 200). A transcription of the rule above reproduces all 3 x 128 words exactly, with the distances either read back or from the closed form with near = 1, far = 260 (relative difference of the distances at most 1.2e-5).

Unknowns:
- Source of the projection near (1) and far (260): the camera node's own plane fields were not found ([camera-follow.md](camera-follow.md) lists the same gap); the values come from the matrix read in the oracle.
- Which of several ambient objects wins in a level with room-specific fog (order of the two loops, meaning of type 8, the object's disabled byte); the callers of 0x22d808 and 0x1ee98c other than the level setup; the reader of 0x51654c.
- Whether the real console interpolates the LUT as described (only Azahar was observed).
