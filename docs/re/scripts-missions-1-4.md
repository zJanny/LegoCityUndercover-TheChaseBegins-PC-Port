**The AI spawner class in the executable (kind 14, handler 0x1b4fb0; read in outline).**
- The message handler dispatches 7 (nothing), 8 (reset), 28 (returns a slot's halfword +0x14), 33, 252 (calls a function pointer of the message), 254 and 255. TriggerObject sends 255 for a non-zero flag and 254 for zero, then fires ObjectTriggered / ObjectUntriggered (handler 0x1cddf8).
- Message 8 reads the parameters StartActive (string at 0x1b5234) and StartSpawned (0x1b5240) through 0x2451d0, sets the state halfword +4 from StartActive, and for every slot (record +0x24 is the count, the slot array is at +0x1c in 8-byte entries) either keeps the character (StartSpawned) or holds it: 0x1b5250 sets bit 4 of the character's flags at +0xc, sends it message 53 and calls 0x2428c0. So with StartSpawned 0 the characters are held from level load until the spawner activates them.
- Message 255 with the state at 0 sets it to 1. The update callback 0x288fbc branches on the halfword +2 (1 or 2). Value 1 loops over the held slots, decrements a per-slot byte and, with the other conditions met (a function 0x265190 on a point of the slot and the camera, not read), sets the state +4 to 2 and records the slot index at +0x2b; 0x242cf0, called with the character after its flag bit 4 is cleared, clears bit 0 of the entity's halfword +0x10 when it is set (the counterpart of 0x2428c0, not read). Value 2 waits until the count +0x3e equals +0x3c (every slot done) and then calls 0x23211c on the record at +0xc with 1, the same reference step as [script-triggers.md](script-triggers.md) ("AI spawner, kind 14, +0xc") that fires the `TriggerObject` reference, and sets the state to 0. The port registers that reference but never calls the step for a spawner (SCRIPT-359). Where +2 is set, and the counters +0x3c, +0x3e, +0x40, +0x42, were not traced.

**BulletTime (handler 0x1a2df0).** Reads scale (slot 0), duration (slot 1) and `flag = third argument > 0`, and calls 0x239330(system, owner, flag, scale, duration) with the system `*0x372d3c` and the object `*0x3772b8` (the player), then returns 1. The system is the static object at 0x5140b0 (initialised at 0x34523c with the name string `BulletTimeSystem` at 0x345274 and the vtable at 0x3625d0); its slot at 0x362618 is the update 0x2ec070, 0x362614 the stop 0x2ec044 and 0x3625e0 0x2ec12c (calls 0x25a1a0 on the clock at +0x28 with 3000 and clears the active byte). Fields: +0x28 clock (0x2528b4 returns a tick timer in seconds), +0x50 the scene (0x238784 stores it, called with the result of 0x23878c from 0x1642ec, 0x175cac and 0x2e63fc), +0x54 owner, +0x58 base, +0x5c scale, +0x60 start time, +0x64 duration, +0x68 mode byte, +0x69 active.
- 0x239330 with the flag clear: when active and both the stored scale and the new scale are 1.0, or when not active and the new scale is 1.0, nothing happens. Otherwise +0x54 = owner, +0x58 = the scene's float at +0x1c (1.0 at level load), +0x5c = scale, +0x64 = duration, +0x60 = the clock, +0x69 = 1. For a scale below 1.0: +0x68 = 255, 0x1eecec(1), message 97 (0x61) to the owner without a value (0x23ae84). For a scale of 1.0 or more: messages 97 and 98 with the duration as a value (0x23ae50), 0x1eecec(0), message 99; the mode byte first selects 0x221054 (0 or 4) or 0x1fc060 (3), and a lookup of the object `5-11_AI_Boss_DcamRunning` follows (mission 5-11). With the flag set the branch calls 0x20395c and 0x2a36b4 first (not read).
- Update 0x2ec070 (while active): queries 0x237acc for message 97 and 98 of the owner and may send 98 (not read), reads the clock, progress = (clock - start) / duration; above 1.0 it is clamped to 1.0 and a target scale of 1.0 clears the active byte. The scene's float +0x1c = base + progress x (scale - base), and 0x2a0744 stores the same value into the global 0x376d08 (0x376ce4 + 0x24). The stop 0x2ec044 stores 1.0 the same way and clears the active byte.
