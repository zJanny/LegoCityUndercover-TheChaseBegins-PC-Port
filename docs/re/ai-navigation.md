## 2026-10-14T19:47:10+02:00 — Nav path finder 0x204284, follower 0x27ddb4 and state 11 (0x2c3bd8)

[Corrects ai-natives.md §2026-10-14T18:42](ai-natives.md#ts-20261014-184240): the phase table of `+0x7e` and the avoid bit (see "Front end and flags").

Read with llvm-objdump; no REA session, no emulator trace of the finder. The port tests are hand-evaluated from the code (addresses next to each value in `tests/nav_grid_test.cpp`, `tests/nav_path_test.cpp`); `tests/nav_path_real_test.cpp` checks invariants on the real grids of lvl_01 (no compare with a run of the original).

**Run-time data.**
- Global 0x376bec: byte `+1` diagnostic code (the finder stores 6 first, other values mark the failure site), `+4` the active section record plus 8 (`N`), `+8` a callback pointer (setter 0x2a0538), `+0xc` an optional float table of gate weights (setter 0x102850; null at start).
- `N`: u16 `+0` total grid count, `+2` room count, float `+4` height unit, `+8` cell size, `+0xc..+0x14` origin; `+0x18` the 0x18-byte room descriptors. It is the section record (0x28 bytes, level section +0x30) shifted by 8. Which section record `N` points to is set elsewhere and not found; most levels have several (rooms of one level differ in cell size, height unit or origin, for example lvl_00 from room 1 on), `NavRoom::section` keeps the index.
- Room descriptor (loader 0x1971c4 fills `+8..+0x14`): u16 `+0` grid count, `+2` path-box count, `+4` first global grid number, `+6` end, `+8` grids, `+0xc` boxes, `+0x10` cells, `+0x14` extras. The ranges are consecutive: `end - base` equals the grid count for all 700 nav files (`assets-real-data`).
- Grid record (0x3c): u16 x `+0`, height `+2`, z `+4`, width `+6`, height extent `+8`, depth `+0xa`; `+0xc` cells (one byte each, at most 256 per grid in the data), float `+0x10` stamp, 16 u16 link slots `+0x14` (0xffff none), u16 `+0x34` flags (bits 0..13 extra count, bit 14 restricted, bit 15 closed), u16 `+0x36` link mask, `+0x38` extras.
- Cell byte: bits 0..1 kind (0 free, 1 blocked, 2 temporary mark, 3 restricted), bit 2 link cell, bits 3..7 extra index.
- Extra (4 bytes): b0 low 6 bits link slot, bit 6 temporary off mark; b1 gate number (0 none); b2 / b3 signed cell offset across the link. In the data (census over all 700 files) no slot is above 15, every link cell names an extra, no grid is wider than 127 cells (the neighbour offsets are bytes) and none has more than 256 cells; about one extra in 200 carries bit 6.
- Path record (created by 0x206d18 in one of six static slots, size 0x80): `+4` grid nodes (8 bytes: state, parent u16, cost u16, key u16; 8192 nodes), `+8` cell nodes (10 bytes: state, parent byte, mark byte, cost, key, total; 256 nodes), `+0xc` entry cell per grid (bytes), `+0x38/+0x3a` start / goal room, `+0x3c/+0x3e` start / goal grid, `+0x40/+0x42/+0x44` start / exit / goal cell, `+0x48/+0x4c` grid open list (u16, count), `+0x50/+0x54` cell open list (bytes), `+0x58` next waypoint (x, y, z), `+0x64..+0x6b` the eight neighbour offsets (signed bytes, written from the width by 0x208338), `+0x74` and `+0x78` masks, `+0x7c` flags, `+0x7e` phase, `+0x7f` obstacle callback switch.

**Lookup 0x1c2ccc(position, tolerance, out room / grid / cell, optional near grid).** Per room, the first path box that holds the position in x and z (0x20d99c) is searched. Per listed grid the box centre is origin + (x + width / 2) * cell, y origin + unit * ((height + extent / 2) / 256), z likewise, the half sizes cell * width / 2, unit * extent / 512, cell * depth / 2. Inside the 3D box (0x2397a0) and a free cell (0x20d8a8) ends the search (result grid = list entry + descriptor base). Otherwise a grid below the position within `tolerance` of its top is the best candidate, the cell lookup of the best grid decides, and the optional output takes the last grid whose box scaled by 1.25 holds the position. The cell index is the quotient (position - corner) / cell truncated toward zero, so up to one cell before the grid still maps to cell 0.

**Finder 0x204284(record, start, goal)** returns 0 arrived, 1 failed, 2 blocked path, 3 path. Steps:
1. Both positions are looked up with the tolerance `2 * class[+0x70]`. A missing start with a near grid and a found goal takes the near grid and sets phase 4 (return 3); otherwise 1.
2. A start grid with bit 15 returns 3 without a phase; bit 14 returns 3 unless `+0x74` has bit 0 (it always has, see below).
3. Same grid and same cell: phase 0, return 0.
4. 0x1d05d0 sets every link mask to 0xffff and clears the bit of every slot an extra names (a link without an extra stays closed); when the stamp is more than 2 s old the extras lose bit 6. 0x1d0700 clears all grid node states, seeds the goal grid (parent itself, cost 0) and runs 0x294768 until the start grid node is closed, then 0x208338 builds the leg inside the start grid.
5. If the start cell node is closed afterwards: phase 2, return 3. Otherwise the start grid node must be closed with cost at least 2000 (a cost below fails with code 2 in byte `+1`); then its link slot to the parent grid is checked against the extras (gate 0 or an open gate bit in `+0x74` fails): phase 1, return 2. Everything else: phase 1, return 1.

**Grid search 0x294768 (a label-correcting search).** Pop the front of the open list (sorted by key, ties after equals, insertion 0x2160d8), close it, set its entry cell (0x1fc6a4: the goal cell for the goal grid, otherwise the link cell of the grid whose link leads to the parent and lies nearest to the parent's entry cell, the middle cell without a candidate). Three phases follow: while cost > key the parent is re-chosen among the neighbours by `cost(n) + edge(u -> n)`; a key of 0xc350 or more ends the step; with cost equal to key the neighbours are relaxed with `edge(n -> u)`, with cost not equal also the node itself and closed neighbours are re-queued. Costs saturate at 0xffff. Edge cost 0x1f9ea0: 10000 for a missing or closed grid, a closed link bit or a link without extras; 2000 for a restricted grid when `+0x74` has no bit 0, or when every extra is behind a closed gate; otherwise the distance of the two grid centres in world units (centre `(x + w/2) * cell`, `((h + ext/2) / 256) * unit`, `(z + d/2) * cell`, integer halving), `int(distance * 0.5 * 2.0)`; with the weight table the factor is the smallest positive weight (default 50) or the largest non-positive one.

**Exit cell 0x27d90c.** For a start grid with a parent grid, every link cell (bit 2, passable for the masks) whose extra leads to the parent and whose bit 6 is clear is scored `d(start)^2 + d(entry of the parent)^2` (squared cell distances; with the weight table `d2 * weight` or `- weight`) plus 250000 behind a closed gate; the lowest (first on ties) is the exit cell `+0x42`. While the parent grid's stamp is at most 1 s old the cell across the link must also be passable.

**Cell search 0x208338.** Cells with kind 2 are cleared when the stamp is older than 1 s. With an exit cell: clear the 256 cell nodes, seed the exit cell (cost 0) with 0x215e08 and walk a Bresenham line (error terms `2 * minor - major`, diagonal step cost 3, straight 2) from the exit to the start cell, calling 0x215e08 (insert the cell, close a passable one, expand its eight neighbours with parent links) for each; a blocked cell on the line clears the "clear" flag. A clear line marks every cell of the chain with the exit cell (mark `+2`) and ends. Otherwise 0x294b74 (the same label-correcting step over cells, neighbour offsets and the step cost table 3 2 3 2 2 3 2 3 at 0x376c0c, blocked 10000, temporary 2000) runs until the start cell is closed and the open list's best total is not below its cost; a cost under 10000 then goes through 0x27dc98, which marks each straight run of the parent chain with the run's last cell. The cell open list sorts by `key + int(sqrt(dz^2 + dx^2))` (distance to the start cell), ties by key. Without an exit cell the search first closes the link to the parent (`+0x36` bit) and re-searches the grids until the parent changes (loop at 0x2084f4).
Not ported: the time budget (200 ticks of a stopwatch unless byte 0 of the global is non-zero) and the obstacle pass 0x2af1cc (third argument of 0x208338, never passed by 0x204284; also called by the follower while `+0x7c` bit 0 is clear).

**Follower 0x1faf04(record, position, ...).** Dispatch on the phase: 0 returns 0 (arrived), 2 runs 0x27ddb4, 3 and 4 have their own branches (0x1fb104 and 0x1faf70), anything else returns 1. The result is the code in the low byte and a heading byte in bits 8..15. 0x27ddb4 (phase 2), with the obstacle pass skipped: the position must lie in the start grid (otherwise code 1, phase 1, diagnostic 4); a position on the exit cell, where the grid has extras and the extra named by `cell >> 3` has no bit 6, ends the path: same start and goal grid returns 0 with phase 0, a different grid starts the transition 0x272598. Otherwise the start cell moves to the current cell when the current cell is the start cell's mark; an exit cell of kind 3 without `+0x74` bit 0 returns 2 (byte 0xff); a start cell node that is not closed or costs 10000 or more returns 1 in the same grid; standing on the exit cell returns 3; else the next waypoint is the centre of the start cell's mark cell, stored at `+0x58`, and the result is 4 with the heading byte `int(atan2(dx, dz) * 128 / pi)`. So a plain AIMove inside one grid ends on the first tick in which the character is in the goal cell, and only if that grid has extras; a grid without extras (such as the restricted grids with only flag 0x4000, among them the police station entry grid 26 of lvl_01) keeps returning 3.

**Caller 0x2c5d3c (states 4 and 5).** The tick passes through target and attack checks (bit 3 of `+0xd9`, set by AIMove, skips them) and calls the follower with the record `+0xc8`. Code 0 ends a plain move (`+0xa8` zero): AIMove event 0x23cee8(`*0x3775e8`, entity, entity, **component byte 0**, 0) at **0x2c630c**, follow-up 0x1f8d5c (a target to attack found: 0x21102c state 2; none: idle 0x2246c0). Codes 1 and 2 count `+0x84` down and then send message 49 (0x244fc8). Codes 3 and 4 and above go to 0x1fae48: 3 clears the low nibble of `+0xd8` (and sets bit 2 of `+0xe` for locomotion 89), 4 turns toward the heading (0x1a6544) and walks, 5 and above call the gate handler 0x2684b8 (gate = code - 5), which for an unregistered gate marks the link off (0x202064, extra bit 6, cell kind 2, phase 2).

**Front end and flags (0x22d85c, corrects the earlier reading).** AIMove (0x171f7c) passes avoid argument 1 and the new stack argument 0, AIMoveNoAvoid (0x1cd798) the stack argument 1: **bit 0 of `+0x7c` is the stack argument**, so a plain AIMove has it clear (obstacle pass active, kind 2 cells block) and AIMoveNoAvoid has it set. Bit 3 of `+0xd9` is the avoid argument (1 for both), bit 5 the walk argument. The masks `+0x74` and `+0x78` of a new record are both `0x2b66d8(entity) | 1` (0x202054 in 0x206d18): bit 0 is always set, the other bits come from the gate types registered in the table at 0x376f10 (entity has the ability, callback result). The finder gate 0x1f9834 refuses a call when byte 0x3771d8 and the avoid argument are zero.
The phase byte `+0x7e` is 1 after record creation: 0 arrived, 1 failed / blocked, 2 path inside the grid, 3 after a transition (0x272598), 4 start beside a grid. The finder returns 3 without touching it for a restricted or closed start grid; the follower then returns 1.

**State 11 (0x2c3bd8) is the AISuperJump state.** 0x213300(entity, target, frames, height) is what AISuperJump calls (also 0x1fac38, 0x25e274, 0x25e318, 0x2baed0): it stores the target at `+0xb8`, sets heading `+6` and bit 0 of `+0xc`, computes a flight time from the height and the vertical offset, stores horizontal distance / frames at `+0x308` and the climb at `+0x30c`, starts locomotion state 72 and requests state 11. Each tick 0x2c3bd8: arrived when `+0x8c` (MinDistance, default -1.0) is greater than the horizontal distance (0x229708: sqrt(dx^2 + dz^2)), or when the character's y is below the target's (compare "higher or same" fails) and bit 6 of `+0x314` is set. Arrival raises the AIMove event (second site 0x2c3c68, byte 0) and does the same follow-up as above. Otherwise heading `+6` = `int(atan2(dx, dz) * 10430.378)` and bit 0 of `+0xe` is set; for `+0x6c == 1` locomotion state 72 is requested.

- The grid transition 0x272598 (target cell across the link, `+0x7f` obstacle callback, phase 3), the follower branches for phases 3 and 4 (0x1fb104, 0x1faf70), the rebuild at 0x27e12c for a path across grids, the obstacle pass 0x2af1cc and the stopwatch budget.
- Component byte 0 and who else raises the AIMove event with it; the follow-up lookup 0x1f8d5c; speeds (locomotion 72).
- No original run was compared: the finder and follower values are hand-evaluated from the code. An oracle trace of `+0x3c..+0x44`, `+0x58` and the result codes for one AIMove across several grids would confirm the search order.
