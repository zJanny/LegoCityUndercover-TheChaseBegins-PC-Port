# Vehicles: which props a vehicle contact destroys

What a moving vehicle does to the placed props of a level: the grid test for box and mesh entries, the reaction of each prop class to the vehicle's message 0, the bricks it releases and the timing against the port. The first findings (the pass 0x16ce9c -> 0x275c00, the wobbly handler) are in [vehicles-physics-props.md](vehicles-physics-props.md#ts-20261016-111522). Plan: [features/vehicles-prop-smash.md](../plans/features/vehicles-prop-smash.md).

**The grid test is the same for both kinds.** The branch of 0x237f30 for the descriptor mode 1 (0x238168 for kind 1 entries, 0x2381c8 for mode 2) takes the owner node matrix (0x250810), multiplies the entry's optional matrix (+0x14, null for entities), and runs 0x22ec3c on the shape at entry +0x18, whatever the entry kind: the entity box (+0x60 / +0x6c) of a box entry, the root node of the collision item (centre +0, half +0xc of the 0x1c-byte node) of a mesh entry. The filter 0x2c02c8 afterwards always uses the target's entity box +0x60 / +0x6c, also for a mesh entry. The port's mesh-kind props therefore use the item's root node in the first test and the automatic entity box in the second. Of the 674 wobbly props of lvl_01 393 register a mesh, among them all 62 `Lampost_*`; that is why cars drove through lamp posts in `chase-game`.

**Create.** 0x15a4b4 reads the class parameter `Destructable` (int, default 0) and passes it to the prop create 0x16a268, which stores it as the record mode +0xcc. The record (0xf0 bytes, zero-filled) exists for every mode other than 0, and for mode 0 when `ControlObject`, `TriggerObject`, `Navnode`, `ATTR_SFX`, `ATTR_SFX_DESTROYED`, `Rotating`, `Rocking` or `FaceTargetSpeed` is set; without it the entity byte +0x13 stays 2. Fields: +0xdb `ProjectileType` (default -1), +200 `ATTR_SFX_DESTROYED`, +0xde bit 0 cleared, bit 6 `Rocking`; `Health` (default 1) into +0xd4 (and +0xd5) for the modes 1, 4, 7 and 11, into +0xd4 for mode 3 (with `Damage` +0xd6 and `Radius` +0xcd); mode 11 also loads up to four clips `StudSpawnAnim01..04` into the slot words +0x10 + 0x10 n; for every mode `StudSpawnCount` +0xda, `StudSpawnAfterAnim` / `ReturnToIdle` / `WaitForAnim` / `RepeatLastAnim` (+0xde bits 2, 3, 4, 5), `StudSpawnParticleDef` +0xc4, per slot `StudSpawnFrame` +0x17, `StudSpawnSFXFrame` +0x18, `StudSpawnValue` +0x16, `ATTR_SFX_STUDSPAWN` +0x14, `StudSpawnDebris` +0x19; `DamageWhenCulled` +0xdf bit 3.

**Collision (post-link 0x15a640 -> 0x16aeb4).** 0x23e578 calls 0x23aff8(entity, +0x10 bit 0x100, bit 0x400, !+0xc bit 17, autoBox 1, margin 0): the CollisionBound record or the automatic box, `MeshCollision`, `BoundCollision` as in [collision.md](collision.md#ts-20261013-205344). Then, when no item was set and `HasCollisionMesh` is not 0, 0x2337e0 takes the model's first collision item as +0x78 with its root node as the entity box +0x60 / +0x6c, or else the model's box record (centre through its matrix, half) as the box. `Destructable` 6 or `NoBoundCollisions` clears 0x200. `NoPhysics` 0 (default 1) builds a physics body at +0x84 (0x23e090). The oracle grid of veh-smash-prop holds 29 kind 67 entries (mask 6); the 22 objects of lvl_01_cherrytreehills_main other than `Sea` (`NoBoundCollisions`, no item: no entry) are among them, each with the kind and box of this rule within 1e-3 (`1-4_WindowSmashed` keeps the 0.05 clamp of the automatic box, `1-4_Window` takes its box record with half x 0.0334; `1-3_crane_built` and the four roadblocks are mesh entries; `1-3_Crane_Girder` takes its box record). **Message 0, handler 0x15e408 (0x15e594).** In order: entity byte +0x13 = 2 returns 0; with a record and `ProjectileType` -1 or equal to message byte +0x15, the event 0x23cee8(*0x3775e0, entity, entity, 255, 0); message byte +0x15 in 1..6 returns; with a sender (msg+4): `IgnorePlayerDamage` and the sender being *0x3772c0 returns; `AbilityDestructable` set: the sender must pass 0x245b00 (kind 27 or 149, a kind of the character table 0x515a94 that 0x23e394 fills, or entity word +0xc bit 14) and 0x23a70c(sender record, ability) -> 0x219a8c, else return; sender kind 27 with mode 50, or message byte +0x14 = 2 with mode 52: health +0xd4 minus the damage, destroy at or below 0; mode 11 with message byte +0x16 = 255: the slot loop 0x15e780 (studs 0x23a6b0 and the destroy, not followed further); everything else goes to 0x2398d8(entity, 0, msg).

**What a car does.** The vehicle message (0x275e74: word 0, sender the vehicle, damage 100, byte +0x14 = 11, +0x15 = +0x16 = 0) reaches 0x15e408 only for targets without a physics body (0x275c00).
