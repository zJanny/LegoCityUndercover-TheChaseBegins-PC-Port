## 2026-11-12T00:10:29+01:00 — The writers of the brake light parts and the glow effect (llvm-objdump only, no REA session, no emulator)

**The parameter reader 0x1658a8(entity, record).** For u = 1, 2 the name `BrakeLightModel%02u` (format at 0x165c90) is looked up through the class values (0x241624); when the value exists and its first word is not 0, 0x23645c(node = entity +0x3c, value) gives the part, else -1; the part is stored at record +0x2ac + 4 (u - 1) and, when it is 0 or more, 0x2363d4(node, part, 0) hides it. For u = 1..4 `BrakeLightLocator%02u` (0x165ca4) is stored the same way at +0x2b4 + 4 (u - 1) without hiding. `BrakeLightParticle` (0x165cbc) is read by 0x2451d0 with the default 242 (a value of type 5 or 7 is its first word, a float is truncated) and stored at +0x2d8; the level +0x2d4 is set to 0.0. 0x165ce8 and 0x165d0c read the emergency light values (`EmergencyLightPattern`, `EmergencyLightDynamicLocator%02u`, `EmergencyLightParticle%02u`) after it, which this file does not follow.

**The node helpers.** 0x23645c(node, name): the model of the node (+0xc0, LOD 0) gives its node table through 0x250830(model, 0) (count at +2, entries of 24 bytes at +0xc whose first word is the name); the loop returns the first index whose name compares equal with 0x25ad90, else -1. 0x236368(node, part): the palette entry node +0x110 + 64 part when the node has a palette, else the entry of the model's +0x20 block when its w (+0x3c) is not 0, else the default matrix 0x52fce4; +0x30 of it is the translation. 0x2363d4(node, part, shown): the bit set +0x114 (one byte per eight parts, allocated on the first hide); shown clears the bit, not shown sets it. The visibility function 0x2072ec loops over the model's node table (count at +2, entries of 24 bytes whose halfword +0x10 is the node's mesh index, -1 for none) and skips the node whose bit is set (0x2074f4), so a part index is a node index.

**Part alpha 0x23f124 -> 0x10c6a4.** The message record is {alpha, part, 0}. With a part below 0 the node's alpha +0x11b is set; with a part, the handler walks the part's draw records and, for an alpha below 255, writes the blend mode bytes 4 and 5 and the material alpha (+6) = the model material's alpha x alpha / 255 (the multiply by 0x80808081 and shift 7), vertex alpha bytes +0x13 / +0x17 = the part's alpha, and for 255 copies the model's bytes back. The port draws a shown part with the instance fade scaled by alpha / 255 (the blended list, blend source alpha), which is the same blend for an opaque material (STAND-IN PED-S12 of the scene fade).

**What the port draws.** The part is the node with the model's node name; `Scene::setInstanceNodeShown(instance, node, shown, alpha)` hides the node's draw parts or scales their fade. 0x278b78 runs in the post step of every live traffic car; its part changes are applied after the cars' update. The glow effect starts at the world position of the locator node's matrix (the model's +0x20 entry +0x30 through the car's node matrix) and follows the car by setting the emitter position every update; it stops through the callback at event 2 (0x2cb42c) as in the original.

**Stand-ins (TRAFFIC-S36).** The emitter is not attached to the car's node (0x23de24 gets the node as parent and the position as an offset, then 0x241540 sets the matrix; the port's particle system has no parent mode, so the position follows by `setPosition` and the emitter's own node orientation is the identity); the undo of the lights (0x170e68 / message 251) runs when the car's entity is disabled, which of the two a removal reaches was not read; the brake input of 0x278b78 and the gear of the body (+0x294) are taken as the post step passes them and a forward gear (the port has no body, TRAFFIC-S28).
