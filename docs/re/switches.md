# Switches: the switch base class and the lever

The switch base: the record that the loader 0x23e84c fills for the switch kinds, its per-update state machine, its message handler, and the lever class (kind 58) that the key switch and the pull switch of mission 1-3 use. The reference-trigger step these classes call is in [script-triggers.md](script-triggers.md); the studs the state change drops are in [studs-drops.md](studs-drops.md).

## Current state

- Kind 38 (`lightonoff`) is the pure switch base: loader 0x23e84c, post-link 0x242494, link 0x23e5b0, update 0x1de740 (0x2424d0 with the stable-state update 0x21435c, then the state change 0x22c6d0), handler 0x23aac0. Kind 58 (levers, key switches, pull switches, keypads, valves, X spots, class lockers) adds a use zone, the message 3 use and its own handler 0x17f6f4 and update 0x175338 around it. States: 0 off, 1 used, 2 on with a reset timer, 3 on for good, 4 on with a reset timer (AlwaysReset), 5 switching off. [§2026-10-25T16:34:17](#ts-20261025-163417)
- A switch whose reference fires its target gets message 0xff back from the step and stays in state 3 (unless AlwaysReset); one that waits for a join stays in state 2 and switches off when its ResetTime runs out. [§2026-10-25T16:34:17](#ts-20261025-163417)
- Ported for kinds 38 and 58 (`switch_base.*`, `switch_set.*`); the mission 1-3 key switch opens the garage door in `chase-game`. The player's use state 76, the switch's use animation and the class code of the other kinds are not ported. [§2026-10-25T16:34:17](#ts-20261025-163417)
- Oracle (key switch of mission 1-3): placing the key only enables the switch; a second A press puts the player into state 76 (from update 8 to 81), the switch's use bit is set after update 31 with no message to its handler, state 1 follows at update 32 and state 3 (reference Fired, reset timer from 1.0) at 33; the shutter rises from about update 40. The port uses these update counts. [§2026-10-25T16:34:17](#ts-20261025-163417)

**Stable-state update 0x21435c** (0x2424d0 calls it only while state == target; shared by kinds 38, 58, 100, 125, 222 and called by 0x2847a0, 0x2b3b9c, 0x2b3fb8), by state:

- 1: no use animation, or the animation ended (0x245f84 == 6), or `TriggerBeforeAnim` → target 3 when `ResetTime` is -1, else 2.
- 2: use requested → reset timer = `ResetTime`, bit 0 cleared; else reset timer ≤ 0 → target 5.
- 3: nothing. 4: reset timer ≤ 0 → target 5.
- 5: no use animation → target 0; the animation ended → target 0 and the animation back to frame 0.

**What the step does to a switch.** In the target 2 branch the step runs before state takes the target: when the switch's reference fires its target (no other reference to that target is idle) the step sends message 0xff to every owner, and 0x23aac0 turns this switch's target 2 into 3 (or 4) before 0x22c998 stores it. A switch that only joins (another reference idle) gets nothing back, stays in state 2 and goes to 5 when its reset timer ends; target 5 deactivates the record (ObjectUnswitched; a Fired join also gets 0xfe and ObjectUntriggered). Another owner of the same join gets its 0xff in the middle of the firing switch's update, so its state follows in its own next update.
