## 2026-10-14T21:21:58+02:00 — AISuperJump set-up 0x213300, state 10 (0x2c5bc4), state 11 arrival value, state numbers of stalk, run away and pursuit

Corrected by [ai-states.md §2026-10-25T16:37:12](#ts-20261025-163712): ctrl+0x308 is read by the horizontal step 0x203d18 and ctrl+0x30c by the jump enter 0x200cc4; state 72 only starts state 73.

**State table.** Record N of the table built at 0x2a3c24 (global 0x3771f0) is at +16 N; word 0 is the update function. Read from the literals 0x2a3ea4..0x2a3f64: state 2 0x2c4708, 4 and 5 0x2c5d3c, 9 0x2c3a50, **10 0x2c5bc4**, 11 0x2c3bd8, 12 0x2c3d1c, 22 0x2cbe14, **25 0x28b7a0**, **27 0x2c1c90**, 35 and 36 both 0x2ab6cc.

**AISuperJump set-up 0x213300(entity, target, frames, height)** (AISuperJump passes frames = 28 and its height argument). v = target - node position (0x257f14, node = 0x250810(entity+0x3c), position at +0x30); the target is stored at ctrl+0xb8 (0x2554c0); heading ctrl+6 = int(atan2(vx, vz) * 10430.378) and bit 0 of ctrl+0xc are set. distance = sqrt(vx^2 + vz^2) (0x20e968; 0x25b578 is vsqrt). When vy > 0: frames = int((pi - asin(vy / (vy + height))) * 8.9126768) (0x1ff204 jumps to 0x2406c4, a fdlibm asinf: pio2_hi 0x3fc90000, pio2_lo 0x39fdaa22 and a sqrt; literals 0x40490fdb = pi and 0x410e9a53). ctrl+0x308 = distance / float(uint frames), ctrl+0x30c = max(vy, 0) + height. Then 0x2414b4(entity, ctrl+0x50, 72, 0) starts locomotion state 72 and 0x218b38(entity, ctrl, 11) requests state 11. Ported as `planSuperJump` (`src/runtime/ai_super_jump.*`); the formula is hand-evaluated for two cases in `ai-core` (the asin is the C library's, the original's polynomial may differ in the last bit, the result is truncated to an integer).

**State 11 arrival value.** ctrl+0x8c is written by the character set-up 0x236d74 at 0x236ed4 from `0x241280(entity, "ATTR_RunSpeed", 0, *0x37450c)`, default 0.23 ([player-locomotion.md](player-locomotion.md): the player's value read in the oracle). The -1.0 comes from constructors that run before (0x2309c8..0x2309e8 write one literal into +0x84..+0xa0). So state 11 ends when 0.23 (or the class value) is greater than the horizontal distance to the target: a jump lands within 0.23 of its target. Class overrides of `ATTR_RunSpeed` were not read for non-player characters.

**State 10, face target (0x2c5bc4).** Requested by 0x211110(entity, target) (stores 10 at ctrl+0x15, the target at +0xc4, bit 3 of +0xdb when the target is the player entity *0x3772b8, home position +0xb8 = node position). Each tick: node x and z are set to ctrl+0xb8 / ctrl+0xc0 (the home position) and the node is applied (0x24c118); when the target exists and bit 3 of +0xdb is set, +0xc4 is reset to the player entity; when a target with a node exists, heading ctrl+6 and ctrl+10 = int(atan2(dx, dz) * 10430.378) of target - node (0x23df44). Ported as `stepFaceTarget` (`src/runtime/ai_face_target.*`) and run by `AiCore::update`. The state never ends by itself.

**Set-up of the other natives.** AIRunAway 0x228c70(entity, -1.0, target 0x3772b8): requests state 25, sub-structure (ctrl+0xe0) +0xac = target, +0xa8 = -1.0. State 2 (0x2c4708, requested by 0x21102c) tests bit 3 of a class table word, calls 0x206ad0, and goes idle (0x2246c0) when the target +0xc4 is invalid (0x245b00) or its ctrl+0x6c fails the tests (324 / 0x2107e0), else continues in 0x2bb558. `AiCore` records the requested state numbers 25 and 27 of the natives.

**Follow-up lookup 0x1f8d5c** (target to attack after a move, shared by the arrival sites 0x2c3c68 and 0x2c630c) is a target search over the player and entity lists (about 0x200 bytes; uses +0xd9 bit 0 and +0xc4); not transcribed. `AiCore` stands in "no target": idle.

The 52 bad guys of lvl_01 are 46 of row 142 with behaviour 0, three `char_ai_goon_fists` with behaviour 2, two `char_ai_tonyknucklesmcgee` (row 163) and the booster chaser (row 147, behaviour 2).

**Weapon choice 0x1f6e40 and mode 0x1f6d90.** 0x1f6d90 answers the mode for the distance d to the target: 3 for behaviour 3; 2 (melee) for a melee character of behaviour 0, 2 or 5 within 1.5 x ctrl+0x80; 4 for behaviour 4; else, for a ranged character of behaviour 0 or 1, 1 (ranged) within ctrl+0x7c (and beyond 1.5 x ctrl+0x80 when it has melee too); else 3. 0x1f6e40 sets the switch presses ctrl+0xe bits 9 (melee), 10 (ranged), 11 (third) when the mode's weapon is not out. Every fight decision calls it first.

**The ticket 0x1f6b40(entity)**: 1 for a boss. It walks the bad-guy list 0x58deb0 (whatever the side of the asker): every other member that attacks the asker's target (0x1fbb54: same ctrl+0xc4, AI state 3, 5, 28 or 31..34) counts when its melee weapon is out; at the limit 0x3771e0 (1) the answer is 0. An asker with its ranged weapon out then counts the members with theirs out against 0x3771e4 (2).

**Decision of state 2 (0x2c4708 -> 0x2bb558).** A target that is a character in ARREST or ARRESTED (323, 324) or that passes the arrest test 0x2107e0 ends in idle. Then: without a target with a node the search 0x1f8d5c (none: the release 0x21decc and return); the sight test 0x1f6958 must pass (else mill about with ctrl+0x315 bit 7, or idle). The heading ctrl+6 turns to the target; in locomotion state 4 only the move bit ctrl+0xc bit 0 is set. Else ctrl+10 = ctrl+6, range = ctrl+0x80 (ctrl+0x7c with a ranged weapon out), d = 0x2507dc (3D), ticket = 0x1f6b40.
- range > d: the hand-over 0x2080a0(entity, target): log "Attacking %s (%s mode; %.2f)", ctrl+0xb8 = own position, AI request 3, ctrl+0xd9 bit 2 and ctrl+0xa8 cleared.
- Else with ctrl+0x84 0 and a ticket: the hand-over too, unless the character has a range bound and the target stands outside it.
- Else, with ctrl+0x84 0: 0x235498(5) is drawn; on 0, with the character's ctrl+0x316 bit 5, a target that is no character kind (0x21aae0) or is visible, and a pending locomotion state 1..3, it taunts: locomotion 111 TAUNT, AI request 16, ctrl+0x84 = 10 + random % 10.
- Else with `AIDontChase` ctrl+0x84 is lowered by 1 without a test for 0; without it a non-zero ctrl+0x84 counts down, and at 0 the hold move: unless d <= 3 x ctrl+0x80 without a ticket, ctrl+0xb8 = target + (self - target) x s with s = 3 x ctrl+0x80 / d without a ticket (the character waits 3 melee distances out) or range / (2 d) with one, and the move 0x22d85c(entity, ctrl+0xb8, 0, `AIDontRun`, 0); then ctrl+0x84 = 10 + random % 10.
- Last, when the request is still 2 and ctrl+0x84 is 0: hidden (0x23de70) goes idle with a new countdown; else with ctrl+0x72 0 the target is searched again (none: idle). Then the bound keeper 0x1faa6c and ctrl+0x72 counts down.

**Decision of state 3 (0x2b82ec -> 0x2a92a4).** With ability 63 and not in locomotion 163 / 164: when ctrl+0x84 is not above 0, 0x2345dc() is below the float 0x374310 and the target is nearer than 0x21a1d0, AI request 33 (the charge; not read further). With ctrl+0x84 0, a target, ability 54, a current state 1..3, a ticket and 0x1f5114(entity, target, 3.0): **AI request 31**. A player target in the air ends in idle for characters with sub +0x12e bit 5; so does a target under arrest (as in state 2). Then 0x2a92a4: no target is idle; ctrl+0x84 above 0 counts down and skips the rest; else the attack routine 0x2896d4(entity, mode of 0x1f6d90) answers
- 0 (nothing to do, or G): nothing;
- 1 (out of range): unless `AIDontChase`, the chase 0x2a136c(entity, 0, `AIDontRun`, range); when it started, ctrl+0x84 = ctrl+0x77 and AI request 5. Else ctrl+0x84 = 10 + random % 10 and a search: a target found is sighted again (0x21102c, AI state 2), none is mill about or idle;
- 2 or 4 (no target to attack, the same side): the search; another target is sighted, the same or none is mill about or idle;
- 3 (pressed): unless `AIIgnorePlayer` or ctrl+0x72, a target beyond the range (or any for a boss) is replaced by the search's (none: idle).

Then, with a ranged weapon out, ctrl+0x140 = target and the aim 0x205fbc; a character without a ticket, or whose target is invisible to it (0x1f6b18), is sent back by the sighting 0x21102c; the bound keeper; ctrl+0x72 counts down.

**The attack routine 0x2896d4(entity, mode).** 2 without a target, for a target of mode ctrl+0xda & 7 other than 0 (2 only when the target targets the entity, 3 only for the player as attacker) or without a node; 4 for the same side; 0 in locomotion 163 / 164. Unless `AIDontFaceTarget` (or mode 1 with byte 0x3771d5) ctrl+6 and ctrl+10 turn to the target. With `AILineOfSight` a ray between the two (0x22b108) that is blocked answers 1. Only a character that has turned (ctrl+10 - ctrl+8 within 0x13fe / 2) and whose ctrl+0x84 is not above 0 goes on: a boss always, anyone else only when its side's cool-down word is 0, which it sets to 10. Then by mode: 1 ctrl+0x84 = ctrl+0x75 + random % ctrl+0x76 and press ctrl+0xe bit 6; 2 and 5 ctrl+0x84 = ctrl+0x73 + random % ctrl+0x74 and press bit 5 (beyond ctrl+0x80: the old heading back, answer 1); 3 the old heading back, answer 0; 4 the ranged delay and bit 7; 0 ctrl+0x84 = 30 + random % 30. Last: a destroyed target answers 2; a target beyond the range (ctrl+0x7c with the ranged weapon out) restores the heading, clears the three press bits and answers 1; else 3 when a bit was pressed, 0 when not. The AI controller 0x200c30 ors ctrl+0xe into the button word ctrl+0xc after the decision.

**The move 0x22d85c(entity, destination, avoid, walk, no-avoid).** 0 when (G clear) the destination and the character are both outside its range bound, when no path record ctrl+0xc8 can be had (the engage 0x206d18), or when the path request 0x1f9834 answers 1 ("I can't get there"). Else ctrl+0xb8 = destination, AI request 4, ctrl+0xd9 bit 5 = walk, bit 3 = avoid, ctrl+0x84 = 5, answer 1. **The chase 0x2a136c(entity, avoid, walk, range)**: P = the entity's offset +0x60 at the target's node with the target's height; 0 when |self - P| is not above 0.8 x range; else the move to target + unit(self - P) x 0.8 x range (with byte 0x3771d4 the two radii +0x5c instead); when that fails and the range is above 3, the move to P.

**Decision of states 4 and 5 (0x2c5d3c).** Weapon choice, ctrl+0x72 counts down; the ticket is 1 in state 5. The chase part runs in state 5, and in state 4 only for a bad guy without `AIIgnorePlayer` whose move had no avoid flag (and never with the low four bits of ctrl+0xd8, whose writer 0x2c9ee8 was not read): a target is searched when none is kept; with a ticket an invisible target ends in locomotion 113 LOST TARGET; a friendly character without a slot gives up beyond its view distance; a target nearer than the range (and not behind a blocked `AILineOfSight` ray) is handed to state 3 with a ticket and sighted (state 2) without; a target that moved more than max(range, 5) from ctrl+0xb8 gets a new chase 0x2a136c with the state kept (idle when it left the range bound). Then 0x23d4c0(entity, position, 0, 3.0) (not read) and the follower 0x1faf04: arrived in state 5 with a target is the hand-over 0x2080a0; arrived otherwise takes the next point of a simple path (ctrl+0xa8) or raises the AIMove event 0x23cee8(*0x3775e8, entity, entity, component byte 0, 0) and searches (sighting or idle); blocked counts ctrl+0x84 down, then sends message 49, tries the path again for a move with the avoid flag, else logs "I can't get there", searches and sets ctrl+0x84 = 10 + random % 10; moving applies 0x1fae48. A move without the avoid flag ends with the bound keeper.

**The bound keeper 0x1faa6c(entity).** Inside the range bound (or without one): with the move bit, the next step position + ctrl+0x8c x (sin, 0, cos) of the heading must stay inside; if not the heading turns to the target, and if that step leaves too the move bit is cleared, ctrl+10 = ctrl+6 and a walk of state 4 or 5 is reset (0x215988) and asked again as state 4. Outside the bound: a boss jumps back with AISuperJump (0x213300, 28 frames) when beyond the bound's half sizes plus its own; anyone not in locomotion 72 turns to the bound's centre with the move bit (and bit 3 with `AIDontRun`), and a walk of state 4 or 5 is reset.

**State 31 (enter 0x2c1ad4, decision 0x2c9d24), the strike.** The enter sets ctrl+0x140 = target and 0x206ad0(ctrl, 1, 1) (melee weapon out). The decision goes by the character's locomotion state: in any other state it holds button bit 7 of ctrl+0xc and turns to the target; in 304 it holds on while 0x1f5114(entity, target, 4.5) passes (or the target is in locomotion 163 with combat record byte +9 = 8) and sets ctrl+0x84 = the update rate x the float +56 of the character's `HitTimingStun` row of tablescombat sheet 5; in 305 it holds, counts ctrl+0x84 down and at 0 presses bit 5 (the strike); 306 requests AI state 32; 230 (MELEE PARRY), or a failed 0x1f5114 in 304 / 305, ends in idle with ctrl+0x84 = ctrl+0x73 + random % ctrl+0x74. 304 and 305 are the two states in which the player's counter finds a goon ([combat-characters.md §2026-11-01T15:23:21](combat-characters.md#ts-20261101-152321)). 0x1f5114(entity, target, reach): the target is the player, both stand on the ground (ctrl+0x314 bit 6), the player is in state 257 or can be targeted (0x219ba0), 0x20bf3c and 0x219990 pass and the distance between the two entity offsets +0x60, less the target's radius +0x5c, is within the reach.

**So a mission 1-4 goon** (by the code): sighted, it goes 2 -> 3 in the next decision (alone, target in the bound); in 3, too far to strike, the attack routine answers 0 once (it takes the cool-down, behaviour 3) and 1 from the next update, so it chases (state 5) to 0.8 x 2.2 from the player, is handed back to 3 within 2.2, waits the 10 updates of `AITargetDelay` and, within reach 3, starts the strike (state 31). It never presses the attack bits of 0x2896d4 itself. A second goon without a ticket starts for the hold point 6.6 out, but that point is more than 5 from the player, so its first decision of state 4 replaces the walk by the chase path; arrived, it is sighted again and state 2 hands it over within 2.2 whatever the ticket. Only a character whose 3 x ctrl+0x80 is within 5 keeps the hold point.

**AIRunAway, state 25.** Enter 0x26a9d4: the release, ctrl+0x84 = 0, a run, then 0x2013f4, which picks a path with 0x1fa88c(record, position, box, 10): the range bound when the character has one, else a box of half size 5 placed 10 away from the threat sub +0xac (0x23b92c), or around a random offset (0x25b390) without one. Decision 0x28b7a0: the follower; arrived picks again (0x2013f4), blocked asks for a path in a box of half size 10 around itself, moving applies 0x1fae48; then the bound keeper. Update 0x275ed4: with a distance sub +0xa8 of 0 or more (the native passes -1, never), no threat or one farther than it requests state 0.

**AIStalkPlayer, state 27 (0x2c1c90).** A bad guy without `AIIgnorePlayer` or the avoid flag whose target has no node goes idle. The follower: arrived runs the face decision 0x2c5bc4; arrived or blocked then counts ctrl+0x84 down and, at 0 with the target farther than sub +0xa4, asks 0x1fc080 for a new path to target + unit(self - target) x sub +0xa4 (ctrl+0x84 = 15); moving applies 0x1fae48; then the bound keeper.

**AIPursuit, states 35 and 36 (0x2ab6cc).** The character runs along pursuit nodes (sub +0xb4): blocked asks again for a path to the node (0x21038c(point, 10), log "[AI PURSUIT] no valid route to pursuit node"); within 1.0 of the node or arrived, and only when the player (*0x3772b8) is nearer to the node than the node's float +4 (0x2ad530), it goes on to the node's next (0x261074: word 0 of the node's record; 0x231108 on the new node) or, at the last node, raises the PursuitEnded trigger of the character (0x23cff4(*0x376008), after 0x241304) or goes idle. The states 35 and 36 share the decision; the takedown flag was not followed.

**Port.** `src/runtime/ai_pursuit.*` holds the decisions of states 2, 3, 4 / 5 and 31 as a state table over the entities of the idle conduct (`goon_conduct.*` calls it, with the controller's engage of 0x200c5c for these states), the ticket, the weapon mode, the behaviour adjustment, the character-row facts (which also fill ctrl+0xdb bit 1 of the sight test), the move, the chase and the side cool-downs; walks run through the conduct's walker (`AiCore::startPatrolWalk` / `followPatrolWalk`) and the hit aggro 0x1d1170 now acts on the conduct's entity (`LevelSession::aiAggro`). CTest `ai-pursuit` pins the rules on made-up characters with the goon's table rows; `game-goon-conduct-1-4` the run in chase-game. Stand-ins SCRIPT-S341 (inputs taken as clear: G, the taunt bit, the sight ray, the turn test, the low bits of ctrl+0xd8, the charge of ability 63, sub +0x12e bit 5), SCRIPT-S342 (node positions for the strike reach and the chase point, the keeper reduced to its test, no decision in a hit, takedown or arrest state, the arrest target from the arrestable list, the turn applied at once) and SCRIPT-S343 (in state 31 the character only holds and faces its target while 0x1f5114 with reach 4.5 passes and then leaves like a failed wind-up, because the locomotion states 304 to 306 are not ported; it never strikes).
