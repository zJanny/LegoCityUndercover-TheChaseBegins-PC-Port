## 2026-10-25T11:21:25+01:00 — The reference-trigger step 0x23211c in full: records, lists, events, messages, nav node, and the classes that register and call it (llvm-objdump of artifacts/game/game.arm.elf, level data through chase_assets; no REA session, no new oracle run)

**Record and lists.** `0x269d2c(entity, record, name)` is the only writer of the list at 0x591d88 (8-byte entries {entity, record}, count word 0x377424). It clears the record's kind (byte 0, bits 0 to 4), stores `AiAssist` in bits 6 and 7, `record+4` = the slot of the object-reference parameter `name` (always `TriggerObject`, string 0x359bb8), `record+8` = the slot of `NextSwitch` (0x359b98), byte 1 = 0xff, sets bit 5 of byte 0 and registers {entity, record} when either slot holds a non-zero name hash (a zero slot is cleared to null). Its two callers are the loaders 0x233de8 and 0x23e84c; both clear bit 5 again and read the int parameter `NavNode` (0x359bb0, default 255) into byte 1, and when it is not 255 register {entity, record} in a second list (base 0x5923c8, count word 0x377428). The level-start pass 0x2fed98 walks that second list and calls `0x22c470(*0x37754c, NavNode, kind != 0)` for each entry whose entity passes 0x1a5184 (so the nav node flags follow the record state). 0x1b6584 returns the kind of the first entry of an owner (3 when there is none), a getter for class code.

**Kind byte.** Byte 0 bits 0 to 4: 0 idle, 1 registered, 2 fired. Bit 5 is set only between 0x269d2c and the end of the loader; the owner search skips entries with bit 5 set. A name slot is resolved to an entity with 0x238354 (name hash to entity; 0 when no object has the hash).

**The step 0x23211c(owner r0, record r1, mode r2).** With r1 = 0 it searches the list from the start and keeps the last entry whose owner is r0 and whose bit 5 is clear (none: return). Target = 0x238354(`*record+4`), 0 when the slot is null. Order of effects, with the instruction that does it:
- Activate (r2 = 1): kind 1 returns at once (0x2321b4). Kind := 1. Event `*0x3775d8` on the owner, the owner as instigator (0x2321dc). Target 0: go to the nav node call. Otherwise, if any entry with the same resolved target has kind 0 (bits 0 to 4 clear; the current entry is already 1): message 10 to the target with the owner as instigator and **return** (0x232370, tail call of 0x244fc8; the nav node call is skipped). If none is idle: message 10 to the target (0x232258), then every entry with that target (list order) gets kind := 2 and message 0xff to its own owner with that owner as instigator (0x2323f0), then `0x242cf0(target)` (enable), message 0xff to the target (instigator = the owner of this call), and event `*0x3775d0` on the target with the owner as instigator (0x232438). Nav node call at 0x232448: byte 1 != 0xff gives `0x22c470(*0x37754c, byte 1, 1)`.
- Deactivate (r2 = 0, 0x23226c): kind 0 returns. Kind 2 with a target: every entry with that target gets kind := 1 and message 0xfe to its owner (itself as instigator); then message 0xfe to the target, event `*0x3775d4` on the target (instigator = owner of this call). Then, for any non-zero kind: `0x22c470(..., byte 1, 0)` when byte 1 != 0xff, event `*0x3775dc` on the owner, kind := 0 (0x232368).
- `0x22c470(manager, id, active)` finds the section whose id range holds `id` and sets bit 15 of the halfword at node `+0x34` to `active ^ 1` (nothing when no section holds it).
- 0x244fc8(entity, message, instigator) calls the message handler at +0x14 of the class descriptor `0x583124 + kind * 40`. 0x244f40 (the code-side trigger of carry and use spots) is the target part alone: enable, message 0xff, `*0x3775d0`; 0x244f88 is message 0xfe and `*0x3775d4`.
