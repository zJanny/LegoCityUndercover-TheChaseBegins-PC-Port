# Level transitions

## 1. Scope

Leaving a street for a building and travelling between world levels: `SceneChange` script native, `scenechange` objects, the loading page, the destination placement. Room loading is in [world-streaming.md](world-streaming.md). The police station (lvl_00) and the city (lvl_01) are separate level files in the port.

## 2. Status

IN_PROGRESS, updated 2026-10-20T09:17:09+02:00. `chase-game` switches between the police station and the street at run time in both directions: the lobby exit (walk-in bound of a master `scenechange` object) and the entry (script `Police_ExtToInt`, `SceneChange` native) show the loading page, wait for A and place the player at the destination point of the original (positions and headings from oracle traces). The master level is not loaded as a scene (TRANS-3), the loading page is a stand-in, and the lifts inside the station take the same-level entry (slot +0x28: no loading page, the player is moved, TRANS-S6), the other world levels are not done.

## 3. Verified behaviour

- `SceneChange <bound>` (handler 0x1b262c) finds a `scenechange` object (type 78) by bound hash and sends it message 0xff; manager slot +0x2c (0x3037e8) stores the request (`[[entity+0x7c]+0x14]` at +0x28) and pushes the loading page (mode 6); after the A press the execution 0x303480 unloads and reloads the world when the destination world level is not loaded and only moves the player when it is. evidence: [streaming.md §2026-10-13T22:27](../../re/streaming.md#ts-20261013-222700), [§2026-10-14T11:13](../../re/streaming-transitions.md#ts-20261014-111312).
- Entry order in the original (unmodified state): trigger `PlayerOnFootBoundEntered` on `Police_Station_Transition_Lower`, `WarningDialogBox`, 3 s wait, `SceneChange`, loading page, second A, switch 4 updates later; the dialog answer does not request the switch. The master level lists 35 `scenechange` objects with qualified bounds (`WorldLevel_01_CherryTreeHills.Police_ExtToInt`).
- Exit in the original: no script. The master object `SceneChange_LobbyToCherryTree` fires from its own update 0x1c47e8 when the player is inside its enabled bound `Lobby_to_CherryTree` of lvl_00 (update 13 of the traced walk, z 20.156 inside, 19.673 outside), through manager slot +0x2c when the destination world level is not loaded (slot +0x28, 0x3038a0, without loading page, when it is). evidence: [streaming-transitions.md §2026-10-14T12:02](../../re/streaming-transitions.md#ts-20261014-120258).
- Destination: the `SceneChangeTo` parameter (hash d2fb9421) is a 20-byte reference {world level hash, point hash, pointer, flags, scene index byte +0xd}; the player lands exactly on the `point` object, heading = its yaw, no world level offset: lobby to street (902.00848, 16.57730, 1111.12634) yaw 249.25; street to lobby (-1.11520, 2.09010, 15.70230) yaw 152.32, then it falls to y 1.43053. The second destination parameter (hash 0xccaaccdd) is not read. `scene-change-real-data`, `game-scene-change-exit`, `game-scene-change-entry`.
- Loading page (oracle screenshot): key art on the top screen, black bottom screen with a blue line, badge and `Continue (A)` bottom right; the same in both directions. The A wait is in the generic menu widget (addresses in the streaming entry).
- Entries inside a loaded level: a `scenechange` object whose destination point resolves in a loaded scene takes manager slot +0x28 (0x3038a0): it pushes the same mode node as +0x2c without the loading page, 0x303480 then only moves the player (no `OnSceneExit` / `OnSceneEnter`, no A). The four lift objects of lvl_00 (unqualified references) and six master objects use it; `chase-game` lands the player on the destination point one update after the request (`same-level-entry-real-data`, `game-same-level-entry`). evidence: [level-transitions.md §2026-10-20T09:16:06](../../re/level-transitions.md#ts-20261020-091606).
- Event bindings (bound entered and others to scripts) are decoded and pinned (`streaming-real-data`).

## 4. Stand-ins

- TRANS-S1 The port runs one level file at a time and rebuilds the level at each switch (`chase-game`), not the master level `lvl_the_city` with resident world levels; the state of the left level is lost, and `--call-script` runs again in the new level when it has the script (stands in for the saved game, SAVE-1). needs: TRANS-3.
- TRANS-S2 `SceneChange <bound>` is qualified with the calling level's world level instance name (data fit, every shipped call matches; 0x26344c not read). needs: TRANS-10.
- TRANS-S3 The loading page is drawn from one oracle screenshot (`drawSceneChangeBottom`); the top screen shows the generic1 background instead of the key art, the badge has no ring (the original shows the spinning 3D badge, user report 2026-10-14: FE-3), the text key `Continue` (systemtext 0xe3f70996) is inferred from the text. needs: TRANS-8, TRANS-14.
- TRANS-S4 The page accepts A from its first update, and nothing runs between the A press and the switch, which comes 4 updates after the press (trap measurement of the execution 0x303480). needs: TRANS-8.
- TRANS-S6 The same-level entry applies the move one update after the request and does not hold the level meanwhile; the fade and mode node of slot +0x28 are not ported, the destination room is assumed loaded, and the loaded set of the port is the current level only (a destination in another world level takes the loading page). needs: TRANS-15, TRANS-16, TRANS-3.
- TRANS-S5 The follow camera is reset behind the landing heading after a switch; the original's pose was not compared. needs: TRANS-12.
