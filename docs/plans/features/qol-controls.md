# QoL PC controls

## 1. Scope

Escape that is consistent and never closes the game, and the overhaul of the controls so that the game plays like a typical PC game on foot and drives like a typical PC driving game. Plan: [qol.md](../qol.md). A QoL feature with its own "PC controls" toggle on the Quality of life tab (on in Improved, off in Original); with it off the faithful 3DS mapping of [input](input.md) holds. The Escape rules apply in both modes. Design: [qol-controls.md](../../design/qol-controls.md). The settings menu and its Controls tab are [qol-settings-ui](qol-settings-ui.md).

## 3. Verified behaviour

PC controls toggle and on-foot set pinned by test `qol-pc-controls` against the design entry (original mode first: no file written, `config/controls.cfg` untouched; Original off, Improved on, Custom own mix; the layout key by key; the running input; toggle through the settings menu; rebinds and Reset kept per mapping). Escape (QOLCTL-1) and Quit game (QOLCTL-5), tests `escape-binding`, `qol-ui-page-game`, `qol-ui-menu`, `qol-quit-event`, `qol-pause-entry-real-data`: Escape is a fixed second binding of Start in `chase-game` (`InputState::fix`), never a quit; Quit game asks "Quit the game?" with Yes and No (focus on No), Yes pushes `SDL_QUIT`, No, Escape, pad B and a click on No cancel. Mouse camera (QOLCTL-6), test `qol-pc-mouse-camera`: with the toggle off the cursor is never captured and no motion turns; on, a captured cursor adds mouse X as an analog R value to the follow camera's shoulder turn (same camera yaw as R in proportion; left is negative; Y gives nothing; Invert camera flips it); a menu (pause screen or settings menu) drops the capture and the motion; a hidden pointer starts at the real cursor, follows the relative motion and, entering the lower-screen rectangle, releases the capture and puts the real cursor there; moving the cursor out captures again; a held mouse button never starts a capture (a touch drag); the lower screen hidden in Improved never releases. Left button Y, middle button L and R, right button unused: already pinned by `qol-pc-controls`. Escape on the pause screen (QOLCTL-12), test `escape-pause-pages`: play keeps Start; every page of the open pause screen takes B (the main wheel resumes with the back sound, Options and Languages go back one page, a second Escape closes), and a held key keeps its button until released. Vehicle keys (QOLCTL-3, QOLCTL-7), tests `qol-pc-vehicle-controls` and `qol-pc-vehicle-controls-game`: the vehicle set pinned key by key against the design (W or Up accelerate A, S, Down or Space brake B, A and D or the arrows steer, H horn Y, F leave X; E, Return, left mouse and R unbound; no hand brake or siren), the seated switch (Original never switches), the vehicle file kept apart from `controls.pc.cfg`, and a scripted drive into the van of mission 1-1 printing the switch. Add missing keys (QOLCTL-10): an old-format file keeps every binding and gets only the actions it lacks, with free keys, rewritten strictly and unchanged at the next start. Every behaviour is tested first in original mode (all QoL off, the port's tests unchanged), then with the feature on ([qol rules](../../rules/qol.md)).

## 4. Stand-ins

- QOLCTL-S5 — The mouse camera's sensitivity is a fixed 0.0018 button-seconds per pixel (`mouseShoulderSecondsPerPixel` in `src/qol/pc_mouse_camera.hpp`: about 0.0022 rad of yaw per pixel at the OnFoot turn gain). Replaced by: QOLCTL-15. evidence: [qol-controls.md §2026-11-01T13:50:47](../../design/qol-controls.md#ts-20261101-135047).

- QOLCTL-S4 — The vehicle set lives in its own file `config/controls.pc.vehicle.cfg` (the design names no file) and can be changed only by editing it. Replaced by: QOLCTL-13. evidence: [qol-controls.md §2026-11-01T13:50:47](../../design/qol-controls.md#ts-20261101-135047).
