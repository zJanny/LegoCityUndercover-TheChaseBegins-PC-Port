# QoL PC controls

## 1. Scope

Escape that is consistent and never closes the game, and the overhaul of the controls so that the game plays like a typical PC game on foot and drives like a typical PC driving game. Plan: [qol.md](../qol.md). A QoL feature with its own "PC controls" toggle on the Quality of life tab (on in Improved, off in Original); with it off the faithful 3DS mapping of [input](input.md) holds. The Escape rules apply in both modes. Design: [qol-controls.md](../../design/qol-controls.md). The settings menu and its Controls tab are [qol-settings-ui](qol-settings-ui.md).

## 3. Verified behaviour

PC controls toggle and on-foot set pinned by test `qol-pc-controls` against the design entry (original mode first: no file written, `config/controls.cfg` untouched; Original off, Improved on, Custom own mix; the layout key by key; the running input; toggle through the settings menu; rebinds and Reset kept per mapping). Escape (QOLCTL-1) and Quit game (QOLCTL-5), tests `escape-binding`, `qol-ui-page-game`, `qol-ui-menu`, `qol-quit-event`, `qol-pause-entry-real-data`: Escape is a fixed second binding of Start in `chase-game` (`InputState::fix`), never a quit; Quit game asks "Quit the game?" with Yes and No (focus on No), Yes pushes `SDL_QUIT`, No, Escape, pad B and a click on No cancel. Mouse camera (QOLCTL-6), test `qol-pc-mouse-camera`: with the toggle off the cursor is never captured and no motion turns; on, a captured cursor adds mouse X as an analog R value to the follow camera's shoulder turn (same camera yaw as R in proportion; left is negative; Y gives nothing; Invert camera flips it); a menu (pause screen or settings menu) drops the capture and the motion; a hidden pointer starts at the real cursor, follows the relative motion and, entering the lower-screen rectangle, releases the capture and puts the real cursor there; moving the cursor out captures again; a held mouse button never starts a capture (a touch drag); the lower screen hidden in Improved never releases. Left button Y, middle button L and R, right button unused: already pinned by `qol-pc-controls`. Mouse sensitivity (QOLCTL-15), test `qol-mouse-sensitivity`: 12 steps x0.25 to x3.00, default x1.00 = 0.0018 button-seconds per pixel; `mouse_sensitivity` in `config/qol.cfg` is written only when not x1.00 and rejects off-step, out-of-range, malformed, extra and repeated values; the row sits above the bindings of the Controls tab, greyed out in Original, hidden in Custom with PC controls off; Reset to defaults of the Controls tab sets x1.00 too; the help line is "How fast the camera turns when you move the mouse."; the camera scales by the active setting. Escape on the pause screen (QOLCTL-12), test `escape-pause-pages`: play keeps Start; every page of the open pause screen takes B (the main wheel resumes with the back sound, Options and Languages go back one page, a second Escape closes), and a held key keeps its button until released. Vehicle keys (QOLCTL-3, QOLCTL-7), tests `qol-pc-vehicle-controls` and `qol-pc-vehicle-controls-game`: the vehicle set pinned key by key against the design (W or Up accelerate A, S, Down or Space brake B, A and D or the arrows steer, H horn Y, F leave X; E, Return, left mouse and R unbound; no hand brake or siren), the seated switch (Original never switches), the vehicle file kept apart from `controls.pc.cfg`, and a scripted drive into the van of mission 1-1 printing the switch. Add missing keys (QOLCTL-10): an old-format file keeps every binding and gets only the actions it lacks, with free keys, rewritten strictly and unchanged at the next start. Controls tab switch (QOLCTL-13), test `qol-controls-set-switch`: with PC controls off no switch and no PC file; on, the first row "Controls for" (On foot or Vehicle) moves with keyboard, pad and a value change (a click), lists, rebinds, resets and checks conflicts in the chosen set only, writes only that set's file, is locked while a prompt waits, keeps its choice over off and on, and a hint line names the set and file. Held keys across the switch (QOLCTL-14), test `qol-held-keys-switch`: `InputState::rebindKeepingHeld` (used only by `QolWindow::syncSeatedControls`) keeps every physical key that is held, whatever action it has in the new set, and a toggle state when the new set has the same action, key and mode (F3 stays on); a fixed binding (Escape) is untouched; the plain `rebind` of the original mode and of file reloads still drops both. Rule approved by the user on 2026-11-12 ("Key stays held", [qol-controls.md §2026-11-01T13:50:47](../../design/qol-controls.md#ts-20261101-135047)): the key, not the action, is what stays held (W held on foot accelerates after sitting down). Bug QOLCTL-16, tests `qol-pc-controls-off-view`, `qol-bottom-hook`, `qol-view-hook`, `qol-hud-hook`: PC controls on to off keeps the widened view and the hidden bottom screen in Original, Custom and Improved. Every behaviour is tested first in original mode (all QoL off, the port's tests unchanged), then with the feature on ([qol rules](../../rules/qol.md)).
