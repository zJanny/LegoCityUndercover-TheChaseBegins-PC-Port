# QoL settings menu: modern PC menu

## 1. Scope

The redesigned PC settings menu: a full-window overlay with top tabs, bundled font, crisp text and widgets at the window's real resolution, shared mouse and keyboard focus, and its dialogs (reset, binding conflict, keep settings). It replaces the drawing of [qol-settings-drawing](qol-settings-drawing.md); the models and stores of [qol-settings-menu](qol-settings-menu.md) and [qol-settings-tabs](qol-settings-tabs.md) stay. Plan: [qol.md](../qol.md).

## 7. Code and tests

- Font and licences: `third_party/fonts/NotoSans-Regular.ttf` (Noto Sans Regular, hinted), `third_party/fonts/OFL.txt`, `third_party/stb/stb_truetype.h` (rasteriser, MIT or public domain); sources and commits in `REUSE.toml`. The binary-file check admits only `third_party/fonts/*.ttf` (user decision 2026-10-30). Test `qol-bundled-font` (`tests/qol/bundled_font.cmake`).
- `src/render/ui_font.*` and `ui_text_layout.*` (library `chase_ui_font`, no OpenGL, usable as a measure callback): `uiTextWidth`, `uiFontMetrics`, `uiKerning` (GPOS kerning through stb), `decodeUtf8`, `UiGlyphAtlas` (shelf-packed R8 atlas, one entry per code point and whole pixel size) and `layoutUiText` (quads of a line with per-glyph clipping). Pixel sizes are em sizes rounded to whole pixels. Test `ui-text-core` (`tests/ui_text_test.cpp`).
- `src/render/ui_text.*` with `shaders/ui_text.vert.glsl` and `ui_text.frag.glsl` (in `chase_render`): `UiText::draw` queues text (string, pixel size, position, colour, optional clip) and `flush` paints it at window resolution. `UiDraw` owns one and draws `UiBatch::texts` through it (QOLSET-84); the menu itself is wired by QOLSET-79.
Done: `src/qol/ui_layout.*` (QOLSET-71: scale, tab bar, row column, scrolling, widget rectangles, hit test, slider mapping, dropdown popup, focus rectangles, palette with 4.5:1 check), test `qol-ui-layout` in `tests/qol/ui_layout_test.cpp` at 720p, 1080p, 4K, ultrawide and 800x600 with a fixed-width fake text measure. `src/render/ui_draw.hpp` (plain-type `UiDrawList`: fill, border, line, dim, text, clip stack; `UiBatch`, `UiDraw`), `src/render/ui_batch.cpp` (pure batching: rounded corner tessellation by `uiCornerSegments`, scissor runs, clip intersection with the window) and `src/render/ui_draw.cpp` with `src/render/shaders/ui_draw.vert.glsl`/`ui_draw.frag.glsl` (GL executor, library `chase_render`). Test `render-ui-batch` (`tests/render_ui_batch_test.cpp`, no GL context, no game data). Text commands keep their order against the shape runs (`UiTextRun::runsBefore`; a text splits a run); `UiDraw` draws them between the runs. Test `render-ui-draw-window` (`tests/render_ui_draw_window_test.cpp`): hidden SDL window with a GL 4.6 core context, `readWindowPixels` of `window.hpp`, shapes, nested clips, dim, text and its order; exit 77 without display or GL; run with `SDL_VIDEODRIVER=offscreen`. The text colour type is `UiTextColour` (bytes), the draw list uses the float `UiColour`. Planned: font under `assets/` or `third_party/` (QOLSET-68), text and primitives in `src/render/` with `.glsl` shaders, the models in `src/qol/` with tests in `tests/qol/`.
Done: `src/qol/ui_nav.*` (QOLSET-72, no SDL, no GL, not wired): `UiNav` owns a `ui::Screen` and turns plain-type events (key, pad button, mouse move, down, up, right-click, wheel) into plain-type actions (value changed, tab changed, activate, dropdown opened, selected or closed, prompt or dialog cancelled, dialog confirmed, modal click, scrolled, close). Prompt and dialog are set by the caller with `setModal`; the dropdown item count comes from a callback. Test `qol-ui-nav` (`tests/qol/ui_nav_test.cpp`, mouse part at five window sizes).
Navigation conventions of `UiNav` not given by the spec text: a positive wheel count scrolls down; disabled rows stay hoverable and are skipped by Up and Down (design entry answers 11 to 14); the Dialog modal confirms on Enter or A, the SwapDialog modal cancels on them.
Done (20261101-qolui3-A): `UiNav` takes `promptInput(source, code)` events (key name with underscores, mouse button name, pad button name) that become `PromptInput` actions only while a Prompt modal is open, and `Key::Delete`, which becomes `PromptClear` in a prompt and does nothing elsewhere; clicks in a prompt still arrive as `ModalClick` (button 1 left, 3 right). `RowSpec::cells` (additive in `ui_layout.*`) splits the control of a Button row into equal cells with hit areas (`RowLayout::cells`, `Part::Cell`, `Hit::cell`); `UiNav` moves `Screen::focusCell` with Left/Right and sends `Activate` with `item` = cell (answer 15 of the design entry). `src/qol/ui_page_controls.*` (`ControlsPage`, no SDL, not wired): rows Action, Slot 1, Slot 2, Mode over a `ControlsPort`, outcomes `PromptOpen`, `PromptClosed`, `Changed`, `Rejected`, `NeedsConfirm`, `NeedsSwapDialog(otherAction)`; menu keys (Esc, Q, E, PageUp, PageDown, arrows, Enter, Delete) refused, pad buttons only after `setPadConnected(true)`, both slots follow the Mode, `reset()` after the confirm. Tests `qol-ui-page-controls` (`tests/qol/ui_page_controls_test.cpp`, with the nav at 720p, 1080p and 4K), cell cases in `qol-ui-nav` and `qol-ui-layout`.
Done: `src/qol/ui_page_qol.*` (QOLSET-74, in `chase_qol`, no SDL, no GL, not wired): `QolPage` over `Settings&` with the page interface (`rows`, `dropdown`, `handle`, `reset`) and `help(row)` returning `PageHelp`. Rows: preset selector, one toggle per feature (table `featureHelp` with its help text and default, `static` size tied to `featureCount`), "Reset to defaults" button. A hand change of a feature copies the effective values into the custom switches, flips the one and sets Custom; the preset steps over Original, Improved and Custom (only once an own mix exists) and wraps; the confirmed reset sets Original and keeps the own mix. Test `qol-ui-page-qol` (`tests/qol/ui_page_qol_test.cpp`). Conventions as the user approved them (design entry answers 25 to 28): any value change on a toggle row flips it, the preset selector wraps at both ends and skips Custom without an own mix, the confirmed reset keeps the own mix, and the help texts.
Done: `src/qol/ui_paint.*` (QOLSET-78, library `chase_qol_paint` when `chase_render` is built, no GL call): `paintMenu(UiDrawList&, Screen, UiLayout, MenuChrome)` draws the dimmed picture, panels, tab bar (selected tab underlined, focused tab filled and bordered), rows per `RowKind` (slider, selector, toggle, button, dropdown, disabled colour), focus bar plus border, scrollbar, help line, hint bar with the Back button, the dropdown popup and a generic modal dialog over a second dim; `computeDialogLayout` and `hitDialogButton` give the dialog rectangles for the wiring; `defaultHintText` follows the input device. `MenuChrome` carries palette, help and hint text, device, dim alphas, dropdown item texts and focus, the optional dialog and the measure and line-height callbacks (default: bundled font). Test `qol-ui-paint` (`tests/qol/ui_paint_test.cpp`) at 720p, 1080p and 4K: rectangles and counts of tabs, focus, popup and dialog, clip stack balance, text inside clip regions, no overlap of rows and hint bar, scrolling, batching through `buildUiBatch`, and fit of the page's texts with the bundled font. The tab bar, hint bar and row column are filled opaque so that every text sits on the palette's panel colour, as the 4.5:1 contrast rule of the Layout bullet requires; the hint texts, dim values and dialog proportions are answer 29.
