# Script system: AI movement and navigation

## 1. Scope

How an AI character moves for the script natives: the AIMove path finder and follower on the nav grids (`.bfnnav`), the simple path state of AIFollowSimplePath, the go-to-target state of AISuperJump, the speeds, and the AIMove trigger event they raise. Other AI behaviour (pursuit, stalking, fleeing, weapons) stays in [script-system-natives.md](script-system-natives.md) (SCRIPT-42).

## 2. Status

IN_PROGRESS, updated 2026-11-12T11:34:22+01:00. The path finder 0x204284, the in-grid follower and the follower across grids (transition 0x272598, phases 3 and 4 of 0x1faf04, the recovery of an unclosed start cell) are transcribed (`nav_path.*`, `nav_grid.*`, `nav_follow.*`). `chase-game` loads the nav grids of every room of the level (`nav_load.*`, with the loader fix-up of 0x1971c4) and gives them to `AiCore`, so an AIMove runs the finder and the follower: result 1 refuses the order, paths across grids are followed. Orders the follower cannot continue (result 2 of the finder, gates other than 0) still walk straight (SCRIPT-S31). The follower across grids was not compared with the original (SCRIPT-100). AISuperJump runs the set-up 0x213300 and state 11 (`ai_super_jump.*`, `ai_go_to_target.*`); the flight takes its horizontal step from 0x203d18 (`stepSuperJumpHorizontal`), its height is a stand-in (SCRIPT-S103); the face state 10 is ported (`ai_face_target.*`). The fight states are ported for every placed character (`ai_pursuit.*`): AI state 2 (hold near the target or hand over), 3 (attack), 4 and 5 (the move and the chase on the path finder) and the first part of 31 (the strike wind-up); a goon that sees Chase runs up to him and stands facing him, it does not strike (COMBAT-15). The decisions of AIRunAway, AIStalkPlayer and AIPursuit are read, not ported (SCRIPT-458..460).

AIMove whose finder result is 2, or whose follower cannot continue (a gate other than 0, a walled-off grid), is a straight walk ending on the target; the event argument is component byte 0 stood in by 0; pursuit, stalk, flee and the AIEnable party loop only record their state number (SCRIPT-458..460). needs: SCRIPT-42, SCRIPT-79, SCRIPT-92, SCRIPT-101, SCRIPT-458, SCRIPT-459, SCRIPT-460. evidence: [ai-natives.md §2026-10-14T18:42](../../re/ai-natives.md#ts-20261014-184240).

Exact for levels with one section. needs: SCRIPT-94. evidence: [ai-navigation.md §2026-10-14T20:39](../../re/ai-navigation.md#ts-20261014-203953).
- SCRIPT-S94 The lookup height tolerance (entity float `+0x70`, stood in as 0.5 doubled) and the gate masks `+0x74` / `+0x78` (stood in as bit 0 only, the original adds the registered gate types of table 0x376f10) are not the original's. needs: SCRIPT-94, SCRIPT-101. evidence: [ai-navigation.md §2026-10-14T19:47](../../re/ai-navigation.md#ts-20261014-194710).
- SCRIPT-S95 The obstacle pass 0x2af1cc (run by the follower while `+0x7c` bit 0 is clear, so for a plain AIMove) and the 200-tick budget of the cell search are skipped; the search always finishes. needs: SCRIPT-95. evidence: [ai-navigation.md §2026-10-14T19:47](../../re/ai-navigation.md#ts-20261014-194710).
- SCRIPT-S100 While an AIMove follows its path the character's height is the waypoint's grid base plus the offset it had at the first step; the original character stands on the ground through its physics. needs: SCRIPT-92. evidence: [ai-navigation.md §2026-10-14T20:39](../../re/ai-navigation.md#ts-20261014-203953).
- SCRIPT-S101 The clock of 0x2355c0 that dates the temporary marks of the grids is a nav clock in `AiCore` that starts at 10 s and runs with the updates (the original uses the game time, far above 2 s at level start). evidence: [ai-navigation.md §2026-10-14T20:39](../../re/ai-navigation.md#ts-20261014-203953).
- SCRIPT-S102 All rooms of the level have their nav grids from the start; the original reads a room's file when the room object is loaded and no release was found. needs: SCRIPT-94. evidence: [ai-navigation.md §2026-10-14T20:39](../../re/ai-navigation.md#ts-20261014-203953).
- SCRIPT-S103 AISuperJump flight: the horizontal step is the code's (0x203d18) along the heading of state 11 (the facing equalled it in the oracle); the height follows a parabola from the start through the apex `+0x30c` above the start to the target height instead of the jump-run clip scaled to the climb, and instead of the 28-count end (fall) and the landing of state 73 a step longer than the distance left is cut at the target, so state 11 arrives in the next update. The follow-up lookup 0x1f8d5c after arrival is "no target" (idle). needs: SCRIPT-103. evidence: [ai-states.md §2026-10-25T16:46:40](../../re/ai-states.md#ts-20261025-164640).
- SCRIPT-S104 State 11 arrival uses ATTR_RunSpeed 0.23 for every character (class values not read) and bit 6 of `+0x314` as false. needs: SCRIPT-103. evidence: [ai-states.md §2026-10-14T21:21](../../re/ai-states.md#ts-20261014-212158).
- SCRIPT-S341 Inputs of the fight decisions the port does not track are taken as clear: a global mode byte, the character's taunt bit (so nobody taunts), the low bits of ctrl+0xd8, sub +0x12e bit 5, the sight ray of `AILineOfSight` (never blocked), the turn test of the attack routine (always turned); the charge of ability 63 (AI state 33) is left out; of the weapon bits ctrl+0x2cd only the melee bit of the enter of state 31 is kept; the check that a destroyed target answers 2 runs only at the start of the attack routine, not at its end. needs: SCRIPT-461, COMBAT-15. evidence: [ai-states.md §2026-11-12T11:25:53](../../re/ai-states.md#ts-20261112-112553).
