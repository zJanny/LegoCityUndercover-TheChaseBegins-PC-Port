# Script system

## 1. Scope

The level scripts (level section +0x18), the per-update runner 0x169254, the executor 0x234204 and its words, Wait, CallScript / SpawnScript, the natives with a handler (EnableObject, EnableCollision, TriggerObject, EnableTrigger, EnableBound), the trigger pass 0x1746c0 with the bound checks, the `startup` script, the class `startup` scripts of placed objects, the camera bound and trigger start switches, the `OnSceneEnter<room>` event, the revealer links and the start state of placed objects. Class scripts and events at run time and the `ScriptCheckExtras` request source are not covered. Mission flow and enemies are not covered ([README.md](README.md) lists them as not started).

## 2. Status

IN_PROGRESS, updated 2026-10-14T14:37:00+02:00. `ScriptRunner` runs threads every update like the original (waits, CallScript, SpawnScript). The director camera runs: StartDCam, StartDCamTrack, WaitForDCam and EndDCam follow the oracle timing of the police entry script. The scene start (`SceneStart`) runs class `startup` scripts, the level `startup` and `OnSceneEnter<room>`, and applies the camera bound and trigger start rules; player bound triggers and `TriggerObject` start scripts. 23 natives run (`WarningDialogBox`, `PositionObject` for the player and `KillScript` among them) and 9 more as stand-ins (`FadeScreen`, the batch 26 flag and message natives, which only record their value); the other 213 are sorted into batches SCRIPT-27 to SCRIPT-39 and the rest of batch 26 (SCRIPT-57 to SCRIPT-60).

- Script data layout and loader 0x1cfc50; function names re-derived by hash (0x208a3c). lvl_01 has 314 scripts.
- Over the 896 lvl_01 objects that would register collision, the state rule gives 819 enabled in both, 48 flag-0 in both, 4 without entity and disabled by the script, 12 flag-0 only through the revealer links, 8 co-located twins; no object that the rule disables while its entity is enabled. `level-start-real-data` pins this against the oracle grid read.
- The runner is entered once per update per resident scene from the gameplay update (oracle trap, lr 0x2e54b8), and no thread is alive at gameplay-start or police-station; `level-start-real-data` checks that the lvl_01 startup threads all end.
- Executor, Wait, CallScript / SpawnScript and thread creation rules were transcribed from the disassembly; `script-runner` covers them with synthetic scripts.
- After the startup run, 236 of 241 trigger enable bytes and 479 of 482 bound enable bytes equal the oracle read at gameplay-start, and the bound room rule gives exactly the oracle's 257 active bounds for its 12 loaded rooms; `level-start-real-data` pins all three.

- After the scene start, all 241 trigger enable bytes and 482 bound enable bytes of lvl_01 equal the oracle read at gameplay-start; for lvl_00 the 53 trigger bytes and 137 bound bytes equal the oracle read at police-station (`OnSceneEnter1` switches bounds 13 and 14). `level-start-real-data`, `scene-start`.
