# Script system: mission 1-2 world natives

## 1. Scope

The six natives that mission 1-2 called without a handler: DestroyProp and KillObject (SCRIPT-58, same handler), EffectFadeObject, AddToSemiTransNearCameraList and the rest of batch 13 (SCRIPT-38), EnableDistanceFade (SCRIPT-57), SetPartyCharacter (SCRIPT-35) and StreamRoomIn (SCRIPT-38). The census and the other batches are in [script-system-natives.md](script-system-natives.md), room streaming in [world-streaming.md](world-streaming.md), the draw side in [rendering.md](rendering.md).

## 2. Status

IN_PROGRESS, updated 2026-10-19T13:23:58+02:00. The six natives have handlers read from the original and the port run of mission 1-2 no longer reports them: DestroyProp and KillObject destroy an entity as 0x23cd80 does (Dead event, message 1 to the class, destroyed bit for every kind, hidden only for the classes that disable; a car smash and an on-foot hit use the same call), the node tween acts on the objects, a killed character falls apart or vanishes ([script-system-natives-world-death.md](script-system-natives-world-death.md)), StreamRoomIn requests the room from the streamer and waits for it, the distance fade flag, the semi-transparent list and the party request are recorded. The original draws a distance fade on every mesh node by default (found while reading EnableDistanceFade), which the port does not (RENDER-66).

## 3. Verified behaviour

- `1-2_MissionStart` runs `DestroyProp(1-4_Police_Car)`, `EnableObject`, `EffectFadeObject(1-4_Police_Car, 0, 1, 1.2, 1)`: in the port the car is disabled at that point (startup state; not checked in the original), so the destroy is a no-op, and the fade raises it from hidden to opaque in 1.2 s. Pinned by `natives-world-real-data`. evidence: [script-natives-world.md §2026-10-18T11:01:40](../../re/script-natives-world.md#ts-20261018-110140).
- `1-2_Cage_Key_Target_Script` waits at `StreamRoomIn("Room40")` until the room is loaded; in `chase-game` the cutscene `1_2_c` starts after the load (9 updates, WSTREAM-S30) and the 1.5 s wait. Pinned by `natives-world-real-data` and `game-stream-room-in`.
- A scripted room request is a wanted room with priority 0 that unloads when the request stops. Pinned by `room-streaming-real-data`.
- The startup script's `SetPartyCharacter(Player1, 9, 1)` calls change nothing (character 9 is the player). Pinned by `natives-world-real-data`.
- No class handler returns non-zero for message 1, so DestroyProp / KillObject set the destroyed bit on every enabled entity; the classes of the targets in the 30 level files hide it (kinds 27, 64, 67, 71, 85, 102, 119, 134, 242) except kind 58 and the vehicles (183), which stay visible. Pinned by `natives-objects` (synthetic scripts over real class kinds) and `natives-objects-real-data` (lvl_01: 1-3_smash_crate kind 67, 1-3_Fence_08 kind 119, 1-4_Police_Car kind 183). evidence: [script-natives-world.md §2026-10-19T08:53:30](../../re/script-natives-world.md#ts-20261019-085330).
- The destroy effects per kind (explosion definition, bricks, sound id) of the targets in lvl_01, 04, 05 and 07 are pinned by `destroy-effects` and `destroy-effects-real-data` (class parameters from a loader census, 2026-10-19). evidence: [script-natives-world.md §2026-10-19T10:02:26](../../re/script-natives-world.md#ts-20261019-100226).
- The Dead event is raised before the class sees message 1, and the TriggerObject of kinds 85, 119, 134 and 214 enables and triggers its object; EnableObject brings a hidden destroyed entity back without its collision; ResetObject on a destroyed platform (kind 64, lvl_04 4-1_Crate_Faller_Platform) shows it, clears the destroyed bit and keeps the collision gone (`natives-objects-real-data`). Pinned by `natives-objects` and, for a car-smashed crate of lvl_01, `vehicle-prop-smash-real-data`. evidence: same entry.
